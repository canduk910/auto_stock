**kojiro 리스크 통제 (표 밖 상세)**

- **Σ 오픈리스크 캡** `max_open_risk_pct=4.5`(예산 대비 %, 개수 캡과 **병존**). 포지션 리스크 = `qty×(매수가−실효손절선)`, 실효손절선 = `max(buy×(1+hard_stop_pct/100), _stop_floor 또는 buy−stop_atr×ATR, high_since_buy−trail_atr×ATR)` = 청산 **세 가격선 전부**와 동일 산식·동일 ATR 리졸버. ⚠️ 샹들리에는 앞 두 선과 달리 **tighten-only 가 아니다**(ATR 팽창 시 하락) — 이 값은 "최악 보장"이 아니라 **평가 시점의 실제 손절선**이며 매수 시도마다 재평가된다. `stop ≥ buy_price` 인 포지션은 **0 으로 계상**(음수 금지 — 한 종목의 확정 이익이 다른 종목 실노출을 상쇄하면 캡이 조용히 무력화된다). `_stop_floor` 는 **읽기만** 한다 — 매수 게이트가 청산 규약을 부작용으로 바꾸면 안 된다. ATR 결측 → 고정% 추정, 예외·예산 0·cap 0 → fail-open. 매수 게이트 전용 — 청산 절대 미차단(AST 가드). 4.5% 는 `max_positions 6 × 유닛 1.0% = 6.0%` 보다 낮게 잡아 저리스크 포지션은 6개까지, full-size 유닛은 4~5개에서 정지시킨다.
- **섹터/테마 동시보유 캡** `max_positions_per_sector=2`(매수 게이트 전용·fail-open·청산 미차단). 동일섹터(`_kojiro_sector_key` KRX basket) 카운트에 **전일 보유 포함** — `_position_sectors` 영속 맵이 `_candidates` 와이프·ATR 밴드/유니버스 이탈과 무관하게 held 를 집계한다(stamp = recompute / BUY 반환 직전 / `on_position_closed` pop). ⚠️ `_reset_daily_state` override 금지(밤샘 보존).
- **ATR 리졸버 `_effective_atr(ticker)`** = `_candidates` live 우선 → `_position_atr` 영속 폴백. 손절·리스크캡 **양쪽이 같은 리졸버**를 거친다(불일치 차단). `_candidates` 는 `prepare()` 마다 와이프되므로 **손절이 거기 단독 의존하면 안 된다** — 2026-08-04 실증: 보유 6종목 중 삼영무역(002810)만 `_candidates` 부재 → `atr=0` → 2ATR 손절 분기 통째 skip → 손절선 21,674 관통에도 미발화. `_position_atr` stamp 3지점 = recompute / BUY 직전 / `on_position_closed` pop. ⚠️ `_reset_daily_state` override 금지(밤샘 소멸).
- **`max_units_per_stock=2`/`max_units_total=10` 은 소비처 0건 = 미강제**(안전장치 아님) — 피라미딩 없이는 1포지션=1유닛 항등이라 `max_units_total`≡`max_positions` 이고 `max_units_per_stock=2` 는 도달 불가 상한이다. 리스크 한도로 오인 금지. **조기진입(스테이지6)·피라미딩 = Phase 2 연기.**
- `recompute_held_atr`(boot/저녁 훅, enrich Wilder ATR, fail-open)은 같은 일봉 응답으로 `high_since_buy` 재시작 복구도 수행한다(`StrategyBase._apply_high_since_buy_from_candles` 위임). 배치는 ATR/stage 블록보다 **앞** — 워밍업 봉 부족(`len(usable) < 80`)으로 그 블록이 `continue` 해도 고점 복구는 살아남아야 한다. 이게 없으면 2.5ATR 샹들리에 기준점이 매일 아침 매수가로 리셋돼 트레일링이 하드손절과 구분되지 않는다.

**각주 ① BFB·VCP 매수 게이트** — 거래량 컷 소스 = `tick_volume` 실측 단일(미관측 `None` = **fail-closed** + `[bfb|vcp_vol_gate_no_data]` WARNING, 읽기 예외도 no_data 로 흡수). **충족 래치** — retention 완주(BFB)/edge-crossing(VCP) 후 거래량 미달·미관측이면 무장 `[bfb|vcp_latch_armed]`, 후퇴에도 유지, 해제선 = **전략 자신의 §2 손절선**(`flag_low`/`base_low`, `reason=stop_line`) + 레벨 박제(`level_moved`), 재평가는 돌파선 이상 틱에서만, 통과 시 매수 `[bfb|vcp_vol_gate_pass] ... latch_age_sec=N`. **추격 상한** `max_breakout_extension_pct` = BFB **5.0** / VCP **7.5**(리터럴 — `PARAM_RANGES` 미편입, `current_price` 단독 판정·`daily_high` 금지) + 도출 관계 부팅 관찰 `[extension_cap_invariant]`. 래치·cap 은 날짜 키 자기 리셋(scheduler 훅 미의존). `_scan_stats` 6키 = `vol_gate_pass/reject_ext/no_data`·`latch_armed_count`·`breakout_seen/retreat_count`(cap 무관 총량). `_effective_setup` 은 구조 레벨(`flag_low`/`pole_*`/`base_low`)을 **stamp 우선**, 지표(`atr14`/`ema50`)를 live 우선으로 병합하고 `[setup_structure_conflict]` 를 관측한다. 자문 = `_workspace/domain_consult/cycle228_vol_gate_latch.md` · 명세 = `_workspace/red/cycle228_gate_latch_spec.md`.

## 자금관리 — 사이징 방식 × 손절 기준 매트릭스

**핵심 명제**: `수량 = 예산 × risk_pct ÷ (진입가 − 손절가)`. 손절이 **고정 %** 면 명목 = `예산 × risk_pct/s` = 종목 무관 상수 = `position_ratio` 와 수학적으로 동일 → **고정% 손절 + 비율 사이징은 이미 리스크 균등**. ATR 유닛 사이징이 리스크를 균등화하는 것은 **손절도 ATR 기반일 때뿐**이고, 사이징만 전환하면 정규화가 오히려 깨진다(**함정 #1**). ⇒ **터틀 전환은 하드손절 ATR화와 반드시 한 커밋에 묶는다.**

|---|---|---|---|
| `momentum` | (키 없음) | 고정 % | **영구 제외** — `prepare` 빈 stub·일봉 0건 → ATR 산출 구조적 불가 |

**규약 (신규 전략 추가 시에도 적용)**

- **제한 축은 셋이다** — ① 개수 `max_positions` ② 명목 `Σ매수금액 ≤ total_investment` ③ **리스크 `Σ오픈리스크 ≤ max_open_risk_pct × 예산`**(kojiro 한정). 터틀의 유닛 캡이 실제로 통제하려던 값은 ③이고 유닛 **개수는 그 프록시**일 뿐이다 — 프록시는 "1유닛 = 상수 리스크"일 때만 정확한데 (a)소액 계좌 수량 절삭 (b)`hard_stop_pct` 가 `atr_ratio>4%` 에서 2ATR 을 자름 (c)사이징 혼재 로 헐거워진다(2026-08-04 실측: "6포지션(=6유닛)"이 실제로는 **3.2유닛**, 포지션별 편차 8.3배). ⚠️ **개수 캡을 리스크 캡으로 대체하지 말 것** — 리스크 캡만 두면 저ATR 종목으로 포지션 수가 무한정 늘 수 있다(개별 리스크는 작아도 상관·운영 부담). 터틀도 유닛 캡과 시장군 캡을 병행했다.
- **개수 캡(`max_positions`)은 걷어내지 않는다** — 소액에서는 ②명목 캡과 중복이지만 무해하고, 계좌가 커지면 **유일한 상관·운영 통제축**이 된다. 흡수 검토는 로드맵의 마지막 단계다(자문 `_workspace/domain_consult/kojiro_position_count_vs_unit_cap.md`). 피라미딩·`max_open_risk_pct` 상향·상관군 캡은 **net 500만 도달 시 재개**한다 — 피라미딩 해상도 임계(1유닛 ≥ 10주)가 그 자본에서 교차하기 때문이다. ②명목 개수 천장 = `1/position_ratio`(자본 무관)이라 성장하며 ratio 를 낮추면 저ATR 종목이 실제로 쌓여 한국 중소형 폭락일 상관=1 수렴 위험이 생기고, ③Σ리스크 캡은 **규모 불변**(항상 4.5 full유닛에서 물린다)이라 더 담으려면 `max_open_risk_pct` 상향이 필요하며 그건 **상관군 캡이 전제**다.
- ⚠️ **VCP/BFB 는 kojiro 와 로드맵이 갈린다** — VCP=변동성 수축 진입(entry ATR 국소 최소, 2N 손절 과도 타이트)·BFB=measured-move 목표 확정이라 **둘 다 피라미딩 부적합**이다. 유닛 사이징(리스크 균등)까지만 태우고 피라미딩은 제외하므로 `max_units_total`≡`max_positions` 가 영구히 성립하고 **개수 캡이 영구 load-bearing** 이다. 활성은 자본이 아니라 **체결+백테스트 게이트**다.
- **매수 수량은 `StrategyBase._apply_budget_limit()` 관문을 반드시 경유**한다(AST 가드 A-GATE 가 7전략 모든 `return` 을 검사). **관문 순서 = 잔여 클램프 → K축 랏 유닛 캡 → `[oversized_fallback]` 관측 → ρ축 명목 캡 → `return`** 이고, 이 순서가 계약이다(ρ축을 관측 앞에 두면 차단된 랏의 관측이 `final_qty < 1` 로 사라지고, K축 앞에 두면 조기탈출이 K축 마커 3종을 지운다).
  - **잔여** = `total_investment - (positions buy_price×qty 합 + pending_buy_amounts 합)`. 부족하면 **부분 매수**(잔여 < 1주 → 0). 비중 기준 0주면 관문이 `_fallback_one_share` 로 위임한다 — **이 분기 순서가 계약**이다.
  - **K축**(`max_lot_units`, K=2.0 — `sizing_mode="turtle"` 전략 한정) = `min(final, floor(max_lot_units × 예산 × risk_pct ÷ ATR))`, 0 이면 **매수하지 않는다**. ATR 은 터틀 분기와 같은 `_candidates[ticker]` read-only 이고 `atr`/`atr14` 두 키가 서로 다르면 불채택 = fail-open + `[fallback_cap_skipped]` WARNING.
  - **ρ축**(`max_lot_ratio_mult`, K_ρ=2.5 — **관문을 지나는 모든 랏**) = `min(final, int(max_lot_ratio_mult × int(예산 × position_ratio)) // 현재가)`, 0 이면 **매수하지 않는다**. 사이즈드 터틀 랏과 `position_ratio` 낙하 랏은 `compute_unit_qty_guarded` 의 notional 상한 덕에 항등적으로 무접촉이라 **실효는 1주 폴백 랏뿐**이다. 판정기 `_lot_units_cap_governs` 자체가 예외(`probe_error`)일 때만 조기탈출한다.
  - `position_ratio` 결측·예산 0·초소액·판정 예외는 전부 fail-open + `[ratio_cap_skipped]` WARNING. **ρ축은 키 부재 = 캡 OFF**(K축과 반대 관례 — 매수를 막는 통제라 fail-closed 는 P0-1 유령 키 재현 경로다). `[ratio_cap_config]` 라벨 = `off|on`.
- **불변식 `position_ratio × max_positions ≤ 1.0`** — DEFAULT_PARAMS 는 AST 가드(C-DEFAULT), AI 추천은 `_validate_recommendations` 교차검증이 강제. `max_positions` 는 `PARAM_RANGES`/`INT_PARAMS` **편입 금지**(리스크 정체성 상수).
- **ATR 손절 게이트는 `_entry_atr` 스탬프 존재** — `sizing_mode` 게이팅 **금지**. DB 토글 하나로 기보유 포지션의 손절 규약이 바뀌면 안 된다. 스탬프 값은 sizing 에 쓴 ATR 과 **반드시 동일**(커플링 불변식). 터틀이 0 을 반환하는 모든 경로(변동성 floor / 잔여 부족 / `ticker=None` / 예외)는 **미스탬프** → 기존 % 손절 경로를 그대로 탄다.
- **터틀 수량 ≤ 비중 수량**이 항상 성립 — `compute_unit_qty_guarded` 의 notional 상한이 `position_ratio × 예산` 이기 때문. 즉 전환은 **순수 축소 방향**이고 저ATR 수량 폭증은 구조적으로 불가능. 임계 = `atr_ratio = risk_pct ÷ position_ratio`(기본 2.5%).
- **3단 밴드 손절**(VCP/BFB) — `base_stop = min(buy − stop_atr×entry_atr, buy×(1+turtle_min_stop_pct/100))` 로 **과도한 타이트화 차단**, 상단은 `turtle_backstop_pct` 캡. ⚠️ VCP 는 정의상 변동성 수축 시점 진입이라 진입 ATR 이 국소 최소 → `atr_ratio 1.5%` 면 `2ATR = −3%` 로 −7% 대비 절반 이하가 된다. `turtle_min_stop_pct`(VCP −5.0 / BFB −4.0)가 유일한 방어선이며 **실제 활성화 전 백테스트 스윕 필수**.
- live-ATR breakeven 래치는 `entry_atr <= 0` 로 게이팅 — 두 tighten 메커니즘 공존 차단. 승격은 `max()` 로만 이동(tighten-only).
- 터틀 키 **7종**(`sizing_mode`/`risk_pct`/`stop_atr`/`turtle_backstop_pct`/`min_vol_floor_pct`/`turtle_min_stop_pct`/**`max_lot_units`**)은 전부 `PARAM_RANGES`/`INT_PARAMS` 미편입 = AI 자동튜닝 제외. **기계 가드는 `max_lot_units` 하나뿐**(`tests/unit/ast/test_cycle242_ast_fallback_notional_cap.py` G-242-1 = 런타임 dict + 소스 리터럴 이중)이고 나머지 6종은 문서 규약이다.
- **`max_lot_ratio_mult` 는 터틀 키가 아니라 전 전략 키**(cycle245) — 위 7종과 함께 세면 8종이 되지만 성격이 다르다. **7 전략 전부**의 `DEFAULT_PARAMS` 에 `2.5` 로 명시하며(터틀 2전략 포함 — `sizing_mode` 를 되돌리는 순간 ρ축이 자동으로 받는다), `PARAM_RANGES`/`INT_PARAMS` 미편입 = AI 자동튜닝 제외. 가드 = `tests/unit/ast/test_cycle245_ast_ratio_notional_cap.py` **G-245-1**(런타임 dict + 소스 리터럴 이중) + **G-245-6**(전략 파일 **glob 전수**로 키 존재 + 값이 `_MAX_LOT_RATIO_MULT_DEFAULT` 와 동치) + **G-245-7**(전략 `calc_buy_quantity`·터틀 사이징 함수에 `max_lot_ratio_mult` 토큰 0 = 캡 로직은 관문 안에만). 읽는 쪽 클램프 `[1.0, 20.0]` 이고 **하한 1.0 이 "정상 비중 랏 무접촉" 항등식의 전제**다.
- ⚠️ **BFB 는 익일 청산 전략이 아니다** — `_execute_next_day_clear` 대상 = `("momentum","long_tail_volatility","volatility_breakout")` · `_force_clear_main_only` 대상 = `("volatility_breakout","long_tail_volatility")` · BFB `check_force_clear()==[]`. 즉 BFB 는 `max_hold_days`(5영업일) 시간 청산까지 **실질 멀티데이 보유**이고, `_MULTIDAY_STRATEGIES` 비멤버라는 사실은 `is_next_day` **배지 표시에만** 영향한다. 재시작 복구 = `_rederive_entry_atr`(매수일 *이전* 봉만, 부족 시 미스탬프) + `recompute_high_since_buy`(`StrategyBase._apply_high_since_buy_from_candles` 위임, 복사 금지). **배선은 `boot_manager`** — DB positions 복구가 끝난 뒤라야 보유가 확정되고 `scheduler.py` 는 8영역이라 손대지 않는다. ⚠️ `_SWING_POLL_STRATEGIES` 에 BFB 편입 **금지**(그 상수는 매수 폴루프·구독 대상에도 쓰여 매수 행위가 바뀐다).
- **청산 파라미터는 `_position_setup` 영속 맵 + `_effective_setup` 리졸버 경유**(VCP·BFB 공통). `_candidates` 는 `prepare()` 마다 와이프되고 **보유 종목은 셋업이 무너져 후보 자격을 잃는 게 정상**이라, 청산이 거기 단독 의존하면 **T+1 아침부터 매일** 죽는다(재시작 사고가 아니다). 죽는 범위는 트레일링 하나가 아니라 — VCP = §1.5 래치·**§2 `base_low` 손절**·§3 트레일링·§4 `ema50` 이탈 / BFB = §1.5 래치·**§2 `flag_low` 손절**·**§3 measured-move 익절 전체**·§4 트레일링이다. **필드별 갱신 규약이 다르다** — 구조 레벨(`base_low`/`flag_low`/`pole_*`/`flag_high`)은 BUY 직전 stamp 후 **불변**, 지표(`atr14`/`ema50`)는 boot 훅이 **이미 fetch 하는 일봉으로 매일 갱신**한다(`ema50` 을 박제하면 상승 추세에서 뒤처져 이탈 청산이 늦어진다). BFB §3 은 `.get()` 방어 + **키 결손 시 미발화**(과잉 청산 금지)가 계약이다. ⚠️ `_reset_daily_state` 에서 clear **금지**(밤샘 소멸, AST 봉인). VCP 는 `recompute_high_since_buy` 의 **기존 일봉 fetch 응답을 재사용**해 `_rederive_entry_atr` 를 호출한다(추가 KIS 호출 0).
- **트레일링 기준점(`high_since_buy`) 영속은 전략 책임** — `risk.on_tick` 은 메모리만 올린다(hot path 라 DB 쓰기 금지). DB 되쓰기 경로가 없으면 `_boot()`(매 영업일 기동 직후)이 DB row 로 Position 을 재생성할 때 **트레일링 기준점이 매수가로 리셋**된다. 보정 헬퍼 `StrategyBase._apply_high_since_buy_from_candles` 가 **단일 진실원**이고 전략별 복사본은 금지다. 신규 보유형 전략은 이 헬퍼를 **이미 fetch 한 일봉 응답으로** 호출할 것 — 추가 KIS 호출 0 + `scheduler.py`(8영역) 무접촉.

## 공통 패턴

### funnel (깔때기)

- `prepare()` 단계별 통과 카운트는 `_scan_stats` 누적 → `get_scan_stats()` → `strategies.<id>.scan_stats` 로 프론트 ScanMonitor 깔때기.
- `_scan_stats` 키(`_empty_scan_stats()` 가 시드) = **VB 9키**(`universe_candidates / universe_filtered / price_filtered / mcap_pass / trade_amount_pass / candle_fetch_ok / k_value_computed / final_prepared / last_run_at`) · **LTV** = VB 9키 + `consecutive_limit_pass`(10키, 연속상한가 N일 제외 통과) · **momentum** 은 `prepare` 가 없어 `scanner.scan_filter_stats` 모듈 전역 dict 7키(`universe_candidates / rate_pass / mcap_pass / trade_amount_pass / limit_up_excluded / final_prepared / last_run_at`)이고 `MomentumStrategy.get_scan_stats()` 는 그 사본을 반환한다. BFB 는 `min_trade_amount_failed`(시총 통과 + 거래대금 미달), VCP 는 `mcap_pass` 를 추가로 센다.
- `scan_stocks()` 는 등락률 30%+(상한가)를 명시 분기한다 — `limit_up_excluded` 카운트 + 구독 후보 풀에서 제거(`check_buy_signal` 의 30% 가드와 이중 안전망).
- funnel 단계 수 = BFB·VCP·donchian·kojiro 각 **9**(`FUNNEL_STAGES`) · VB **9**(`VB_FUNNEL_STAGES`) · LTV **7**(`LTV_FUNNEL_STAGES`). **momentum 은 영구 제외** — 실시간 돌파가 본질이라 `prepare()` 가 빈 stub 이고 `_record_funnel_step` 호출 0건을 AST 가드가 영구 강제한다(UI 안내 "실시간 돌파 기반 — funnel 적재 미적용" 동행).
- `StrategyBase._record_funnel_step(step_no, step_name, survived, excluded=None, *, step_conditions=None)` — VB/LTV 는 같은 계약의 `_record_funnel_pipeline_step(STAGES[i-1], survived=..., step_conditions=..., excluded=...)` 위임형을 쓴다 — `survived` cap **200** / `excluded` cap **20**, 같은 `step_no` 는 **in-place upsert**(없으면 append). `_reset_funnel_steps(<STAGES>)` 가 전 단계를 `survived=[]` count=0 으로 **0-시드**하므로 조기반환·실패 run 도 전 단계가 0 으로 일관된다(stale count 영구 차단). `survived: list[str | dict]` 자동 dict 변환(`_resolve_ticker_name`), `excluded: list[{ticker, name, reason}]` 는 수치 포함 사유("음봉 비율 35% > 30%" 등), `step_conditions` 는 UI 단계 조건 툴팁용.
- 09:30 `_scan_loop` 첫 진입에서 `scheduler._auto_capture_funnel_snapshots` 가 자동 발화 → DB `strategy_funnel_snapshots` 단계별 INSERT. `_reset_daily_state` 동행 reset.
- step1 의미는 **"원천 유니버스 후보(필터 전)"** 로 통일한다. `list_by_filter(return_stage_counts=True)` 가 `(filtered, {union_tickers, mcap_tickers, trade_tickers})` 를 돌려주고(미지정이면 list — 기존 호출자 회귀 0) donchian 이 그것으로 step1=union / step2=거래대금 컷 후를 갈라 단계 collapse 를 막는다.
- BFB 는 `_detect_pole_and_flag_detailed(candles) -> (result, fail_stage, detail)` 이 `fail_stage`(`pole_return`/`pole_red_ratio`/`flag_retracement`/`volume_contraction`)와 측정 수치를 내고 `prepare()` 가 그것을 단계별 사유로 분배한다. `_detect_pole_and_flag` 은 result 만 반환하는 thin wrapper 다(기존 계약 보존).
- `GET /api/strategy-funnel` 응답에 `is_business_day: bool` + `holiday_note: str | None` — 휴장일이면 UI amber 배너("오늘은 휴장일 — 영업일 데이터 미수신"). `is_market_open` 호출 실패 시 graceful 영업일 가정.
- funnel 은 **순수 관찰성**이다 — `check_buy_signal`/`check_exit_signal` 에서의 funnel hook 호출 0건을 AST 가드가 강제한다.

## donchian·BFB·VCP 개별 파라미터 규약

### BFB `breakout_retention_minutes`

- 기본 3분. 첫 돌파 감지 → `_breakout_first_seen[ticker]=now` 등록 + NONE. 경과 후 BUY 발사.
- 가격 후퇴 시 dict pop. `_reset_daily_state()` 에서 clear.
- `DEFAULT_PARAMS["breakout_retention_minutes"]=3`. `PARAM_RANGES["breakout_retention_minutes"]=(1,30)`. `INT_PARAMS` 등록.
- `retention_minutes=0` 이면 즉시 BUY.

### donchian `breakout_fail_n_days`

- 기본 5일. `check_exit_signal` 에서 보유 N**영업일** + 현재가 < `_breakout_high[ticker]` → STOP_LOSS.
- **보유일 = 영업일** — `_business_days_held()` 가 `_trading_days` 캐시(일봉 union, **KIS 추가 호출 0**)로 계산하고, 캐시가 아직 오늘을 못 담은 구간만 하루 가산한다(주말 제외). 달력일(`(today - buy_date).days`)로 세면 주말·연휴가 보유일에 섞여 청산이 최대 2~3일 앞당겨진다.
- `_breakout_high`: 매수 신호 발사 시 donchian_high 등록. graceful skip(0이면 분기 진입 안 함). 재시작 복구는 `_rederive_breakout_high` 담당이고 재도출 창은 **`prior[1:period+1]`** — `prepare()` 의 `prior_high = max(highs[1:period+1])` 과 **같은 창**이다(한 칸 어긋나면 재시작 전후로 청산 임계가 달라진다).
- **`PARAM_RANGES`/`INT_PARAMS` 제외** — 청산 정체성 상수. 자동 자문뿐 아니라 **수동 적용 라우트**(`routes/recommendations.py`)도 같은 정본을 참조해 차단한다(한쪽만 막으면 제외가 아니다).
- 기존 ATR 트레일링/하드 손절 보존, 추가 분기만.
- **돌파선 0 방어 3중** — 상류에서 하류까지 같은 사고의 세 지점을 막는다.
  **(D-1)** `prepare()` 가 `prior_high <= 0` 이면 후보를 **거부**한다 + `[donchian_zero_breakout_line]` **WARNING**. 돌파선 0 은 "돌파했다" 가 아니라 "계산하지 못했다" 다. 탈락 사유는 정상 미달과 **문자열이 달라야** 한다(funnel step5 에서 구분).
  **(D-2)** 재도출 진입 게이트는 **값 기준**이다 — `_breakout_high[t] == 0` 이면 재도출을 **시도**한다(복구 전용 — 매수를 만들지 않는다). 멤버십 판정으로 두면 0 이 "무장됨" 으로 오판돼 **영구 미복구**다. 시간청산 게이트(`breakout_high > 0`)·관측기와 **같은 축**이다. ⚠️ 게이트의 값 읽기는 `isinstance` 정규화다 — `int()` 를 조건식에서 부르면 **try 밖 예외 지점**이 생겨 뒤 보유 종목의 `_channel_low`·`_entry_atr`·고점 보정이 통째로 유실된다(청산 약화 방향).
  **(D-3)** `src/db/stock_master_daily.py::_extract_raw` 가 `raw` 부재로 row 자체를 반환할 때 `[daily_raw_missing]` 흔적을 남긴다 — 그런 row 는 KIS 원본 키가 없어 `prepare` 의 `int(c.get("stck_hgpr","0"))` 가 0 을 내고 그게 곧 D-1 사고의 **상류**다. ⚠️ 이 함수는 donchian 전용이 아니다(kojiro·VCP·BFB 공유) — 호출당 1행 + 1회/ticker/일 cap, 반환값 불변(`is` 동일성 고정).
  **판독법**: 두 마커 동시 = 같은 사건(고가 결손 → 돌파선 0). D-3 단독 = 다른 전략 쪽 일봉 열화. D-1 의 실제 표면은 "종가는 살고 **고가만** 결손" 인 부분 결손 row 뿐이다(완전 정규화 row 는 `stck_clpr` 부재로 기존 `prev_close <= 0` 가드가 먼저 잡는다).
- **복구·보유일 관측 마커** — `_breakout_high` 가 재시작 후 무장되지 않는 경로를 전부 남긴다.
  - `[held_recompute_skip]` — `recompute_held_atr` 게이트 `continue`, fetch **앞**. cap `ticker`.
  - `[donchian_breakout_high_rederive_skip] reason=insufficient_prior|zero_high|no_candles|no_buy_date|no_position` — **미복구일 때만** 발화한다(무장된 정상 skip 을 매일 찍으면 신호가 희석된다). cap `ticker|reason` — 사유별 대응이 갈리므로 한 사유가 다른 사유를 삼키면 안 된다. `no_candles|no_buy_date|no_position` 3사유가 특히 중요하다: 그 경로는 상위 게이트를 통과한 뒤라 `buy_date < today` 이고, `days_held` 가 계속 자라는데 시간청산은 `breakout_high > 0` 에 막혀 **영구 미발화**한다(`fetch_daily_candles` 는 빈 `output2` 에 예외 없이 `[]` 를 돌려주고 5분 캐시에 박는다).
  - `[days_held_observe]` — 발화 여부와 무관하게 **하루 1회**. `days_held`·`calendar_days`·`days_ok`·`price_ok` 를 한 줄에 나란히 실어 영업일↔달력일 차이와 어느 조건이 막는지를 함께 보여 준다. 호출은 `check_exit_signal` **최상단**(§1 하드손절보다 앞) — §2.5 안에 두면 하드손절이 그날 첫 평가에 발화할 때 도달조차 못 하고, 매도 거부로 포지션이 생존하면 **영구 억제**된다. cap 키는 `ticker|armed`/`ticker|disarmed`(최대 2행/종목/일) — `ticker` 단독이면 장중 재시작 시 재도출 전 `breakout_high=0` 스냅샷이 박제돼 종일 무장 해제로 오독된다. 실패는 흡수하되 `[days_held_observe_failed]` debug 흔적을 남긴다.
  - 무장 판정은 **값(`> 0`)** 이다(멤버십 아님) — 시간청산 게이트·`[days_held_observe]` 와 같은 축.
  - 게이트가 fetch **앞**에 있는 이유는 KIS 호출 절약이다 — 재도출을 억지로 호출하지 않는다.
- **청산 계열 로그 폭주 cap** — `[donchian_breakeven_promote]` 와 `도치안 시간 기반 청산` 을 각각 **1회/ticker/일**(`_emit_breakeven_promote` / `_emit_time_exit`). donchian 은 `base_stop` 을 매 틱 `buy − stop_atr×entry_atr` 로 재계산하므로 `promoted_stop != base_stop` 이 영원히 참이고, 승격 자체는 매 틱 올바르게 일어나므로 잘못된 것은 로그뿐이었다. kojiro 는 승격 결과를 `_stop_floor` 에 영속해 다음 틱 `promoted == eff` 로 자연 1회라 **무접촉**이다.
  - ⚠️ **cap 은 로그에만 건다 — 행위는 cap 밖이 계약**: 승격 대입 `base_stop = promoted_stop` 과 `return Signal.STOP_LOSS` 는 cap 성패와 무관하게 매 틱 수행된다. cap 이 신호까지 삼키면 매도 거부 후 재시도가 끊겨 포지션이 청산되지 못한 채 잔존한다 = 관측 시정이 아니라 **결함 주입**이다.
  - 두 cap 은 기존 5개와 **별개 인스턴스**, 날짜 키 자기 리셋, peek→로그→mark, 예외 전량 흡수 + debug 흔적, 메시지 서식 **byte 동일**(운영 grep 연속성).
  - cap 이 없는 동류 = `도치안 스윙 손절`·`[donchian_turtle_stop]`·`[donchian_turtle_backstop]`·`[donchian_channel_exit]`·`도치안 스윙 트레일링`(매도 거부가 길어지면 같은 폭주가 난다).
  - ⚠️ **판독법 — 시간청산 로그의 첫 타임스탬프가 09:00 이전이면 프리장 게이트 이상 신호**다. donchian 은 `risk._PRE_MARKET_EXIT_EVAL_STRATEGIES`(LTV 단독) **밖**이라 PRE_NXT 단독 구간엔 청산 평가가 보류돼야 한다. cap 은 그날 **첫** 발화를 남기므로 이 신호가 D+1 판독 채널이다.

### donchian `max_breakout_extension_pct`

- 기본 **4.0%**. `check_buy_signal` 갭 스킵 *후*, BUY 확정 *전* 삽입.
- `daily_high = max(stck_hgpr, high_price, current_price, open_price)`. `ext_pct = (daily_high - donchian_high)/donchian_high*100 > max_ext` 이면 NONE (추격 금지).
- **구조적 주의**: donchian 후보 = "전일 종가 > donchian_high(어제 제외 20일 신고가)" = 등록 순간 이미 돌파 → 오늘 기준가 위 시작 → extension 하한이 이미 양수다. 따라서 불변식 **`max_breakout_extension_pct ≥ gap_skip_threshold`**(4.0≥3.0) 가 필수다 — 0.5% 같은 값은 갭 통과 종목까지 상시 차단해 모순이 된다. `PARAM_RANGES` 편입 금지(진입 임계 = 전략 정체성 상수). DB 값 우선 → 변경 시 `strategy_config.params` 동반 UPDATE 필수.
- 기존 `gap_skip_threshold`(3.0, 시가 갭)와 별개다(당일 고가 추격 상한).

### donchian 박스 수축 필터 재도입 금지

- `box_contraction_period`·`max_box_volatility_pct` 를 **다시 넣지 않는다** — "20일 신고가 돌파"(추세 상승 → 최근 박스가 넓다)와 "박스 ≤임계 초압축 횡보 요구"는 앞단·뒷단이 반대 종목을 선호해 교집합이 사실상 공집합이고, donchian 최종 후보가 상시 0 이 된다(자문 `_workspace/domain_consult/cycle_donchian_box_contraction.md`). VCP/BFB 와 역할도 겹친다.
- 페이크 돌파 방어는 **청산 규칙**(ATR×2 트레일링 / -7% 하드 / `breakout_fail_n_days` / `max_breakout_extension_pct`)이 담당한다.
