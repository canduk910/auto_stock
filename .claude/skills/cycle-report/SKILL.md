# Cycle Report — 작업 주기 마무리 보고

승인을 자주 묻는 대신, 사전 승인 범위 안에서 작업을 이어가고 **주기의 끝에 한 번** 읽기 쉬운 보고서로 결과와 결정 요청을 모은다. 보고서의 형식과 말투 기준은 `.claude/agents/report-writer.md` 가 정본이고, 이 스킬은 그 에이전트를 언제·어떻게 부르는지를 정한다.

## 트리거 (정본 — 다른 문서는 이 네 가지를 참조한다; 하나라도 해당하면 호출)
1. 사이클(Red→Green→Verify→배포)을 3회 이상 연속으로 끝냈다.
2. 자율 진행 구간(주·야간 무관 — 사용자가 끝과 커밋·배포 허용을 명시한 구간)이 끝났다(시간이 됐거나 할 일이 떨어졌거나).
3. 사용자가 "리포트" · "보고서" · "정리해 줘" 라고 했다.
4. 세션을 닫기 전에 사용자가 못 본 배포·결정 사항이 쌓여 있다.

사이클 1~2회짜리 짧은 작업은 터미널 요약으로 충분하다. 그때도 결정이 필요한 항목이 3개 이상이면 이 스킬을 쓴다.

## 흐름
```
[메인 세션] 입력 꾸러미 준비
  → [report-writer] 원문 md + HTML 초안
  → [검토 2렌즈, 병렬] 쉬운 말 렌즈 · 사실 대조 렌즈
  → [report-writer] 지적 반영 → Artifact 게시 → SendUserFile(원문 md)
  → [메인 세션] URL + 결정 목록 10줄 이내로 전달
```

### 1. 입력 꾸러미 (메인 세션이 만든다)
report-writer 는 세션 맥락이 없다. 아래를 프롬프트에 담아 준다.
- 집계 창: 시작 커밋(또는 시각)과 끝. 예 `13db0d9..HEAD`, `2026-09-04 20:25 ~ 09-05 04:30`.
- 이번 주기에 끝낸 사이클 번호와 한 줄 요지(changelog 행이 있으면 "changelog 상단 N행 참고" 로 충분).
- 배포·검증 결과: 어떤 커밋이 서버에 올라갔고, 재시작 여부, 시각, 확인한 방법(EC2 마커·헬스체크·CI 링크). 없으면 "확인 안 됨" 이라고 적어 준다.
- 발견한 문제와 그 정본 문서 경로(포렌식·자문 메모).
- 사용자 결정이 필요한 항목 목록(번호·내용·제안). 메인 세션이 아는 우선순위.
- 다음 확인 시점(예: 월요일 07:55 부팅 후)과 확인 항목 후보.
- 보고서 주제 슬러그(파일명용)와 아티팩트 제목 후보.
- **모드** `draft` / `publish`. `publish` 호출에는 초안 md·HTML 경로와 2렌즈 지적 전문을 그대로 담는다(에이전트는 매 호출 새 맥락이라 이전 호출을 기억하지 못한다).
- 재게시면 기존 아티팩트 URL(메인 세션이 `Artifact action: list` 로 찾는다). 없으면 새 게시.

### 2. 초안 (report-writer)
`Agent({subagent_type: "report-writer"})` 에 `mode: draft` 로 호출. 결과 = 원문 md 경로 + HTML 경로(스크래치패드). 초안 단계에서는 게시하지 않는다.

### 3. 검토 2렌즈 (병렬, 읽기 전용)
기본은 `Agent({subagent_type: "general-purpose", model: "fable"})` 2개를 한 메시지에서 병렬로 띄운다(읽기 전용). 사용자가 워크플로에 옵트인한 세션(ultracode 등)에서만 `Workflow` 로 대체한다. 둘 다 파일을 고치지 않고 지적만 돌려준다.
- **쉬운 말 렌즈**: 무설명 용어·영문 약어, 40자를 크게 넘는 문장, 수동태·번역투, 같은 것의 다른 이름, "그래서 내가 뭘 하면 되지?" 를 놓치는 절, 주어 없는 실행 문장. 각각 원문 인용 + 대체 문장.
- **사실 대조 렌즈**: HTML 의 모든 숫자·시각·커밋·주장을 원문 md, `docs/HARNESS_CHANGELOG.md` 상단 행, `git log` 와 대조. 집계 창 불일치, 완료형으로 쓴 예상치, 정본 자체의 stale 문장까지 보고.
지적은 `{severity, where, problem, suggestion}` 구조로 받는다.

### 4. 반영과 게시 (report-writer)
- `mode: publish` 로 report-writer 를 다시 호출한다(초안 경로 + 지적 전문 + 기존 URL 이 있으면 URL). 에이전트가 지적을 전부 처리(수용/불수용 사유)하고, 정본 md 쪽 오류는 md 도 고친 뒤 `artifact-design` 스킬 로드 → `Artifact` 게시(새 게시 favicon 🌙 / 재게시는 `url` 을 `read` 한 뒤 같은 `url`, `label` 판 이름, `description` 한 문장) → `SendUserFile` 로 원문 md 첨부.
- **report-writer 는 커밋·push 를 하지 않는다.** 산출물 경로를 받은 메인 세션이 커밋 정책(사용자 명시 지시 또는 명시된 자율 구간)에 따라 커밋 여부를 결정한다.

### 5. 전달 (메인 세션)
터미널 메시지는 10줄 이내: 아티팩트 URL, 원문 경로, 결정 카드 제목(급한 순), 가장 먼저 답이 필요한 것 한 줄. 상세는 아티팩트에만.

## 자율 진행 구간과의 관계
CLAUDE.md "자율 진행과 승인 빈도" 절이 정한 범위 안에서는 사이클마다 승인을 묻지 않는다. 그 대신 이 스킬이 주기 끝의 **유일한 보고 지점**이 된다. 여전히 승인이 필요한 일(8영역·scheduler 변경, 보유 중 장중 push, 기능 비활성화, 되돌리기 어려운 운영 조치, 사용자 결정 항목)은 보고서의 "결정해 주세요" 카드로 올린다 — 보고서가 승인 요청을 대신하지 않는다.

## 안전 규칙
- 보고서에 비밀값을 넣지 않는다(키·비밀번호·토큰·계좌번호). 화면 캡처로 노출된 값도 다시 쓰지 않는다.
- 아티팩트는 비공개 기본값을 유지한다. 공유는 사용자가 한다.
- 실측하지 않은 효과는 "예상" 으로 쓴다. 배포 전후 의미가 바뀐 지표(예: `[stale_force_retry]` 감소가 정상)는 그 사실을 함께 적는다.
- report-writer 는 코드를 고치지 않는다. 검토 렌즈가 코드 결함을 찾으면 보고서의 후속 항목으로만 적는다.
