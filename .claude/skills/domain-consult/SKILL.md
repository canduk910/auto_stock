# Domain Consult — 트레이더 자문 흐름

매매 의사결정의 근거가 흔들릴 때 domain-expert 에게 깊이있는 자문을 요청한다. 자문은 *권고* 이며 채택은 team-leader 의 권한이다.

## 언제 자문하는가

| 상황 | 자문 의뢰자 | 자문 주제 예시 |
|------|------------|--------------|
| 신규 전략 발의 | team-leader | "이 전략의 시장 가설은 무엇이고 어느 레짐에 적합한가" |
| 파라미터 변경 발의 | team-leader / 사용자 | "K=0.5 → 0.4 변경 시 진입 빈도/손익비 변화는?" |
| AI 자문 결과 해석 | recommendation_engine 결과 사용자 | "이 추천 파라미터가 실전에서 합리적인가" |
| 보드 가드 변경 발의 | team-leader | "POST_NXT 에 VB 매수 허용해도 되는가" |
| KIS 거부 패턴 해석 | backend-dev / tester | "왜 이 시간대에 시장가가 거부됐는가" |
| 운영 결함 1 차 판단 | tester | "이 결함이 시장 행태 정상인가 코드 결함인가" |
| 리팩토링 행위 영향 평가 | refactor-expert | "이 리팩토링이 보드 가드를 깨지 않는가" |
| 회귀 테스트 시나리오 합성 | tdd-engineer | "VB 페이크 돌파의 결정적 가격 시리즈 구성" |

## 자문 요청 형식

요청자는 다음 정보를 SendMessage 또는 Agent prompt 로 전달한다:

```
[자문 요청]
주제: {1 문장 주제}
배경: {왜 이 자문이 필요한가, 현재 코드/명세 상태}
질문: {구체적 질문 1~3개}
현재 가설: {요청자가 가진 가설 — 있으면}
참고: {운영 로그 경로 / 관련 파일:라인 / 외부 자료 링크}
긴급도: LOW / MEDIUM / HIGH
```

```

- 의뢰자: {team-leader / tdd-engineer / ...}
- 의뢰일: YYYY-MM-DD
- 긴급도: {LOW/MEDIUM/HIGH}

## 질문 요약
{한 단락}

## 트레이더 시각
### 시장 가설
{이 의사결정 뒤의 시장 가설을 1~3 문장으로}

### 실전 사례 / 통계
{과거 운영 사례, 유사 상황의 시장 통계, 호가창/체결창의 미시적 신호}

### 위험 시나리오
{이 가설이 깨지는 시장 조건 2~3 가지}

## 정량 권고
- 파라미터/임계/시각: {수치}
- 근거: {백테스트 / Supabase trade_history 통계 / 일반 시장 통계}
- 신뢰 구간: {운영 로그 양에 따른 신뢰 수준}

## 현 코드와의 정합성
- 충돌 항목: {file_path:line — 충돌 사유} (없으면 "없음")
- 선택지: 변경 / 유지 / 부분 적용 — 각각의 트레이드오프

## 반례 / 한계
- 반례 1: {반례 시나리오}
- 반례 2: ...
- 자문의 한계: {데이터 부족 / 신규 시장 환경 / 외부 변수}

## 후속 검증 권고
- tdd-engineer 에게: {합성 가격 시리즈 / 회귀 테스트 시나리오}
- tester 에게: {통합/E2E 시나리오}
- backend-dev 에게: {구현 시 주의 엣지 케이스}
```

## 자문 채택 흐름

```
[자문 요청] → domain-expert 가 메모 작성 → SendMessage 한 줄 요약 →
team-leader 가 채택/보류/폐기 결정 →
  - 채택: _workspace/00_leader_trading_rules.md 에 반영 + 후속 Red→Green 사이클
  - 보류: 메모 보존, 운영 데이터 추가 수집 후 재자문
  - 폐기: 메모 보존, 사유 기록
```

## 빈출 자문 토픽 빠른 참조

### VB / LTV K 값 조정
- K 의 미시 해석 = "전일 변동폭의 K 배 추가 상승 시 추세 확정"
- 자문 시 함께 제시: 현 운영 진입 빈도, 페이크 돌파율 (운영 로그 기반)
- 권고는 보드별 K 분리 가능성 포함

### 보드 가드 변경
- CLAUDE.md "절대 깨지 말 것" 의 VB 15:20 일괄매도 / NXT 좀비 차단 / KRX ONLY (사이클 26) 우선
- 자문 시 보드별 거래원 슬림/호가 두께 통계 + 갭 위험 함께

### 손절/익절/트레일링 정책
- 손절 = 가설 무너진 가격 / 익절 = 추세 종료 인식 / 트레일링 = 직전 변동성만큼 양보
- 자문 시 운영 trade_history 의 *익절 도달 시각 분포* + *손절 직전 호가 두께* 인용

### 시장 레짐 (DKSTOCK)
- VIX 25+ / FG 15- / FG 85+ 임계의 *트레이더 본능* 해석
- cash_usage_ratio 자동 조정의 신중 권고 (레짐 전환 직후 갭 위험)

## 안전 규칙

- domain-expert 의 자문은 *권고* — 채택은 team-leader 권한
- CLAUDE.md "절대 깨지 말 것" 안전 규칙을 깨는 자문은 domain-expert 자체가 거부
- 자문 메모는 폐기 시에도 보존 — 사후 시장 검증 위해
