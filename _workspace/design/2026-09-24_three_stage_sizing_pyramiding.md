## 0. 한 줄 결론

**고지로(kojiro) 한 전략만, 지금 사는 신호 그대로 첫 덩어리를 2/3 유닛만 사고, 다음 날부터 마지막 체결가보다 1N 오를 때마다 2/3 유닛씩 더해 최대 3덩어리(합계 2유닛)까지. 손절선은 「마지막 체결가 − 2N」 하나를 세 덩어리가 같이 쓴다. 먼저 과거 일봉 재현과 야간 가상 기록(shadow)으로만 돌린다.**

이렇게 하면 **손절에 걸렸을 때 잃는 돈의 최대치가 오늘과 같다.** 달라지는 것은
「맞았을 때 더 많이 들고 있다」와 「승률이 내려간다」 두 가지다.

## 1. 용어 (이 문서 안에서만)

| 말 | 뜻 |
|---|---|
| N | 그 종목의 ATR(하루 평균 변동폭). **첫 덩어리를 살 때 값으로 고정**한다 |
| 유닛(u) | `예산 × risk_pct ÷ N` 주. 2N 손절에 걸리면 예산의 1%(kojiro `risk_pct` 0.005 × 2)를 잃는 크기 |
| 트랜치 | 한 번에 사는 덩어리. 이 설계에서는 2/3u |
| 사다리 | 첫 트랜치 + 추가 트랜치들의 묶음 |
| 세트선 | 사다리 전체가 공유하는 손절선 = 마지막 체결가 − 2N |
| R | 오늘 kojiro 1랏이 2N 손절에 걸렸을 때의 손실 = 1R |
| 3단 분할 | 확신도에 따라 **첫** 크기를 나누는 것 (원전 = 시험·조기·본매매) |
| 피라미딩 | 이기고 있을 때 **같은 종목을 더** 사는 것 |

## 2. 왜 이 모양인가

### 2-1. 출발점 (09-22 보고서 D2·D3)

- 대순환 MACD 원전은 「이른 신호일수록 작게 산다」(시험 < 조기 < 본매매)를 전제로 한다. 우리는
  사면 한 덩어리라 그 전제가 없다. 그래서 국면6 조기진입(D2)은 **보류**됐고, 수량 사다리를 먼저
  설계하기로 했다(D3).
- 루트 `CLAUDE.md` 가 「피라미딩 착수 시 `max_lot_units` K→1.0」 과 「`pending_buy_amounts` 키를
  `(ticker, order_no)` 로(카드 E)」 를 선결로 적어 두었다.

### 2-2. 버린 것과 이유

| 후보 | 판정 | 이유 (실측) |
|---|---|---|
| 원전 국면 사다리 (시험 국면5 → 조기 국면6 → 본매매 국면1) | **기각** | cycle340 실측 — 국면5 조기는 전 구간 최악, 국면6 의 D+5 이점은 D+20 에 사라진다, 국면4 는 평균회귀. **신호 등급이 확신도의 증거가 되지 못한다.** 증거는 진입 뒤의 **가격**에서 받는다 |
| 체증 1:2:6 (갈수록 크게, 확신도 노트) | **기각** | 같은 위험으로 맞춘 재현 855건에서 **유일하게 확실히 손해**(Δ −0.075R, 95% 구간 [−0.134, −0.018]). 게다가 우리 계좌에서는 첫 단(1/9)이 kojiro 65%·donchian 80% 가 0주라 모양이 안 선다 |
| 4트랜치 | 기각 | Δ −0.057R. 네 번째 추가가 손절선을 첫 진입가 +1N 까지 올려 멀쩡한 추세를 털어낸다 |
| 1유닛씩 3번 (내 원안) | 기각 | 오늘 kojiro 정상 랏은 **이미 1유닛**이라 첫 단이 작아지지 않는다. 손절 기준 위험 최고치가 오늘의 **1.5배**, 갭 최대손실은 **3.8배**(−5.27R vs −1.39R). 평균이 커 보인 것은 위험을 더 쓴 결과였다 |
| 평균단가 기준 손절 | 기각 | 3덩어리가 다 차면 선이 세트선보다 1N 느슨해지고 위험이 2배 |
| 덩어리별 따로 손절 | 기각 | 부분 매도 배관이 없다(`execute_sell` 은 항상 전량). 같은 종목 매도 주문이 여럿 생겨 cycle327·332 가 막은 재발사·취소 타이머 교차 경로를 새로 연다 |
| 체감 4:2:1 (추세추종 노트) | 차선 | 균등과 거의 같다(+0.036 vs +0.047). 첫날 위험이 가장 커서 「이른 자리에서는 작게」와 반대 |

### 2-3. 남은 것 — 같은 위험으로 맞춘 비교 (자문 재현, 운영 일봉)

표본 = kojiro 진입 대리 조건 **855건 / 598종목**, kojiro 청산 규약 근사, 하루 안 순서는
**사다리에 불리하게**(손절 먼저) 셌다. 모든 구성의 손절 기준 위험 최고치를 1R 로 맞췄다.

| 구성 | 평균 R | 승률 | 최대손실 | Δ평균R [95%] |
|---|---|---|---|---|
| 오늘 1랏 | +0.240 | 36.5% | −1.39R | — |
| **1N 간격 · 2/3u × 3 (권고)** | **+0.287** | 25.1% | −3.52R | **+0.047 [−0.029, +0.122]** |
| ½N 간격 · 3트랜치 | +0.258 | 29.2% | −2.01R | +0.018 [−0.022, +0.057] |

🔴 **정직하게 — 「피라미딩이 돈을 번다」는 이 표로 말할 수 없다.** 구간이 0 을 포함한다.
말할 수 있는 것은 「같은 위험이면 균등 3트랜치가 가장 덜 나쁘다」 「체증과 4트랜치는 나쁘다」 뿐이다.
그래서 이 설계의 첫 두 단계는 **매매를 바꾸지 않는 관측**이다.

## 3. 사다리 명세 (착수가 승인되면 이대로 만든다)

### 3-1. 대상

| 전략 | 처리 |
|---|---|
| **kojiro** | 실매매 대상(단, §8 단계 4 이후) |
| donchian_swing | **가상 기록(shadow)에만** 넣는다. 오늘 예산으로 사다리가 서는 종목이 34% 뿐이고, 운영 `atr_trail_mult` 1.8 이 손절 2.0 보다 조여 세트선 배선을 따로 해야 한다. 순자산이 약 2.5배가 되면 다시 본다 |
| momentum · VB · LTV · BFB · VCP | **영구 제외.** 손절이 고정%라 N 이 청산에 없다(함정 #1). VB 는 당일 청산, momentum 은 익일 청산이라 며칠에 걸쳐 증거가 쌓이는 구조가 없다 |

### 3-2. 3단 분할과 피라미딩은 **한 사다리의 손잡이 둘**이다

사다리 = `(첫 트랜치 비율 f, 추가 간격 s, 최대 트랜치 n)`.
「3단 분할」은 **f**, 「피라미딩」은 **s·n** 이다. 오늘 진입 등급은 strict 하나라 f 는 2/3 하나뿐이다.
나중에 국면6 조기진입(D2 보류 중)이 표본으로 증명되면 **등급별 f**(예: 국면6 = 1/3u)로 끼운다.
따로 두 기능을 만들면 같은 종목 명목·같은 손절선·같은 K축 캡을 두 번 걸거나 한 번도 안 건다.

### 3-3. 트리거와 크기

| 항목 | 규칙 |
|---|---|
| 1트랜치 | 현행 kojiro strict 진입 그대로(09:05~09:30, 갭 필터 동일). **크기만 2/3u** |
| 2·3트랜치 | 현재가 ≥ **마지막 실체결가 + 1.0 × N** 일 때. 판정은 **그 순간 현재가**로만 — `high_since_buy` 로 판정하지 않는다(찍고 내려온 값에 사면 안 된다) |
| 최대 | 3트랜치 = 명목 2u |
| 비율 | 균등 2/3 : 2/3 : 2/3 |
| 추가 시간창 | **09:30~15:00 KST**, 첫 매수 **다음 영업일부터**(당일 추가 금지) |
| 추가 금지일 | 다음 영업일까지 **2일 이상** 비는 날(금요일·연휴 전날). 판정 = `api/condition.py` 의 `next_trading_day` (KIS `chk-holiday`). 조회 실패 시 **추가하지 않는다**(추가를 안 하는 쪽이 안전 방향) |
| 갭으로 눈금을 건너뛴 날 | 시가 ≥ 눈금 × 1.05 면 그날 추가 없음. 5% 미만이면 실체결가를 새 기준으로 |
| 사다리를 걸지 않는 경우 | 첫 트랜치 `floor(2/3 × u)` 가 **2주 미만**이면 사다리 없이 **오늘처럼 1u(현행 수량)** 를 산다. 1주 폴백으로 산 랏에도 사다리 없음 |
| MACD | 트리거에 쓰지 않는다. 추가 시점의 MACD 상태를 **기록만** 한다(추세추종 노트의 「새 근거가 날 때만」 과 나중에 비교할 분모) |

### 3-4. 물타기 금지 — 다섯 겹 (전부 AND)

1. `현재가 ≥ 마지막 체결가 + s × N` **그리고** `현재가 > 가중평단`
2. 기준가(마지막 체결가)는 **오르기만 한다.** 새 체결가가 기준가보다 낮으면 기준가를 바꾸지 않고 `[pyramid_averaging_down]` CRITICAL + 그 종목 추가를 청산 때까지 정지
3. 현재가 > 실효 손절선
4. 당일 매도했거나 매도 중(`_selling`)이거나 매도 거부 차단(`SellRejectionTracker.is_blocked()`) 중이면 추가 없음
5. 시세가 120초 넘게 안 왔으면 추가 없음

**시험 규약**: 게이트를 하나씩 지우거나 부등호를 뒤집은 돌연변이가 **각각** 테스트를 붉혀야 한다.

## 4. 손절선

### 4-1. 식 — 새 규칙이 아니라 기존 `max()` 에 항 하나

```
실효 손절선 = max(
    세트선        = 마지막 체결가 − 2 × N_entry        ← 신규 (사다리 스탬프가 있을 때만)
    기존 2N 선    = pos.buy_price(가중평단) − 2 × ATR
    backstop      = pos.buy_price × (1 − 8%)          (hard_stop_pct)
    본전 승격선   = pos.buy_price                      (고점 ≥ 평단 + 1.5N 이면, 운영 DB 활성)
    샹들리에      = high_since_buy − 2.5 × ATR
    _stop_floor   = 이미 확정된 선 (조이기만 하는 래칫)
)
stage3 시간청산 = 가격 무관 전량 (현행 그대로)
```

- **N 은 첫 트랜치 체결 때 한 번 찍고 덮지 않는다.** kojiro 의 현행 손절 ATR 은 `_effective_atr`
  = 오늘 후보 값 우선이라 변동성이 커지면 선이 매일 움직이고 **느슨해질 수 있다.** 세트선과 추가
  눈금에는 그 값을 쓰지 않는다. `buy_date` 도 첫 트랜치 날짜를 유지한다.
- 샹들리에(2.5N)가 세트선(2N)보다 넓어서 kojiro 는 세트선이 **따로 꼭 필요**하다.
- 3트랜치를 다 채우면(P, P+1N, P+2N) 평단은 P+1N 이고 세트선은 P 다. 고점이 P+2.5N 에 닿으면 본전
  승격이 평단(P+1N)으로 선을 올려 **사다리 전체가 본전**이 된다.

### 4-2. 🔴 세트선을 켜는 스위치는 파라미터가 아니라 **포지션의 스탬프**다

루트 `CLAUDE.md` 의 「터틀 ATR 손절 게이트는 `_entry_atr` 스탬프 존재 — `sizing_mode` 로 게이팅 금지」
와 같은 규약을 따른다. 세트선 항은 **그 포지션에 사다리 스탬프(`tranche_count ≥ 2`)가 있을 때만**
켜고, 사다리 파라미터 값으로 켜고 끄지 않는다.
→ 롤백 다이얼(§9)을 내려도 **이미 쌓은 사다리의 손절선은 느슨해지지 않는다.** 1트랜치만 든 포지션은
오늘과 글자 그대로 같은 손절 규약을 탄다.

### 4-3. 위험 합계 — `max_open_risk_pct` 4.5% 는 그대로

| 시점 | 세트선 | 손절 기준 위험 | kojiro 예산 대비 |
|---|---|---|---|
| 1트랜치 | P−2N | 0.67u × 2N = 1.33uN | 0.67% |
| 2트랜치(P+1N) | P−1N | 2.00uN | 1.00% |
| 3트랜치(P+2N) | P | 2.00uN | 1.00% |

최고치가 **오늘 1랏(2uN = 1.00%)과 같다.** `_open_risk_won` 식(`qty × (buy_price − stop)`)은 입력이
맞으면(가중평단·세트선) 그대로 쓴다 — 계량 코드는 안 바꾸고 **입력을 고친다**(§7 P-1).

🔴 **갭 위험은 이 캡에 안 잡힌다.** 명목은 최대 2u 라 갭이 세트선을 뚫으면 손실이 명목에 비례한다
(재현 최대 −3.52R). 추가 금지일(§3-3)과 종목당 누적 명목 캡(§5)이 대응이고, shadow 가 명목 기준
스트레스(`Σ명목 × 10%`)를 **표시만** 한다.

## 5. 한도·캡과의 관계

| 장치 | 설계 | 근거 |
|---|---|---|
| **K축 `max_lot_units` 2.0** | **유지 + 「1주 폴백 랏에는 사다리 금지」 한 줄** (사용자 결정 D-2) | 트랜치는 전부 정상 분기(≥2주)라 K 캡에 안 닿는다. 「K=2 폴백 랏 위에 사다리 = 8유닛」 문제는 그 조합을 막으면 닫힌다. K→1.0 은 사다리와 무관하게 **kojiro 진입 8% · donchian 20% 를 없앤다**(u<1 종목) |
| ρ축 `max_lot_ratio_mult` 2.5 | 무변경 | 한 번 사는 양의 상한이다. 트랜치 명목(ATR 4.45% 기준 예산의 약 7.5%)이 컷오프(약 41.5%)에 한참 못 미친다 |
| **종목당 누적 명목** | **신설: `2 × position_ratio × 예산`** (kojiro 약 33%) | K축·ρ축·`compute_unit_qty_guarded` 의 명목 상한은 전부 **한 번 사는 양**만 본다. 이미 든 수량을 모른다 |
| 명목 한도 `total_investment` | 무변경 — 추가도 `_apply_budget_limit` 관문을 지난다 | 관문 순서 계약·A-PURE·A-ATOMIC 그대로. 단 추가 경로는 **1주 폴백으로 떨어지지 않게** 감싼다(`qty ≤ 0` 이면 관문을 부르지 않고, 결과 < 2주면 0) |
| 슬롯 `max_positions` | **추가는 슬롯을 먹지 않는다** | 슬롯은 종목 수 축. 단 `is_max_positions` = `len(positions) + len(pending_buys)` 라 추가 주문 중인 종목이 **두 번 세어진다** → 합집합으로 세도록 고친다 |
| Σ오픈리스크 `max_open_risk_pct` 4.5% | 무변경 | §4-3 |
| 섹터 캡(종목 수 2) | 1단계 무변경 | 종목당 위험 최고치가 같다. 섹터별 **명목**은 shadow 에 기록만 |

## 6. 1주 언저리 랏에서 성립하는 조건

- 조건: `floor(2/3 × u) ≥ 2` ⇔ **u ≥ 3** ⇔ 주가 ≤ `예산 × risk_pct ÷ (3 × ATR%)`.
- 오늘 예산(순자산 4,959,673원, 09-23 `total` 행):
  - kojiro 예산 약 198만 × 0.005 → ATR 4.45% 종목이면 **주가 약 74,000원 이하**
  - donchian 예산 약 74만 × 0.01 → ATR 6.09% 종목이면 **약 40,700원 이하**
- 과거 체결을 오늘 예산으로 다시 계산하면 사다리가 서는 비율 = **kojiro 77% · donchian 34%**.
- 서지 않는 종목은 **오늘처럼 한 번만 산다.** 스캔에서 빼지 않는다 — 빼면 후보가 바뀌어 kojiro
  성과가 사다리와 무관한 이유로 움직인다(그것은 F2 「스캔 단계 주가 상한」이라는 다른 결정이다).
- 순자산이 늘면 u 가 비례해 커진다.

## 7. 주문 흐름과 실패 처리 (추가 트랜치 한 건)

```
[09:30~15:00 swing poll 60초 주기]
  → 추가 게이트(§3-3·§3-4 전부 통과) → 추가 수량 계산(관문 경유, <2주면 중단)
  → 「추가 주문 중」 표식을 place_order **앞**에 동기로 세운다   ← 신규, 아래 ①
  → place_order → 주문번호 매핑(현행 규약 그대로, await 전)
  → 체결통보(H0STCNI0) → 포지션 **누적**(수량 더하기 · 가중평단 · 기준가 단조 갱신)  ← P-1
  → trade_history 1행(트랜치 번호) · positions 영속(트랜치 수·N·기준가·세트선)
  → 세트선을 `_stop_floor` 래칫에 반영 → 다음 틱부터 새 손절선 감시
```

| 상황 | 처리 |
|---|---|
| ① 체결통보가 주문번호 매핑보다 먼저 온다 (`await place_order` 창) | 지금 코드는 보유 종목에 온 체결을 「그 포지션의 추가 체결」로 보고 **수량·매수가를 덮는다.** 매핑이 비어 있어도 추가인지 알 수 있게 `place_order` **앞**에 「이 종목은 N번째 트랜치 주문 중」 표식을 동기로 세운다. 표식 없는 보유 종목 체결은 지금처럼 처리하되 `[pyramid_unknown_fill]` ERROR |
| 부분 체결 | 받은 만큼으로 그 트랜치를 끝낸다. 잔량은 기존 30초 취소 타이머로 취소. **재발사로 채우지 않는다**(주문 후 재발사 금지 규약). 기준가 = 그 트랜치의 실체결 평균가 |
| 시장가 거부(APBK1943/3013) | 기존 지정가 5호가 폴백 1회 |
| 그 밖의 거부 | 그 눈금은 포기, 그날 재시도 없음. `pending` 정리는 매수 축 경계 래퍼(`_persist_buy_pending_after_send`) 규약 그대로 |
| 주문은 나갔는데 DB 기록 실패 | 현행 `[buy_post_send_error]` 경로 — pending 을 풀지 않는다(묶인 자금) |
| 추가 주문과 청산이 겹침 | 매도 중·매도 거부 차단이면 추가 게이트가 막는다. 같은 종목 매수 두 건은 취소 타이머 키 `(ticker, side)` 가 같으므로 **「매수 주문 중이면 추가 없음」** 으로 막는다 |
| 재시작 | 트랜치 수·N·기준가·세트선이 메모리뿐이면 재시작 뒤 세트선이 사라져 **손절이 느슨해진다.** `positions` 가산형 컬럼 + 부팅 복원이 착지하기 전에는 **실매매 금지** |
| 15분 잔고 동기화 | `_sync_positions_from_balance` 는 **없는 포지션만** 보충하고 기존 수량·평단을 KIS 잔고로 고치지 않는다. 누적이 틀리면 스스로 복구되지 않는다 → 누적 직후 KIS 잔고 수량과 대조하는 `[pyramid_qty_mismatch]` 관측을 둔다 |
| 보유 중 전략 비활성화 | 사다리 포지션은 명목이 2배라 「끄면 손절이 멈춘다」 금기의 피해도 2배다. 설계 변경 없음 — 금기 재확인 |
