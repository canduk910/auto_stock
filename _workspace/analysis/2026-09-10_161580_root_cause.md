## 5. 왜 09:00 매도가 체결되지 않았나 — 방아쇠 : **확정**

### 5-a. 시장가여야 할 주문이 지정가로 바뀌었다

`_drain_pending_next_day_clear` 의 docstring 은 의도를 명시한다 —
*"09:00 KRX 메인 시가 확정 직후에 … 시장가 매도로 일괄 정리한다. **정규장 시간대이므로 시장가 OK**"*
(`scheduler.py:1521-1527`). 실제 호출도 `execute_sell(ticker, Signal.NEXT_DAY_CLEAR, strategy_id)`
= `limit_price` 미지정 = 시장가다(`scheduler.py:1549-1551`).

그런데 `execute_sell` 의 프리장 사전변환 게이트(`order_engine.py:568-586`)가 가로챘다:

```

if _is_pre_nxt_only and target_exchange in ("NXT", "SOR"):
```

`[sell_market_preconvert_pre_nxt]` 로그가 09:00:14.118 에 남았다는 것 자체가
**그 순간 `session_tracker.active == {PRE_NXT}` 였다는 직접 증거다** (그 조건이 아니면
그 줄에 도달하지 못한다).

**왜 09:00:14 에 아직 PRE_NXT 인가** — `boards_at()` 은 `PRE_NXT = [08:00, 09:00)`,
`MAIN = [09:00, 15:40)` 로 시각 기준 판정하지만(`session.py:61-68`), 그 판정을 반영하는
`session_tracker.tick()` 은 **`SESSION_TICK_INTERVAL = 30` 초 주기 루프**에서만 호출된다
(`scheduler.py:78, 1227-1234`). 직전 tick 이 08:59:5x 였다면 다음은 09:00:2x 이고,
그 사이 09:00:14 의 `active` 는 여전히 `{PRE_NXT}` 다. **cycle264 가 다른 맥락에서 실측했던
"09:00:0x 트래커는 30초 stale 캐시" 와 같은 창이다.**

(`risk.py:495-500`) — 보드 필터가 없다. 통합 채널 `H0UNCNT0` 은 NXT 프리장 체결도 실어 오므로,
09:00:14 시점의 캐시값은 **직전 프리장 틱**이다. 실제로 이 종목의 첫 MAIN 틱은
`cntg_hour=090030`(`[open_scope_observe]` 09:00:31 로그) — **09:00:14 에는 KRX 틱이 아직 한 건도
없었다.**

산술 검증 (`src/engine/util/tick_size.py`, 실행 확인):

```
get_tick_size(39050) = 50 ;  step_down(39050, 5) = 38800   ← 09:00 주문가와 일치
get_tick_size(35250) = 50 ;  step_down(35250, 5) = 35000   ← 15:45 폴백 주문가와 일치
```

그리고 **09-08 KRX 고가 = 38,600 < 38,800**(§2 일봉). 39,050 은 KRX 에서 한 번도 형성되지 않은
가격이며, 그 값에서 5호가 내린 38,800 역시 **접수 순간부터 체결 확률 0** 이었다.

### 5-c. 세 결함의 결합

```
30초 stale 세션 캐시 ──▶ 시장가 → 지정가 변환 (프리장인 줄 알고)
                              │
프리장 잔상 가격 39,050 ──────┘──▶ 지정가 38,800 (당일 KRX 고가 38,600 초과) = 영구 미체결
                                         │
                                         ├─▶ 열린 주문 존재 ─▶ selling_reconcile 이 _selling 유지 (설계대로)
                                         │        └─▶ 6h45m 손절·트레일링 마비 (무음)
                                         │
                                         └─▶ PENDING 행 잔존 ─▶ 15:45 체결통보가 order_no 없는 WHERE 로
                                                                  PENDING 2행 동시 COMPLETED (무음)
```

### 5-d. 비용 (추정)

- **회계 손실 0** — 정정 후 실현손익은 정확하다(§1-b).
- **기회 손실 추정 2,750~3,350원** — 09:00:14 에 시장가로 나갔다면 그 시각 KRX 호가(당일
  시가 38,600 근처)에서 체결됐을 것이므로 손익 ≈ +4,750 ~ +5,350(매수가 33,250 기준).
  실제는 +2,000. **추정** — 09:00:14 의 실제 KRX 호가는 관측되지 않았고, 당일 고가 38,600 을
  상한으로 한 구간 추정이다.
- **위험 노출** — 6h45m 동안 이 포지션은 손절·트레일링이 **전혀 평가되지 않았다.** 그 구간에
  주가는 38,600 → 35,050 (−9.2%) 로 흘렀다. 이번엔 매수가(33,250) 위에서 끝나 손실이 안 났지만,
  **결함의 크기는 결과가 아니라 노출 시간으로 재야 한다.**

## 8. 부수 발견 (이 조사 밖이지만 기록)

1. **cycle264/265 계열과 같은 뿌리** — 09:00 경계의 stale 상태가 매매를 바꾼 사례가 하나 더
   늘었다. cycle262 는 `[7] STCK_OPRC` 오염을 **진입** 쪽에서 90초 보류로 지혈했는데, 이번 건은
   같은 09:00 창의 **세션 트래커 stale** 이 **청산** 쪽 주문 구분을 바꾼 경우다. cycle262 의
   보류 창(09:00:00~09:01:30)과 이 사건(09:00:14)이 **같은 창 안**이라는 점이 시사적이다.
2. **momentum 의 갭 계산도 오염된 시가를 쓴다** — 15:45:45 로그
   `익일 즉시 청산: 갭률 4.4% (시가: 34700, 매수가: 33250)` 의 34,700 은 프리장 시가다
   (KRX 시가는 38,600, `[open_source_compare]` 의 `rest_oprc`). 08:00 판정은 KRX 시가가 아직
   없으므로 프리장 값을 쓸 수밖에 없지만, **15:45 재평가까지 프리장 값을 쓰는 것**은 별개 사안이다
   (이번 건에서는 두 값 모두 임계 판정을 뒤집지 않아 결과에 영향 없음).
3. **`daily_log_reports` 는 정정을 따라가지 않는다** — 20:10 스냅샷이라 사후 정정이 반영되지
   않는다(§1-c). 이 표를 나중에 근거로 쓰면 중복이 되살아난다.
4. **`_DbLogHandler` 타임스탬프가 emit 시각이 아니다** — 큐 소비 시점에 `datetime.now(KST)` 를
   박는다(`src/main.py:136-146`). 밀리초 단위 인과 순서를 로그로 다투는 조사에서는 함정이다.

### 이 절이 닫지 못한 것 (원문 유지 — 검증 렌즈가 함께 남긴 한계)

- **`affected == 2` 의 직접 증거는 없다.** `trade_history.py:121-122` 가 `logger.debug` 라
  `system_logs` 에 없다(문서도 D-3 로 인정). 09:00 행의 `price=35250`·`profit_loss=2000` 이
  15:45 체결값과 완전히 동일하다는 **정황은 매우 강하나** WHERE 절이 2행을 덮었다는 직접 증거는
  현재 남아 있지 않다. §3-c 의 대안 배제 3건은 각각 타당하나 직접 증거를 대신하지는 않는다.
- **`session_tracker.active == {PRE_NXT}` 의 "집합 등호"** — 코드가 증명하는 명제는
  `PRE_NXT ∈ active ∧ MAIN ∉ active`(`order_engine.py:572-576`)이지 등호가 아니다.
  `_BOARD_SCHEDULE`(`session.py:61-68`)이 각 구간에 **단일 원소 frozenset** 만 배정하므로 실무상
  동치이나, `session_tracker.active` 가 그 표를 그대로 쓰는지(합집합·잔상 없음)까지는 미확인.
- **§5-d 기회손실 하한 38,000 의 근거가 문서에 없다.** 상한 38,600(당일 고가)은 근거가 있으나
  하한은 임의이며, 09:00:14 시점 KRX 호가·분봉은 이 시스템 어디에도 적재되지 않아 재산출 불가.
  (`[open_scope_observe] cntg_hour=090030` 이 이 종목의 첫 MAIN 체결이 09:00:30 이었음을 시사하므로
  09:00:14 주문은 시가 단일가 직후 구간에 들어갔을 가능성이 크지만 이 역시 추론이다.)
- **`[sell_market_preconvert_pre_nxt]` 과거 재발 빈도(D-4)** — INFO 2일 보존이라 실효 관측창은
  직전 purge(09-09 20:10) 컷오프인 **2026-09-07 20:10 이후**뿐이다. 08-10~09-10 로 넓혀 조회해도
  1건이지만 이는 "1건뿐이었다" 가 아니라 **"1건만 남아 있다"** 를 뜻한다.
- **`[selling_reconcile]` 총 1건의 창(§4-c)** — WARNING 30일 보존, 조회 시각 09-10 16:5x 이므로
  실효 하한은 **2026-08-11 경**이다. 문서의 "2026-08-10 ~" 는 하루 정도 보존 밖을 포함한다.
- **09:00:14~09:30:02 에 `_selling` 이 유지됐다는 점** — 재대조가 그 구간에 0회였음은 P-10 으로
  확정했으나, `_selling` 집합의 실제 내용은 메모리 상태라 로그로 확인할 수 없다(15:45:40 해제
  로그로부터의 역추론).
- **§8-2 "momentum 의 갭 계산도 오염된 시가를 쓴다"** — 15:45:45 로그의 `시가: 34700` 이
  `[open_scope_observe] tick_open=34700` 과 같은 값임은 확인했고 KRX 시가 38,600 도 확인했으나,
  momentum 이 그 34,700 을 **어느 캐시에서 읽는지**(그리고 08:00 판정값을 15:45 까지 들고 있는지)는
  이번 렌즈에서 코드로 추적하지 않았다.
- **(보완 — 인용 출처 명시)** §2 표의 `[open_source_compare]` 행에서 `…` 로 생략된 필드는
