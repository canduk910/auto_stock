## 질문 요약

사용자가 "VCP·BFB 도 kojiro 처럼 전체 상장 중 일부필터(kojiro 동일) 적용한 확대 유니버스"를 지시했다. kojiro 필터 = 전체상장(지수 무제약) ∩ 시총≥500억 ∩ 거래대금≥10억. 자문이 답할 5문항: (1) 확대가 실제 병목을 완화하는가 (2) VCP/BFB 셋업이 소형주 확대에 적합한가 (3) '동일 필터'의 정확한 범위 — 완전 동일 vs 전략별 차등 (4) 관찰 표본(체결 0건) 관점의 순서 권고 (5) max_scan_stocks 상향 규모 + `ORDER BY refreshed_at DESC` 함정.

**핵심 결론 3줄**: (a) 확대는 VCP 병목(추세필터 97.9% 킬)을 *근본* 완화하지 못하나 — 0→소수 후보 전환으로 **관찰 표본을 처음으로 만들어내는** 값이 있다. (b) **VCP 는 소형주 확대가 도메인적으로 타당**(미네르비니 셋업은 대형 지수주가 아니라 중소형 성장주), **BFB 는 거래대금 하향이 가장 위험**(장중 돌파 추격 = 슬리피지 최대 노출). (c) 확대 자체보다 **동반 3종(max_scan_stocks 상향 + 정렬 함정 시정 + BFB 구독 cap)이 실효의 전제** — 안 하면 확대가 오히려 손해.

## 트레이더 시각

### 시장 가설

**VCP (미네르비니 VCP)** — "확인된 상승추세 + 변동성 단계적 수축 + 거래량 마름 → 베이스 상단 돌파" 는 **본질적으로 희귀한 셋업**이다. 어느 유니버스에서도 하루 소수만 나온다. 결정적으로 — 미네르비니가 겨냥한 "슈퍼 퍼포먼스 종목"은 **젊은 중소형 성장주**이지 대형 지수 구성종목이 아니다. 대형주는 이미 시총이 커서 폭발적 VCP 를 잘 안 만든다. **즉 지수(KOSPI200∪KOSDAQ150) 제약이 오히려 VCP 가 작동하는 바로 그 종목군을 배제해 왔을 개연성이 높다.** 확대는 원재료를 늘리는 게 아니라 *맞는 서식지를 여는* 것에 가깝다.

**BFB (눌림목/깃발 돌파)** — "급등 폴 → 얕은 조정 플래그 → flag_high 장중 돌파 + 3분 유지 + 거래량 ×2" 는 **강세로 뛰어드는 추격 전략**이다. 진입이 장중 돌파 순간이라 **슬리피지에 가장 취약**하다. BFB 는 이미 지수 무제약·시총 500억 → 사용자 요청의 실질 변경은 **거래대금 20억→10억 하향 하나뿐**이고, 이게 정확히 가장 위험한 축이다.

### 실전 사례 / 통계

- **VCP 병목 실측 (2026-08-06)**: 지수 348 → 추세필터 329→7 (**97.9% 탈락**) → pullback 7→0 → 후보 0. 병목은 유니버스 크기가 아니라 **추세필터**다. 확대 산술: 979 × 추세통과율 2.0% ≈ **~20 통과** (현 7 대비 ~3배). 하류(추세→최종) 통과율은 현재 7→0 (0%, N=1 소표본). 진짜 통과율이 희귀패턴 전형 5~10% 라면 20 × 5~10% ≈ **하루 1~2 후보**. **0→1~2 는 관찰 목적상 결정적 전환**(0 이면 관찰할 게 없다)이나, "봇물"은 아니다. 정직한 평가: 확대는 병목을 *우회*하는 게 아니라 *같은 병목에 3배 원재료를 넣어* 최종 산출을 소폭 늘린다.
- **VCP 필터 조합의 방향성**: 현재 VCP `_scan_universe` 는 `min_trade_amount=0` (거래대금 필터 **미사용**, 시총 1000억 단독). kojiro 동일화 = 시총 1000억→500억(소형주 유입) + **거래대금 10억 필터 신설**(현재 없는 유동성 스크린 추가) + 지수 제거. **소형주를 열되 유동성 바닥을 새로 까는** 조합 — VCP 에는 순방향이다.
- **BFB 병목 실측 (2026-08-06)**: 후보 18 中 6(33%) 미구독(`BREAKOUT_LOW_CAP=25` 4전략 공유) + 돌파 미발생. 병목은 **구독 미수신**이지 유니버스 크기가 아니다. 거래대금 하향은 유니버스를 키워 **같은 25슬롯에 더 많은 후보가 경쟁 → 구독 미수신 악화**. 단 2026-08-08 로드맵이 이미 "cap 제거(breakout 전체 pass-1 최우선)"를 착수 중이라 — **확대는 cap 제거와 반드시 동반/후행**해야 한다.
- **`ORDER BY refreshed_at DESC` 임의 N 함정 (코드 확정, `stock_master.py:636`)**: `list_by_filter` 는 `refreshed_at DESC LIMIT max_scan_stocks`. 16:10 basics refresh 가 전 종목 refreshed_at 을 거의 동시각으로 갱신 + lazy upsert 가 개별 종목만 튐 → **filtered > max_scan 이면 정렬이 사실상 비결정적 = 임의 N 절단**. kojiro=4000 > ~979 라 절단 없음(안전). **VCP=200 / BFB=100 은 확대 후 filtered ≈ 979+ → 임의 절단 확정** = 확대해 놓고 그 중 임의 일부만 스캔.

### 위험 시나리오 (가설이 깨지는 조건)

1. **소형주 VCP 거짓 돌파 / 작전주** — 조정·분배 장세에서 500억 소형주 "VCP 베이스"가 돌파 직후 실패(bull trap). 거래량 ×1.5 확인이 부분 방어하나 소형주는 거래량 자체를 조작(작전) 가능. 500억/10억 non-index 확대 = 작전주 노출 증가. **완화 = 신설 거래대금 10억 필터 + 거래량 수축·돌파 확인이 다층 방어**(그래서 VCP 는 견딜 만함).
2. **BFB 저유동성 나쁜 체결** — 10억 일거래 종목의 flag_high 돌파 + ×2 거래량은 갭으로 flag_high 대비 3~5% 위 체결 → 즉시 물림 → -5% 손절. **추격 전략 × 저유동성 = 엣지(measured move)를 슬리피지가 먹는다.** BFB 확대의 최대 반례.
3. **추세필터 헛수고 + CPU/KIS 부하** — 확대분 대다수가 추세필터 미통과(소형주는 깨끗한 EMA 정배열이 드묾)면, 후보 산출 증분은 미미한데 prepare CPU(base 검출 + pullback ZigZag)와 **비-index 종목 KIS 폴백 폭주**만 3배. 팀장이 우려한 "죽고 부하만 3배" 시나리오 — **부분적으로 사실**(산출 증분 modest, 비용 real). 다만 그 modest 산출이 "영영 매매 안 함 vs 가끔 매매함"의 차이라 관찰 목적엔 값이 있다.

### 결정 A — VCP 필터 범위 (3안 정렬)

- **A1 (완전 동일, 권고)**: 시총 1000억→**500억** + **거래대금 10억 신설** + 지수 제거. 근거 = (a) 미네르비니 중소형 성장주 의도 정합 (b) VCP 가 현재 없는 유동성 스크린을 신설 (c) 거래량 ×1.5 돌파 + 거래량 수축이 패턴 품질 이중 방어 (d) 현 자본(net ~117만)에서 포지션 극소 → 슬리피지 무의미. **반례**: 자본 성장(T2 5천만+) 시 500억/10억 슬리피지 유의 → 그때 재상향.
- **A2 (지수만 제거, 시총 유지)**: 시총 1000억 유지 + 거래대금 10억 신설 + 지수 제거. 전체상장 ∩ 1000억 도 지수 ∩ 1000억보다 훨씬 넓다(중견 성장주 유입). **가장 보수적**. 반례 = 미네르비니 핵심 서식지(500~1000억 젊은 성장주)를 여전히 배제 → VCP 진짜 잠재력 미실현.
- **A3 (중간)**: 시총 **750억** + 거래대금 10억 + 지수 제거. 절충. 근거 약함(750억은 임의 경계) — 추천 안 함, 참고용.

**권고 = A1** (사용자 "kojiro 동일" 의도 존중 + 신설 거래대금 필터가 핵심 방어). 자본 성장 트리거 시 재검토 조건 명시.

### 결정 B — BFB 필터 범위 (3안 정렬)

BFB 는 시총·지수가 이미 kojiro 와 정합 → **거래대금 하나만 결정**.

- **B1 (완전 동일)**: 거래대금 20억→**10억**. 사용자 문자 그대로. **반례 = 최대 위험**: BFB 는 장중 돌파 추격 + ×2 거래량 진입 = 전 돌파전략 중 슬리피지 최대 노출. 10억 종목 갭 체결 → -5% 손절 직행.
- **B2 (차등 15억, 권고)**: 거래대금 20억→**15억**. 완만한 확대 + 추격 전략의 유동성 바닥 보존. "완전 동일"에서 약간 벗어나나 **도메인 근거 명확**(추격도 BFB>VCP>kojiro → 유동성 요구도 그 순서).
- **B3 (현행 20억 유지)**: 확대 안 함. BFB 는 이미 지수 무제약이라 "확대"의 실질이 거래대금뿐인데 그게 위험축이므로, **max_scan_stocks + 구독 cap 만 시정하고 거래대금은 유지**하는 것도 합리적. BFB 의 진짜 병목(구독)만 풀고 위험축은 안 건드림.

**권고 = B2(15억) 또는 B3(20억 유지) 중 사용자 확정.** 어느 쪽이든 **BFB 는 10억까지 내리지 말 것** 권고. BFB 의 실효 개선은 거래대금 하향이 아니라 **구독 cap + max_scan_stocks + 정렬** 시정에 있다.

### 결정 C — max_scan_stocks + 정렬 (동반 필수)

- **C1 (권고)**: VCP/BFB `max_scan_stocks` 를 **전체 filtered 커버 규모(~1000~4000, kojiro 선례)로 상향** → `ORDER BY refreshed_at DESC` 임의 절단 소멸. 부하 = VCP/BFB 모두 DB 어댑터(`get_recent_daily_normalized`) 사용이라 **KIS 호출 아님**, DB read + prepare CPU(base/pullback/EMA). 비 hot path(boot/16:20/reprepare)라 수용 가능. 단 **비-index KIS 폴백 폭주 주의**(아래 결함 참조).
- **C2 (정렬 전환, 강력 권고 병행)**: `list_by_filter(sort_by=...)` phase-2 훅을 활용해 **거래대금 DESC 정렬**로 전환. 절단이 발생하더라도 **가장 유동성 높은(=돌파 매매가 가장 안전한) 종목이 잔존**. 확대 유니버스의 슬리피지 우려와 임의 N 함정을 **한 번에** 해소. C1 로 절단이 사라지면 moot 이지만 미래 유니버스 성장 대비 안전망 + 올바른 기본값.
- **C3 (현행 유지)**: max_scan 200/100 유지 → **확대해도 임의 일부만 스캔 = 확대 무의미화**. 채택 금지.

**권고 = C1 + C2 병행.** C1 없이 확대는 실효 0(임의 절단), C2 는 저유동성 확대의 슬리피지 방어.

### 결정 D — 관찰 순서 (도메인 권고)

**확대 먼저가 정당하다.** 이유: (1) VCP 병목(추세필터/pullback)은 **전략 정체성 상수**(PARAM_RANGES 미편입, 208/209/212 선례) — 사용자가 손대라 안 했고 손대면 VCP 정체성이 바뀐다. (2) 확대는 **패턴 정의를 안 건드리고 원재료만** 바꾸는 = **가장 덜 침습적인** 후보 증가 레버. (3) 현재 후보 0 → **관찰할 게 없다**. 확대로 1~2 후보/일 생성 → 처음으로 한국시장 VCP/BFB 실체를 실측할 표본 확보. **FREEZE·관찰 무결성 보존**: 확대 사이클에서 추세필터/pullback/진입 임계는 **일절 불변**. 확대가 체결을 만든 뒤 실측 데이터로 임계 재검토는 **별도 사이클**.

- **VCP/BFB 피라미딩 부적합·개수 캡 load-bearing (2026-08-08 로드맵) 무충돌** — 확대는 피라미딩/개수 캡을 안 건드림. 단 확대로 후보↑ → `max_positions=5` 캡이 **더 자주 binding**(정상, 캡의 역할). ⚠️ **부작용 주의**: VCP/BFB 는 kojiro 와 달리 **후보 품질 랭킹이 없다**(kojiro 는 2026-07-20 score DESC 도입). 확대 유니버스에서 5슬롯이 "먼저 돌파한 5종목"으로 채워짐 = 품질이 아니라 **돌파 타이밍 우선** 배분. 큰 유니버스일수록 저품질(소형·저유동) 종목이 슬롯을 선점할 위험 → **후속 개선 후보**(C2 거래대금 정렬이 부분 완화).

### 실측 확인된 결함/의존성 (backend-dev 필수 인계)

1. **[HIGH] 비-index VCP 일봉 백필 경계 결함** — daily-load 의 120일 백필 게이트는 `is_vcp_universe = is_kospi200 OR is_kosdaq150` (scanner.py:2189). VCP 를 non-index 로 확대하면 신규 종목은 **비-index 경로 = 첫 로드 100일 백필**(`count_by_ticker<50 → T-100일`). 그런데 **VCP prepare `min_required=100`** → 마진 0 → 한 봉만 부족해도 `get_recent_daily_normalized` 가 **979종목 각각 KIS 폴백** → boot 시 KIS LMS chain 위험. **시정 옵션**: (a) daily-load 의 `use_vcp_backfill` 게이트를 확대 VCP 유니버스까지 확장(120일 백필) — 권고, 또는 (b) VCP min_required 하향, 또는 (c) 폴백 rate-limit. **일봉 데이터 "이미 존재" 주장은 참이나(daily-load = 지수∪500억/10억 = 확대 상위집합), 100일 min_required 경계가 유일한 실질 갭.**

3. **[LOW] `ORDER BY` 정렬** — C2 채택 시 `sort_by` phase-2 훅 실구현(현재 정의만, 실사용 0). 미채택 시 C1 max_scan 상향으로 절단 자체 제거.

## 반례 / 한계

- **반례 1 (VCP)**: 확대분 대다수가 소형주라 추세필터 통과율이 index 보다 *더 낮을* 수 있다(소형주는 깨끗한 EMA 정배열이 드묾) → 후보 증분이 예상(1~2)보다 작을 수 있다. 동시에 미네르비니 셋업이 **정확히** 그 중소형 성장주에서 나오므로 반대 방향도 성립 — **양방향 불확실성이 곧 확대의 이유**(실측으로만 판정 가능).
- **반례 2 (BFB)**: 거래대금 10억 하향 시 나쁜 갭 체결로 승률·RR 이 오히려 악화될 수 있다(추격+저유동). BFB 의 실측 부재(체결 0건)로 정량 예측 불가 → **B2/B3 보수 채택이 안전마진**.
- **반례 3 (공통)**: 후보 품질 랭킹 부재로, 확대가 저품질 소형주에게 5슬롯을 우선 배분 → 확대 후 첫 체결들이 "나쁜 표본"일 위험. 관찰 초기 데이터 해석 시 **유동성·시총 층화(stratify)** 필요.
- **자문의 한계**: VCP/BFB **체결 0건 = 실측 백테스트 부재**. 후보 산출·승률·슬리피지 추정은 전부 모델 기반이지 실증 아님. 추세필터 킬율 97.9% 도 **N=1(2026-08-06)** 소표본. 확대는 부분적으로 이 불확실성을 줄이려는 조치이기도 하다 — 즉 "확실히 좋다"가 아니라 "확인하려면 확대가 전제"다.
