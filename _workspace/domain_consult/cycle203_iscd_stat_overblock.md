## ① KIS 정본 코드값 표

### KIS 소스코드 정본 (FHKST01010100 / inquire_price)
KIS 공식 저장소(`open-trading-api/domestic_stock/inquire_price`) COLUMN_MAPPING 원문 확인:
- `iscd_stat_cls_code` = **"종목 상태 구분 코드"** (레이블만 정의, KIS 공식 문서에 코드값별 의미표는 **미제공** — enum 상수 정의 없음)
- 별도 상태 필드가 **각각 독립적으로** 존재:
  - `temp_stop_yn` = 임시정지여부
  - `sltr_yn` = 정리매매여부
  - `mang_issu_cls_code` (chk 파일) / `mang_issu_yn` = 관리종목여부
  - `mrkt_warn_cls_code` = 시장경고코드
  - `short_over_yn` = 단기과열여부
  - `invt_caful_yn` = 투자유의여부
  - `sltr_yn` = 정리매매여부

**핵심: KIS 는 `iscd_stat_cls_code` 코드값별 의미를 공식 문서로 배포하지 않는다.** 요청자의 도메인 추정(51=관리/52=투자위험/…)은 KIS 정본으로 **검증 불가**. 따라서 코드값 의미는 **운영 DB 실측 + 별도 플래그와의 교차관계**로 역추정하는 것이 유일한 정본 대체다. 아래 실측이 그 근거.

3. **57 = 정상.** 요청자 확인대로 확정. index의 대다수.

## ② 확정 블록리스트

### 트레이더 관점 — "매수하면 안 되는 상태"
매수 진입 차단의 목적은 **① 거래 자체가 막힌 종목(거래정지/정리매매) ② 규제 신호가 붙은 위험 종목(투자경고/투자위험/단기과열)** 을 유니버스에서 빼는 것. 관리종목은 상장폐지 리스크 신호라 스윙/데이 관점에서도 회피가 맞다.

그런데 실측이 보여주듯 **차단해야 할 상태 대부분은 이미 별도 전용 플래그가 100% 커버**한다:
- 투자경고(53) = `mrkt_warn_cls_code="02"` 100%
- 투자주의(54) = `mrkt_warn_cls_code` nonzero 100%
- 단기과열(59) = `short_over_yn=Y` 100%
- 정리매매 = `sltr_yn=Y` (51/00에 혼입된 것까지 잡음)
- 관리종목 = `mang_issu_yn` / `mang_issu_cls_code`
- 거래정지 = `trht_yn` (요청자 사이클 129/155 기존 플래그)

`iscd_stat_cls_code` 로 **고유하게만** 잡히는(= 다른 플래그가 못 잡는) 위험 코드값은 **실측상 없다.** 58조차 위험이 아니라 데이터 신선도 잔재.

### 확정 블록리스트 (iscd 체크를 남긴다면)

만약 iscd 체크를 유지한다면, **블록 = `{53, 54, 59}` (+ 방어적으로 `52`)**, 정상 허용 = `{55, 57, 51, 00, null}`.

```
BLOCK  = {"52", "53", "54", "59"}   # 투자위험/투자경고/투자주의/단기과열
ALLOW  = {"55", "57", "51", "00"}   # 정상·신용가능·그외·특수(ETF/스팩)
null / "" → 통과 (graceful, 미적재)
```

- **58 은 블록에 넣지 않는다.** 58은 거래정지가 아니라 현재가 0 상태. 이걸 차단하면 더존비즈온 같은 정상주가 데이터 부실 시점에 유니버스에서 빠진다. 58의 진짜 위험(현재가 0 = 거래 불가)은 **거래대금/현재가 필터가 이미 차단**한다(사이클 65 거래대금 필터, 가격 필터). iscd로 중복 차단할 이유 없음.
- **51 은 블록에서 뺀다.** 정상.
- **54(투자주의) 는 판단 분기점.** 요청자 가설대로 `invt_caful_yn`/`mrkt_warn_cls_code` 가 이미 커버하므로 iscd 체크에선 빼도 무방. 다만 **iscd 체크를 아예 남긴다면** 54도 블록에 두는 게 방어적으로 일관적(어차피 mrkt_warn 이 이미 막으니 결과는 동일).

**핵심: 이 블록리스트는 "제거"할 종목 목록이 아니라 "이미 다른 플래그가 막는 것과 정확히 겹치는" 목록이다.**

## ③ iscd 체크 유지 vs 제거 — 권고

### 권고: **iscd_stat_cls_code 차단 체크를 제거한다 (완전 중복).**

근거:
1. **완전 중복 확정.** iscd 로 차단하려는 상태(53/54/59/정리매매/관리/거래정지)는 전부 전용 플래그(`mrkt_warn_cls_code`/`short_over_yn`/`sltr_yn`/`mang_issu_yn`/`trht_yn`)가 **실측 100%** 커버. iscd 가 고유하게 잡는 위험은 0건.
2. **iscd 는 오히려 정상주를 오차단.** 57(정상 대형주 91%) 차단 = 이번 버그의 핵심. 58(정상주 데이터 부실 잔재)까지 잘못 잡음. 유지 리스크 > 유지 이득.
3. **KIS 코드값 미문서화 = 미래 회귀 위험.** KIS 가 코드 의미표를 공식 배포하지 않으므로, 블록리스트를 하드코딩하면 KIS 가 코드체계를 바꾸거나 신규 코드값(예: 52 실물 등장)이 나올 때 또 silent 오차단/오통과가 발생. **의미가 명확한 전용 플래그**에 의존하는 게 견고하다.

### 대안 (제거가 부담되면)
블록리스트를 `{52,53,54,59}` 로 **좁혀서** 유지 (57/58/55/51/00 허용). 이 경우 실측상 차단 효과는 mrkt_warn/short_over 와 동일(순수 이중 안전망). 단 위 3번 회귀 위험은 남는다.

### 반드시 유지할 것 (제거하면 안 되는 것)
- `trht_yn`(거래정지) / `mang_issu_yn`(관리) / `mrkt_warn_cls_code`(투자경고·주의) / `short_over_yn`(단기과열) / `sltr_yn`(정리매매) 전용 플래그 차단은 **전부 유지.** iscd 만 제거.

## 반례 / 한계
- **52(투자위험) 실측 0건.** 유니버스(대형주)엔 안 나오나, 만약 향후 편입 종목이 투자위험 지정되면? → `mrkt_warn_cls_code` 가 투자위험도 코드로 잡는지 **미검증**(실측 표본 없음). iscd 제거 시 이 한 케이스가 전용 플래그로 커버되는지 확인 필요. (교차검증: mrkt_warn 코드값 01=주의/02=경고/03=위험 계열로 추정되나 KIS 미문서화 → sltr/mang/trht 조합으로도 이중 방어됨)
- **58 재해석의 한계.** "현재가 0 = 시세 미갱신"으로 결론냈으나, 이 표본은 특정 적재 시점 스냅샷. 장중 실시간 재적재 시 58 종목이 정상 현재가를 가지면 57로 바뀔 수 있음. 즉 58은 **상태가 아니라 적재 타이밍의 함수**일 가능성 — 더욱 iscd 차단 부적합 근거.
- **null 11건** 은 통과(graceful) 유지. 미적재를 위험으로 오판 금지.
