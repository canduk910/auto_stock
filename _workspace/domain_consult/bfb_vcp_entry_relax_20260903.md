## 1. 실측 병목 — 전략별 한 문장

**BFB** — 병목은 임계값이 아니라 **임계를 재는 시계**다. 임계 = flag 구간의 *하루 평균* 거래량 × 1.0, 관측 = *그 시점까지의 당일 누적*, 창 = 09:05~**13:00**. 한국장의 일중 누적 거래량 프로파일(개장 30분에 15~20% 몰리는 U자)에서 13:00 시점 누적은 하루의 **65~70%** 다. 곧 **"오늘이 평소보다 1.43~1.54배 거래돼야 통과"** 를 요구하면서 파라미터에는 1.0 이라 적혀 있다. 그 앞단의 retention 1분이 래치 무장까지 막아, **재본 적도 없는 게이트에 도달조차 못 하는 상태**가 3영업일 이어졌다.

**VCP** — 병목은 진입 게이트가 아니라 **`prepare()` 가 후보를 한 건도 못 만드는 것**(3일 연속 실질 0)이고, 그 원인은 회수 상한이 아니라 회수를 세는 **자(ruler)** 다. `min_swing_atr_mult=0.5` 가 0.5×ATR 짜리 미세 진동까지 조정으로 세어 회수를 중앙값 5~6 으로 부풀리고, 뒤의 **하드코딩 strict 단조수축**(`curr >= prev → False`)이 전부 떨어뜨린다.

**두 전략 공통(파라미터로 못 고침)** — BFB 후보 25종목 중 8종목(09-01)·5종목(09-02)이 장중 내내 틱 무수신이고, 09-01 실제 3일고가 돌파 7종목 중 3종목(025980 +7.6% · 047770 +19.4% · 317400)이 바로 그 tick-blind 군이다. **기회집합의 약 1/3 이 구조적으로 보이지 않는다.** 아래 완화안은 나머지 2/3 위에서만 작동한다.

## 2. 트레이더 시각

### 2-1. BFB — 고친 것은 임계가 아니라 **자(ruler)와 시계** 다

두 노브 모두 "얼마나 좋아야 사는가"를 바꾸지 않는다. **"좋은지 판별할 기회를 언제·몇 번 주는가"** 만 바꾼다.

- `entry_end` 14:30 = **시계 시정.** 일평균 거래량과 당일 누적 거래량을 비교하면서 창을 하루의 2/3 에서 끊는 것은, 마라톤 30km 지점에서 "풀코스 완주 기록"을 요구하는 것과 같다. VCP 는 **이미 14:30** 이다(라이브 실측) — 같은 게이트 구조를 쓰는 두 전략이 서로 다른 창을 쓸 이유가 없고, 이번 변경은 그 불일치를 정렬하는 것이기도 하다.
- `retention 0` = **입장 자격 시정.** 장중 돌파는 레벨을 뚫고 1~5초 되밀렸다가 10분 뒤 거래량을 싣고 다시 뚫는 것이 정상 행태다. "1분 버텨야 진짜"는 **일봉 트레이더의 규칙**을 틱에 잘못 옮긴 것이다. 001450(09-01)이 증거다 — 09:14:55 감지 → 후퇴 → 09:22:34 재돌파해서야 래치가 걸렸고, 그 래치는 종일 살아 있었다. retention=0 이면 7분 일찍 걸렸을 뿐, **매수 기준은 같다.**

> **retention 은 왜 지금 중복인가.** 도입 시점(사이클 23)에는 **작동하는 거래량 게이트가 없었다**(cycle227 이 밝힌 유령 키 `acml_vol`). retention 은 "가짜 돌파 = 거래량 없는 돌파"를 *시간으로 대신 재던 프록시*였다. cycle228 이 본체를 켠 지금 프록시와 본체가 같은 것을 두 번 재고, **프록시가 본체 앞에 서서 본체를 굶기고 있다.**

**⚠️ 두 노브를 같은 날 켜는 것에 대한 자기 반박과 답.** "한 번에 한 노브"를 어기는 것처럼 보인다. 그러나 적대적 검토가 실측으로 보였듯(부록 A **F2**) **retention=0 단독의 체결 기여는 ≤0.1건/일**이다 — 래치 무장은 공짜이고 체결은 여전히 창 안에서 거래량 게이트를 통과해야 한다. 즉 retention 은 독립 노브가 아니라 `entry_end` 의 **전제 조건**이며, 둘의 관측치가 **분리**돼 있다(retention → `[bfb_latch_armed]` 건수 / entry_end → `[bfb_vol_gate_pass]` 의 **발생 시각**). 반대로 하나만 켜면 각각 이렇게 죽는다:

| 켠 것 | 결과 | 실측 대응 사례 |
|---|---|---|
| retention=0 만 | 래치는 늘지만 13:00 컷 안에서 통과 불가 → 체결 0 | 001450 09-01: 래치 종일 생존, EOD 1.14× 인데 창 안에서 미통과 |
| entry_end 14:30 만 | 창은 늘지만 1분을 못 버틴 종목은 대기실에 못 들어옴 | 042520·089860: 무장 실패로 창 길이와 무관 |

### 2-2. VCP 의 자(ruler)가 틀렸다

미네르비니의 VCP 는 **차트에서 눈으로 세는 2~4회의 수축**이다. 0.5×ATR — 하루 평균 변동폭의 절반 — 을 조정 1회로 세면 25~75일 박스 안에서 회수가 5~13회로 폭발한다. 회수가 5 이상이면 무작위 순서 기준 전부 단조 감소일 확률이 **0.8% 이하**라 strict 단조수축 하드컷이 사실상 전수 탈락시킨다. 현행은 "VCP 셋업이 없다"가 아니라 **"VCP 를 셀 줄 모르는 자로 재고 있다"** 이다. 1.0×ATR = "하루치 평균 변동폭보다 작은 흔들림은 조정으로 세지 않는다" — 트레이더가 차트에서 무시하는 바로 그 크기다.

### 4-0. 왜 SQL 이 오늘 안 먹히는가 (검토 F1, 실측 확증)

EC2 실측(07:33) — 컨테이너가 **오늘 06:21:58 KST 재시작**했고 `system_logs` 에 이미

### 4-2. 적용 (권장 경로 — 재기동 불요, 메모리+DB 동시)

```bash

```
`src/routes/strategies.py:167-187` 이 `strategy.config.params[key] = value` 로 **메모리 dict 를 직접 갱신**한 뒤 `save_params(strategy_id, strategy.config.params)` 로 그 dict 를 DB 에 영속한다. 범위 검증 없음. 재기동 불요.

**⚠️ 부작용 (반드시 인지)** — `save_params` 가 **params dict 전체**를 쓰므로 두 전략의 **DEFAULT_PARAMS 전 키가 DB 에 핀**된다. 이후 코드 기본값을 바꿔도 이 두 전략엔 전파되지 않는다(기존 `breakout_volume_mult` 가 코드 2.0/1.5 인데 DB 1.0/1.2 로 도는 함정과 **동형**). 코드 기본값을 바꿀 때 이 두 행을 같이 손대야 한다 — `strategies/CLAUDE.md` 에 1줄 등재 권고.

**대안 (b)** — SQL UPDATE 후 **07:45 이전** 컨테이너 재기동. 보유 8종목이 있으나 pre-boot 구간이라 D6(09:00~15:30 재시작 금지) 위반 아님. 07:40~07:55 push 는 부팅과 겹치니 자제.

**시한** — VCP 노브는 **07:52 첫 `prepare()`** 전에 메모리에 있어야 한다(후보 0일 때 5분마다 재-prepare 라 여유 있음). BFB 두 키는 매 틱 `params.get` 이라 **09:05 전**이면 된다.

**적용 검증** (둘 다 확인)
1. `SELECT params->>'entry_end', params->>'breakout_retention_minutes' FROM strategy_config WHERE strategy_id='bull_flag_breakout'` → `14:30` / `0` (메모리 dict 를 그대로 저장하므로 DB 값 = 메모리 값)
2. 07:5x `VCP 준비 완료 … pullback=K vol_cnt=M` 로그에서 후보가 **1~2** 로 바뀌는지 (현행 0)

### 4-5. DB 로 못 바꾸는 것 → 후속 코드 사이클

## 7. N=10 프로토콜 (재설계 — 달력 트리거 폐기)

### 7-1. 동결 구간
1. **최소 5영업일 관찰** 또는 **체결 3건 도달** 중 먼저 오는 쪽까지 파라미터 동결. *(초안 3영업일 → 5영업일. 근거: §5 기대치로도 3일 0건 확률이 22~37%(포아송 λ=0.6~1.5, 틱 사각 반영) 라 노이즈로 발화한다.)*
2. 체결이 1건이라도 나면 **N=10 왕복(진입→청산)까지 진입 파라미터 전면 동결** — cycle228 계약. **현실 체결률로 N=10 은 20~50영업일**이다. 이 구간에 만질 수 있는 것은 청산 결함 시정뿐.
3. 매일 확인 5지표: `[bfb_latch_armed]` (09:05:0x **분리 집계**) / `[*_vol_gate_pass]` **발생 시각** / `reason=extension` 건수 / `[stale_watcher_detail]` 종목 수 / `[*_vol_gate_no_data]`.

### 7-2. 2차 노브는 **달력이 아니라 기전 증거로** 연다

현행 코드는 "거래량 미달"을 로그하지 않는다(`bull_flag_breakout.py:1052-1054` — `observed < vol_threshold` 시 로그 0, `_arm_latch` 후 `Signal.NONE`. VCP `:1134-1137` 동형). 그래서 아래 비율은 **EOD 수작업 역산**으로 얻는다:

> **일일 절차** — 그날 `[bfb_latch_armed]` 된 각 ticker 에 대해
> `stock_master_daily` 의 **다음날 아침 적재된** D-0 실봉 `acml_vol` ÷ 그 종목의 `flag_avg_volume`(후보 그리드 `volume_threshold` ÷ mult 로 역산) = **R(EOD 배수)**

| 관측 | 해석 | 조치 |
|---|---|---|
| 래치 ≥5(고유 ticker·일) ∧ **R 중앙값 ≥ 1.2** ∧ `vol_gate_pass` 0 | **시계 가설 확증** — 자격 있는 종목이 창 밖에서만 자격을 얻는다 | `entry_end` 14:30 → **15:00** (여전히 품질 무인하). 종가 단일가 회피 상한 15:00 |
| 래치 ≥5 ∧ **R 중앙값 < 1.0** | **시계가 아니라 진짜 거래량 부족** — 돌파에 거래량이 안 실렸다 | **아무 노브도 열지 않는다.** §7-3 참조 |
| 래치 < 3 (09:05 아티팩트 제외 후) | 돌파 자체가 없다 = 레짐 | 파라미터 무관. 관찰 계속 |
| VCP: **고유 후보 종목 ≥3** 이 3일 누적됐는데 체결 0 | 후보는 나는데 돌파가 없다 | `base_max_days` 75 → 45 (swing 1.0 유지 시 후보 2~5/일). **고유 후보가 001450 하나뿐인 동안은 발화 금지** |

### 7-3. 🔴 `breakout_volume_mult` 1.0 → 0.7 은 **기각한다** (초안 §7 1순위에서 삭제)

초안은 이걸 3영업일 뒤 1순위로 예약했다. 적대적 검토가 옳게 지적했듯(부록 A F2/F6/plumbing-1) 그 배치는 **거짓 음성 위에서 자동 승격**되는 구조였고, 사용자가 오늘 승인하는 것이 사실상 "일주일 안의 품질 컷"이 돼 버린다. 도메인 판단으로 정면 기각한다:

> **거래량 없이 뚫는 건 안 뚫린 것이다.** `mult 0.7` 이 정당화되는 유일한 세계는 **"EOD 로도 일평균의 1.0× 를 못 채우는 돌파를 사겠다"** 인데, 그건 정의상 **가짜 돌파(fake breakout)** 이고 BFB 셋업의 존재 이유를 부정한다. 09-01 표본의 실패 돌파율 60% 가 바로 그 대역에서 나온다.
> 시계 편향은 **시계로 고친다**(`entry_end`, 또는 코드 사이클 ④ 경과비율 정규화). **임계로 고치면 그건 시정이 아니라 품질 매각이다.**

`mult` 를 다시 논의할 수 있는 유일한 조건 = **코드 사이클 ④(경과비율 정규화)가 배포돼 시계 편향이 제거된 뒤, 그 상태에서 N≥20 표본으로 통과 종목의 승률이 측정된 다음.** 그 전엔 어떤 관측치도 mult 인하를 지지할 수 없다.

### 7-4. 롤백 조건 (하나라도 걸리면 §4-3)
- (a) **하루 BFB 3건 이상 체결** = 과개방. (기대 0.15~0.35/일 기준 P≈0.5% — 경보로 적절)
- (b) 누적 5건 시점에 **승률 ≤ 1/5** **또는** 시점 무관 **누적 실현손실 > NAV 1.0%**(≈25,800원) — 둘 중 먼저. *(초안 "승률<20%"는 0/5 에서만 성립하는 공허 조건이라 정정.)*
- (c) `[bfb_vol_gate_pass]` 직후 **당일 −5% 손절 3연속** = 역선택 확증 → `retention` 1 복귀 **먼저**, `entry_end` 는 그 다음.

- (e) **신규** — 첫 3건 중 2건 이상이 `armed_at`/`pass_at` **14:00 이후**이고 전부 손절이면 `entry_end` 를 **13:30** 으로 (14:30 유지 vs 13:00 복귀의 중간값).

## 8. 대안과 기각 이유

1. **`breakout_volume_mult` 인하** — *기각(영구, §7-3).* 품질 매각.
2. **VCP `pullback_count_max` 4→6/8 또는 `volume_contraction_ratio` 상향** — *기각(측정으로 반증).* count_max 를 ∞ 로 열어도 추가 통과 **0/18**(뒤의 하드코딩 strict 단조수축이 전부 잡는다). ratio 는 이미 PARAM_RANGES 상한 1.0 이고 유일 생존 089860 은 last5/pre20 = 2.29 — 통과시키려면 "수축"의 의미가 반전된다. `last_pullback_max` 0.10→0.15 도 +0.
3. **비중/`position_ratio` 확대** — *기각(여지 없음).* BFB 0.25×4 = 1.00, VCP 0.20×5 = 1.00 으로 **이미 예산 상한**(실측). 증액은 마지막 슬롯 상시 부분매수를 뜻한다.
4. **후보 수 확대(`flag_lookback_min` 3→2, 유니버스 확대)** — *기각(병목 아님 + 부작용).* BFB 는 후보 25 중 15가 이미 돌파했는데 감지가 4건이다. 후보를 늘리면 breakout 구독 그룹(**LOW priority, `bypass_limit=False`**)의 슬롯 압력이 커져 **틱 미수신(R5)이 악화**된다.
5. **`entry_end` 15:20 까지 확장** — *기각.* 15:20~15:30 은 KRX 장후 동시호가이고 종가 단일가는 시장가를 접수한다(cycle229 실측). VB·momentum 에 15:20 매수 컷을 넣은 것과 같은 이유로 **오버나잇을 종가에 확정 체결**시키는 경로다. 상한 14:30(2차에서 최대 15:00).
6. **`max_scan_stocks` 자문 수동 적용** — *경고.* 라이브 4000 인데 PARAM_RANGES 상한 500 이라 클릭 시 유니버스 **87% 조용히 축소**. 09-02 pending 2건이 전부 이 키를 담고 있다. **클릭 금지.**

## 9. 반례 / 한계

- **예상되는 첫 실패 모드 = 09:05 첫 틱 갭업 체결** (검토 F9 — 한계가 아니라 *예보*). `_prev_price=0` 이라 창 개시 첫 틱이 곧 크로싱이고, retention=0 이면 **그 자리에서 게이트가 평가된다.** 통과 조건(개장 5분 누적 ≥ flag 일평균 ×1.0)은 **뉴스 갭업 프로파일에서만** 성립하며, 성립하면 되밀림 전에 체결된다. 방어는 추격 상한 5.0%(`max_breakout_extension_pct`, `current_price` 단독 판정)와 −5% 손절뿐. 3연속이면 롤백 (c) ≈ 14,400원 = NAV 0.56%. → **D+1 필수 점검: `[bfb_vol_gate_pass]` 의 발생 시각이 09:05:00~09:05:10 인가?**
- **entry_end 14:30 이 001450 을 못 산다.** §3-1 산술대로 14:30 시점 누적 ≈ 0.97× 로 아슬하게 미달이다. 이 노브가 사는 것은 **EOD 1.2~1.5× 대역**이고, 그 대역의 실제 빈도는 이 자문이 개별 확인하지 못했다.
- **swing 1.0 의 한계.** 1.5 에서 후보 0 으로 떨어지는 절벽(과병합). [0.8, 1.0] 은 3일 전부 동일 결과인 고원이지만 **그 고원은 고유 종목 2개 위에 서 있다.** 시장 변동성이 커지면(ATR 확대) 같은 1.0 이 더 큰 스윙만 세어 회수가 2 미만으로 떨어져 `pullback_count_min=2` 에 걸릴 수 있다. 후보가 다시 0 이 되면 이 방향을 먼저 의심한다.
- **표본 편중.** VCP 후보가 001450·105560·055550·086790·010955 등 **금융·대형주 편중**이다. 지금 시장에서 2단계 상승추세가 금융뿐이라는 레짐 정보이기도 하고, VCP 가 중소형 성장주를 잡도록 설계됐다는 원 의도와의 괴리이기도 하다. 첫 체결이 은행주여도 놀라지 말 것.
- **틱 레벨 시뮬레이션 부재.** BFB 기대치는 **일봉 EOD 거래량 + 로그 4건**의 역산이라 신뢰구간이 넓다. 실코드 재실행으로 확정된 수치는 **VCP 후보 수뿐**이다.
- **`_config_loaded` 계약의 일반적 함의(범위 밖·등재 권고).** 정상 운영일(재기동 없는 날)엔 **어떤 params UPDATE 도 07:45 에 반영되지 않는다.** 오늘은 06:22 재시작이 있었기에 SQL 이 "작동할 뻔"했을 뿐이고, 그 우연이 초안의 오류를 가렸다. 운영 문서에 "params 변경은 PUT 경로" 를 명문화할 것.

## 10. 후속 검증 권고 (tdd-engineer / tester)

1. **BFB `retention_min == 0` 경로 회귀** — 첫 크로싱 틱에서 (a) 거래량 미달 → `_arm_latch` + `Signal.NONE` (b) 충족 + 추격 상한 이내 → `Signal.BUY` (c) `"돌파 1차 감지"` 로그 **0건** · `[bfb_latch_armed]` 1건. *(cycle228 게이트 테스트 헬퍼 기본이 이미 `retention_minutes=0` 이라 사실상 존재 — 계약으로 못박기만 하면 된다.)*
2. **`entry_end` 파라미터화 회귀** — 14:30 로드 시 14:29 틱은 평가되고 14:31 은 시간 가드에 걸리는지. **소비처가 단 한 곳(`:933-935`)임을 AST 로 봉인** — 이 키가 다른 게이트에 결합되면 창 확장이 청산·구독 규약까지 바꾼다.
3. **`_prev_price=0` 갭상승 케이스** — 당일 첫 틱이 이미 `flag_high` 초과일 때 크로싱 성립 + 추격 상한이 실제로 거부하는지(합성: flag_high 대비 +4.9% / +5.1% 경계).
4. **VCP `min_swing_atr_mult` 파라미터화 회귀** — 0.5 와 1.0 에서 `last_pullback_count` 가 실제로 달라지는지. 현행 테스트가 이 축을 고정하고 있으면 완화가 **무음으로 무력화**된다.
5. **DB params 로더 계약** — `breakout_retention_minutes: 0` 이 PARAM_RANGES 하한 밖인데도 로더가 그대로 싣는다는 사실을 테스트로 못박을 것. 현행은 **검증 부재가 우연히 유리하게 작동**하는 상태 = 언제든 "범위 검증 추가" 리팩토링에 조용히 죽는다.
6. **`PUT /{id}/params` 계약** — 라우트가 (a) 메모리 dict 를 갱신하고 (b) **params 전체**를 DB 에 쓴다는 두 사실을 테스트로 고정. (b) 의 부작용(코드 기본값 전파 차단)이 계약임을 명시.
7. **`_config_loaded` 1회 계약** — `_boot()` 재호출이 DB 를 다시 읽지 **않는다**는 것을 테스트로 못박을 것(오늘의 F1 이 문서 신뢰만으로 잡히지 않았다).
8. **VCP `breakeven_promote_atr` 최초 실가동** — donchian cycle237(래칫 부재 → 매 틱 로그 폭주, 단일 종목 하루 11,453건)과 동형인지 첫 체결 전에 코드 레벨로 확인.
