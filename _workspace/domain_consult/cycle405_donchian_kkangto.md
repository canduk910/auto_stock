# cycle405 — donchian 개조 명세(깡토식 청산·사이징) + 현행 대비 재현 (자문)

**쉬운 말 결론**

1. **명세를 확정했다.** 진입·유니버스는 그대로 둔다. 청산은 「−1R 손절 → 3R 에서 본전 → 3R 뒤에만 10일 저가 → 20번째 봉까지 +1R 못 닿으면 15:20 정리」 다. 사이징은 「한 번 틀리면 예산의 1.2% 를 잃는 수량」 이고 1주 폴백은 없다. 슬롯 6 · 종목당 15% · 하루 신규 3종목.
2. **사전 등록 판정은 「미통과」다.** 셋 중 둘(낙폭 · 거래당 R)은 넘었다. 하나(수익 차의 구간 하한 > 0)를 0.64%p 차이로 못 넘었다. 점추정은 개조 쪽이 연 +13%p 낫다(현행 −6.7% → 개조 +5.0%, W4). 규칙대로 대신 고를 판은 없고, **진행 여부는 사용자 결정**으로 돌린다(§11 D1).
3. **8영역과 `scheduler.py` 는 건드리지 않는다.** 바꿀 파일은 `donchian_swing.py` 가 중심이다. 15:20 시간 청산을 붙이려면 `strategy_manifest.py` 의 칸 하나(`close_at_1520`)를 켠다. 새 키 등록은 `param_catalog.py` 다.
4. **「오늘 ATR」(카드 2)은 닫힌다.** 샹들리에가 없어져서 보유 중 ATR 을 쓰는 청산선이 남지 않는다. R 은 매수 시점 ATR 로 한 번 정하고 바꾸지 않는다.
5. **알고 들어가야 할 비용 셋.** ① 지금 예산(743,000원)에서는 신호의 34% 를 사지 못한다(111,450원보다 비싼 종목). ② 이익은 드문 큰 승리에서 온다. 상위 1% 거래를 빼면 거래당 R 이 음수(−0.07)다. ③ 운영 35건에 얹어 보면 오히려 나빴다(−0.92% → −1.62%, 방향만). 2021~2022 진입 거래도 음수였다.

## 2. 청산 명세 (확정)

### 2.1 항목별 결정

| 항목 | 결정 | 산식 · 이유 |
|---|---|---|
| **R(1R 폭)** | 바꾼다 | `R = max(0.08 × E, 1.5 × entry_atr)`. E = `pos.buy_price`, `entry_atr` = 지금 스탬프 그대로(`_atr` SMA14, D−1 창, `int`). 스탬프가 없으면 ATR 항을 0 으로 보고 `R = 0.08 × E`(조이는 쪽) |
| **첫 손절** | 바꾼다 | 가격 ≤ `E − R` → `STOP_LOSS`. 장중 틱 · 60초 폴 그대로 |
| `stop_atr`(2N 손절) | 끈다 | R 이 대신한다 |
| `turtle_backstop_pct`(−9%) | 끈다 | 8% 하한이 받침선 역할을 한다. R > 9% 인 거래가 16% 다(p90 10.1% · p99 14.7%, [실측] W4 거래 단위). 그 거래는 수량이 R 로 줄어 있어 원화 손실은 같다(예산 1.2%) |
| `stop_loss_rate`(미스탬프 −6%) | 끈다 | 모든 랏이 스탬프된다(폴백이 없다). 스탬프가 사라진 재시작 랏은 R = 8% 를 탄다 |
| **본전 승격** | 바꾼다 | `high_since_buy ≥ E + 3R` 이면 손절선 = `max(E − R, E)`. 고점은 단조 증가라 한 번 서면 계속 선다(래칫 상태 불필요) |
| `breakeven_promote_atr`(1.5N) | 끈다 | 3R 이 대신한다 |
| **10일 저가 채널** | 조건을 바꾼다 | **3R 도달 뒤에만** 가격 < `_channel_low` → `TRAILING_STOP`. 3R 전에는 추적 청산이 없다. `channel_exit_period` 10 그대로 |
| 샹들리에(`atr_trail_mult` 1.8) | 끈다 | 깡토 청산에 없다 |
| 돌파 실패(`breakout_fail_n_days` 2) | 끈다 | 20봉 시간 청산이 대신한다. 현행 청산의 46% 가 이것이었다([실측] 거래 단위) — 「빨리 자르는」 몸의 핵심이라 반드시 꺼야 한다 |
| **20봉 시간 청산** | 새로 | 진입봉 포함 20번째 봉(보유 19영업일)의 15:20 판정에서 `high_since_buy < E + 1R` 이면 → `TIME_EXIT`(마감 동시호가 체결 ≈ 그날 종가). 한 번이라도 +1R 에 닿았으면 시간 청산 대상이 아니다 |
| **최대 보유** | 새로 | 보유 249영업일 이상(250번째 봉) 15:20 → `TIME_EXIT`. 드물다(W4 거래 단위 1,827건 중 2건) |
| 불타기 · 점진적 베팅 | 넣지 않는다 | 사용자 결정 |

**청산 사유 이름**: 손절·본전 손절 = `STOP_LOSS` · 3R 뒤 채널 = `TRAILING_STOP` · 20봉 · 250봉 = `TIME_EXIT`. 본전 손절도 지금처럼 `STOP_LOSS` 다(새 이름을 만들지 않는다).

### 2.2 「오늘 ATR」(카드 2) — 닫힌다

- cycle367 §2 의 문제는 **샹들리에가 어느 날의 ATR 을 쓰느냐**였다. 개조 뒤에는 샹들리에가 없다.
- 남는 ATR 소비처는 R 하나다. R 은 깡토 원문대로 **매수 시점 ATR 로 한 번 정하고 바꾸지 않는다**(손절선을 보유 중 ATR 로 움직이면 사이징과 손절의 커플링이 깨진다).
- 따라서 `_position_atr` 신설 · 트레일링 ATR 우선순위 헬퍼는 **만들지 않는다**. 카드 2 는 「대상 소멸로 종결」 이다.

### 2.3 집행 시점

| 규칙 | 운영 | 재현 모사 |
|---|---|---|
| −1R · 본전 손절 | 틱(`risk.on_tick`) + 09:30~15:20 60초 REST 폴. 보드 무관(프리장·애프터 포함 — `tradable_boards` 는 매수 전용) | 봉 안 경로(양봉 시→저→고→종, 음봉 시→고→저→종). 선에 닿으면 선 가격, 시가가 이미 아래면 시가 |
| 3R 뒤 채널 | 같다(장중 이탈) | 같다. 보고판 V6(종가 확인 → 다음 날 시가)도 돌렸다 |
| 20봉 · 250봉 | **15:20 `check_force_clear`** → `force_clear_signal` = `TIME_EXIT` | 그날 종가. 보고판 V3(21번째 봉 시가)와 결과가 같았다(+13.07 대 +13.04%p) |

- 15:20 을 고른 이유 [추정]: ① 재현이 「그날 종가」 이고 마감 동시호가가 그 값이다 ② 시간 청산을 `check_exit_signal` 에 두면 다음 날 첫 틱 — NXT 상장 종목은 08:00 프리장 얇은 호가 — 에 시장가가 나간다 ③ 시간 조건은 가격과 무관(고점·보유일만)이라 etf_trend 가 겪은 「15:20 시세 stale」 문제가 없다. 15:20 을 놓치면(재시작·매도 거부) 다음 날 15:20 이 다시 잡는다(조건이 계속 참이다). `check_exit_signal` 쪽 안전망은 두지 않는다.
- 15:30 이후 호출은 `_force_clear_main_only` 의 시간 가드가 이미 건너뛴다[코드 `scheduler.py:1965`].
- **애프터마켓(16:00~20:00)** — 손절·채널은 애프터 틱에도 발화한다(지금과 같다). 애프터 고가가 `high_since_buy` 를 올려 3R 무장을 앞당길 수 있다 = 조이는 쪽. 애프터 체결은 일봉(정규장)에 없어서 재현이 모사하지 못한다(두 책 공통 한계).

### 2.5 화면 손절가 미러

- `check_exit_signal` 과 `get_effective_stop_price` 가 **같은 헬퍼**(예: `_kk_exit_lines(ticker, pos)` → (손절선, 무장 여부, 채널선 또는 None))를 쓴다.

## 3. 사이징 명세 (확정)

| 항목 | 결정 |
|---|---|
| 수량 | `q = floor(B × m × risk_pct ÷ R)` → `min(q, 잔여 // 가격, int(B × m × position_ratio) // 가격)`. R 은 사이징 시점 현재가로 `max(0.08 × P, 1.5 × ATR)` |

| K축 `max_lot_units` 2.0 | 그대로 둔다. 사이즈드 랏은 `q ≤ 0.012B ÷ 1.5N < 2 × 0.012B ÷ N` 이라 **항등적으로 닿지 않는다** |
| ρ축 `max_lot_ratio_mult` 2.5 | 그대로 둔다. 명목 ≤ 0.15B < 2.5 × 0.15B 라 **닿지 않는다** |
| 관문 순서 | 무접촉. q > 0 만 `_apply_budget_limit` 에 넘기고 q = 0 은 상수 `return 0`(A-GATE 허용 형태) |

### 6.4 전환 방식 — 권고: **구 규칙 대체(모드 키 없음)**

- 비상 브레이크는 이미 있다 — `buy_paused`(신규 매수만 멈춤, 청산은 그대로).

## 9. 반례 · 한계

- **판정 미통과.** 구간이 0 을 품는다. 「개조가 낫다」 는 점추정과 방향의 주장이지 확정이 아니다.

## 10. 후속 검증 권고 (tdd-engineer 에게 — 결정적 입력 시리즈)

1. **R 두 갈래**: E = 100,000 · N = 4,000 → R = 8,000(하한) · N = 6,000 → R = 9,000. 손절 가격이 각각 92,000 · 91,000.
2. **3R 무장**: 고점이 E + 3R − 1 이면 채널 무시 · E + 3R 이면 손절선 = E 이고 채널 이탈 시 `TRAILING_STOP`. 무장 전 채널 이탈은 `NONE`.
3. **20봉 15:20**: 보유 19영업일 · 고점 < E + R → `check_force_clear` 에 포함 · 사유 `TIME_EXIT`. 고점 = E + R 이면 제외. 보유 18영업일이면 제외. 15:20 을 놓친 다음 날 15:20 에 다시 포함.
4. **재시작**: `_entry_atr` 없음 → R = 0.08E. 재도출 성공 → 원래 R.
5. **미러 일치**: 같은 상태에서 `get_effective_stop_price` = `check_exit_signal` 이 쓰는 가격선의 max.
6. **사이징**: 예산 743,000 · 가격 111,450 · N 작음 → 1주 / 가격 111,451 → 0 → 신호 단계 `NONE` + 마커(수량 0 이 `execute_buy` 로 가지 않는다). m = 0.5 → 설계 랏 절반, 폴백 없음.
7. **하루 3종목**: 그날 매수 3건 뒤 네 번째 신호 `NONE`. 재시작 뒤에도 같다(매수일 = 오늘인 보유로 센다).
8. **가드 무접촉**: K축 · ρ축이 사이즈드 랏 수량을 바꾸지 않음 · `_apply_budget_limit` 본문 무변경.

## 12. donchian 비중 — kojiro 에서 떼어 와 키울 때 (추가 자문, 2026-10-03 10:3x)

**사용자 결정(10-03)**: D1 = 명세대로 개조를 진행한다. donchian 비중은 kojiro 에서 떼어 와 키운다(「kojiro 는 안 건드림」 해제). 비중 PUT 은 개조 배포 때 메인 세션이 한다.

**쉬운 말 결론**: **w = 0.25 를 권한다.** kojiro 는 0.329 가 된다. 사지 못하는 신호가 34% → 21% 로 줄고, 1주 랏이 44% → 29% 로 준다. 0.25 를 넘기면 이득은 거의 늘지 않는다. 반면 kojiro 는 지금 보유가 정하는 하한(약 0.203)에 가까워지고, 아직 우위가 확정되지 않은 전략에 계좌가 더 몰린다.

- 표기는 위와 같다. 이 절의 재현은 **보고판**이다. §4 의 사전 등록 판정(미통과)은 그대로 두고 다시 쓰지 않는다.
- 재현: [`c405/c405_weight.py`](c405/c405_weight.py) → `c405/weight_results.json`. `c405_sim.py` 를 그대로 쓰고 시작 자산만 바꿨다. 씨앗 16개 · W4 · 시장 유닛 enforce · 같은 방법이다.

### 12.2 kojiro 하한 — 비중 라우트가 거부하는 선

**라우트 산식** [코드 `src/routes/strategies.py:311-332`]:
- `total_asset = Σ strategy.state.total_investment`(전 전략, 부팅 때 `allocate_funds` 가 나눈 값)
- `invested = Σ pos.buy_price × pos.quantity`(그 전략 보유 매수원가)
- `new_weight < invested ÷ total_asset` 이면 거부한다(`success=false`, 「최소 n% 이상이어야 합니다」).

**자문 적용 경로** [코드 `src/routes/recommendations.py:50-93, 248-251`]는 다르다. 보유 중인 전략의 **비중 0** 만 막는다(`_reject_zero_weight_if_held`). 보유 비율 하한은 검사하지 않는다. 그래서 하한선은 `PUT /api/strategies/weights` 에서만 걸린다. 비중 이동은 그 라우트로 하는 것이 맞다.

**kojiro 보유** [실측, 2026-10-03 10:31 KST, `BEGIN READ ONLY`]:

- `total_asset` ≈ 4,955,600 × 0.95 = 4,707,820(10-02 기준 추정 — 라우트는 그날 부팅 값을 쓴다).

### 12.3 반도체 묶음 노출 (cycle400 의 6종목)

- 묶음 6종목 = 와이씨(BFB) · 월덱스(VCP) · GST · 서울반도체 · SKC(이상 kojiro) · 티이엠씨(BFB)다[인용 cycle400 §3].
- kojiro 몫 3종목의 매수원가 = 150,600 + 201,020 + 108,000 = **459,620원(순자산의 9.3%)**[실측].
- **비중을 옮겨도 지금 노출은 그대로다.** 보유를 팔지 않기 때문이다.
- **앞으로 생길 노출의 모양은 바뀐다**[추정]:
  - kojiro 의 종목당 명목이 329,000 → 257,000원(w = 0.25)으로 줄어, 묶음 종목 하나가 kojiro 로 들어올 때의 크기가 작아진다.
  - donchian 의 종목당 상한은 111,500 → 176,500원으로 커진다. donchian 유니버스(코스피200 · 코스닥150)에는 반도체 대형주가 많다. 한 계좌로 보면 「묶음 종목 한 개의 최대 명목」 은 비슷하다(두 전략 칸 중 큰 쪽이 257,000원).
  - 같은 종목코드는 두 전략이 동시에 못 산다. 하지만 **같은 묶음의 다른 종목은 막는 장치가 없다**(cycle400 — 계좌 묶음 상한은 아직 다크런치다). donchian 이 커지면 반도체 장에서 kojiro · BFB · VCP 와 함께 같은 묶음을 더 담을 수 있다.
  - donchian 은 하루 신규 3종목 · 종목당 15% 라 한 묶음에 단숨에 몰리는 폭이 kojiro(칸 6, 0.166)보다 작다.
- 결론: 비중 이동이 묶음 위험을 줄이지도 키우지도 않는다. 묶음 위험은 cycle400 의 계좌 묶음 상한이 맡을 일이다.

### 12.4 권고 — **w = 0.25**(kojiro 0.329)

1. **랏 문제를 가장 크게 푸는 구간이 여기까지다.** 무매수 34% → 21%, 1주 랏 44% → 29%, 랏 중앙 2 → 3주. 랏이 3주가 되면 「1주 언저리라 성과 귀인이 무너진다」(메모리 `project_lot_geometry`)가 상당히 풀린다.
2. **그 뒤로는 수익이 거의 늘지 않는다.** 산술 연 수익이 0.25 에서 +9.6%, 0.35 에서 +9.9% 다. 낙폭 비율은 비중과 무관하다.
3. **아직 확정되지 않은 우위에 계좌를 너무 많이 싣지 않는다.** §4 판정은 미통과(하한 −0.64%p)다. 0.25 면 계좌의 4분의 1 이다. 0.35 면 3분의 1 을 넘는다.
4. **kojiro 하한과 여유를 둔다.** 0.329 는 하한 0.203 보다 0.126 높다. 0.35 안(kojiro 0.229)은 여유가 0.026 뿐이라 kojiro 가 한 종목만 더 사도 다음 비중 조정이 막힌다.
5. 0.20 은 무매수가 27% 로 여전히 크다. 사용자가 「키운다」 고 정한 취지에 비해 변화가 작다.

- **반례**: kojiro 가 앞으로 donchian 개조보다 잘 벌면 이 이동은 손해다. 이번에는 재지 않았다(§12.2). 또 donchian 의 이익은 상위 1% 거래에 기대므로(§4.4), 예산을 키우면 그 몇 건을 잡았을 때와 놓쳤을 때의 차이도 원화로 같이 커진다.
- **집행 메모**: `PUT /api/strategies/weights` 로 donchian 0.25 · kojiro 0.329, 나머지 그대로(Σ = 1.0). 직전에 kojiro `min_weight` 를 화면에서 다시 확인한다. 반영은 즉시 `allocate_funds` 다.
