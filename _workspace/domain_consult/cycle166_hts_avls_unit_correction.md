# 자문: 사이클 166 — hts_avls 시가총액 단위 결함 시정의 시총 단위 통일 기준

- 의뢰자: team-leader
- 의뢰일: 2026-06-19
- 긴급도: HIGH (매매 기회 손실 직결 — 후보 풀 95.4% 축소)

## 질문 요약

`stock_master.raw.hts_avls`(KIS FHKST01010100 시가총액)의 실제 단위가 **억원**인데, 시총 필터 코드 전반이 **백만원**으로 가정 → 100배 어긋남. 운영 DB 실측 + KIS 정본 + median 933억원 분포가 모두 억원으로 수렴(확정). 결함으로 min_market_cap=1,000억 케이스에서 후보 풀이 1,734 → 80(시총 10조 이상만 통과)으로 95.4% 축소. 시총 단위를 어느 기준으로 통일할지, DB 재적재가 필요한지, KRX 폴백 경로 정합, 헬퍼 명명, 후보 풀 21배 확대에 따른 안전망 충분성을 자문.

## 트레이더 시각

### 시장 가설

후보 풀 시총 하한(VCP/LTV 1,000억, donchian 500억)은 "유동성과 정보 효율성이 충분한 중대형주만 추세·돌파 전략의 신뢰할 만한 모집단"이라는 가설에 기반한다. 현 결함은 이 하한을 **10조원으로 사실상 100배 끌어올린** 상태 — KOSPI 시총 상위 ~80종목(삼성전자/SK하이닉스/현대차 급)만 남는다. 이는 트레이더 관점에서 치명적이다:

- **VB/LTV 변동성 돌파의 본질**은 중형주의 갭·급등 변동성을 노리는 것인데, 시총 10조 초대형주는 변동성이 구조적으로 낮아 K값 돌파 자체가 드물다. 즉 결함 상태에서는 전략이 "가장 안 맞는 모집단"만 스캔하고 있었다.
- **donchian 20일 신고가 돌파**는 중형 성장주에서 가장 잘 작동한다. 초대형주는 이미 가격 발견이 끝나 신고가 갱신 빈도가 낮다.
- **VCP 베이스 형성**도 중형주 특성. 초대형주는 베이스가 길고 폭발력이 약하다.

따라서 시정으로 1,000억~10조 종목 1,654개를 회복하는 것은 단순한 "후보 수 증가"가 아니라 **각 전략이 설계된 모집단을 비로소 스캔하게 되는** 본질 회복이다.

### 실전 사례 / 통계

- median hts_avls = 933 → median 933억원. 한국 상장사(2,800여 종목) 중앙값 시총이 900억~1,000억 수준인 것은 증권 도메인 상식과 정확히 일치. 만약 백만원 단위였다면 median 시총이 9.33억원이 되어 한국 코스닥 최소 상장요건(자기자본 기준)에도 못 미치는 비현실적 수치 — 단위 억원 확정의 강력한 정황.
- 삼성전자 hts_avls=20,812,752 → 20,812,752억원 = 약 2,081조? 아니다. 20,812,752억 = 2,081조가 아니라 **208조** (20,812,752 × 1억 = 20,812,752 × 10^8 = 2.08 × 10^15 = 208경?). 재검산: 20,812,752억원 = 20,812,752 × 10^8원 = 2.08 × 10^15원 = 2,081조원. 삼성전자 실제 시총 ~400조 대비 과대. **이 불일치는 의뢰 검증에서 prdy_avls_scal=21,192,759(억, 비율 0.98)로 raw.hts_avls와 동일 스케일임이 교차 확인되었으므로, hts_avls 절대값 자체가 KIS 응답 시점/기준의 특성(예: 우선주 합산 또는 상장주식수 전체 기준)일 가능성. 단, 본 자문의 핵심인 "단위=억원" 결론은 9종목 ÷10^8 실측으로 독립 확정되어 영향 없음.** team-leader 검증 시 삼성전자 절대값 정합은 부차 확인 권고(단위 결정에는 무영향).

### 위험 시나리오

1. **후보 풀 21배 급확대로 작전주·저유동성 중소형주 유입** — 1,000억~3,000억 구간에는 거래대금이 얕은 종목이 다수. 시세 구독 슬롯(MAX_SUBSCRIPTIONS=41) 경쟁 격화 + WebSocket stale 위험 증가.
2. **단위 혼재 미시정 시 사일런트 재발** — KIS 경로(억원)와 KRX 폴백 경로(백만원)가 같은 hts_avls 컬럼에 공존하면, KRX 폴백이 발화한 종목만 시총이 100배 과소 평가되어 후보에서 잘못 탈락하는 별개의 사일런트 결함 잔존.
3. **헬퍼 명명-단위 불일치로 미래 호출자 오용** — `get_market_cap_millions`가 억원을 반환하면 함수명을 믿은 미래 코드가 다시 100배 오류.

## 정량 권고

### Q1 — 시총 단위 통일 기준: **억원 기준 통일 (옵션 A) 권고**

| 방향 | 장점 | 단점 |
|------|------|------|
| **A. 억원 기준 통일 (권고)** | KIS 정본·실측·운영 DB 적재값 모두 억원 → 자연 정합. DB 재적재 0. 매일 16:10 task가 억원으로 덮어쓰므로 영구 정합. 변경 면적 최소(비교 임계식만) | 함수명 `_millions` 잔재 → Q4에서 명명 정리 필요 |
| B. 백만원 내부표준 유지 + hts_avls ×100 환산 | 함수명 `_millions` 의미 보존 | 매일 적재되는 raw.hts_avls(억원)를 매 비교마다 ×100 환산 — 환산 누락 시 사일런트 재발. master_raw(prdy_avls_scal 억원) vs raw(hts_avls 억원) 단위가 같은데 코드만 백만원으로 끌어올리는 인위적 변환 → 미래 혼동 가중 |

**근거**: 데이터 소스(KIS FHKST01010100 hts_avls + KIS 마스터 prdy_avls_scal)가 **둘 다 억원**이라는 것이 실측으로 확정됐다. 데이터가 억원으로 통일돼 있는데 코드 내부 표준만 백만원으로 유지하는 것은 변환 레이어를 인위적으로 추가하는 것 — 트레이더 관점에서 "원천이 억원이면 억원으로 다루는 것"이 정합. 전략 레이어가 이미 `min_market_cap`을 **원 단위**로 전달(VCP/LTV 100_000_000_000원, donchian 50_000_000_000원)하고 step_conditions 라벨도 `÷100_000_000`(억)으로 표시하므로, **원 ↔ 억원 변환(÷10^8)이 가장 자연스럽고 변환 지점이 명확**하다.

### Q2 — DB 재적재 필요 여부: **재적재 불필요**

raw.hts_avls는 이미 억원으로 적재돼 있고 매일 16:10 KIS task가 억원으로 덮어쓴다. **비교 코드만 억원 기준으로 시정하면 자연 정합** — 재적재 0. 이것이 옵션 A의 결정적 이점.

단, **사이클116 KRX 폴백 경로(백만원 저장)로 적재된 잔존 종목**이 DB에 있다면 그 종목들의 hts_avls는 100배 과소 상태로 남는다(Q3 참조). KIS 1차 성공률이 높아(운영 실측 99%+) 잔존 수는 적을 것으로 추정되나, team-leader가 Supabase MCP로 "raw.hts_avls < 100"인 종목 수를 실측해 잔존 KRX 폴백 적재분 규모를 확인 권고. 매일 16:10 task가 KIS 억원으로 덮어쓰므로 D+1에 자연 정합되지만, 당일 시정 직후~16:10 사이 윈도우는 잔존 가능.

### Q3 — KRX MKTCAP 폴백 경로 정합: **억원으로 통일 (// 100_000_000), 우선순위 MEDIUM**

KIS 경로가 억원으로 통일되면 같은 hts_avls 컬럼의 KRX 폴백도 반드시 억원이어야 한다. 현재 `mktcap_won // 1_000_000`(백만원) → `mktcap_won // 100_000_000`(억원)으로 시정. **단위 혼재는 사일런트 결함의 온상**이므로 같은 사이클에서 함께 시정 권고(분리하면 KRX 폴백 발화 종목만 100배 과소 → 별개 사일런트). 발화 빈도는 낮지만(KIS 1차 성공 시 미발화) 단위 일관성은 빈도와 무관하게 보장해야 한다.

주의: `mktcap_won // 100_000_000`은 1,000억 미만 종목에서 정수 절삭으로 0이 될 수 있다(예: 500억 → 500). 500억은 500억원 = 500 → 정상. 50억원 종목 → 50 → 정상. 5억원 종목 → 5. 5천만원 종목 → 0(절삭). 5천만원 시총은 비현실적이므로 실무상 무해하나, donchian 500억 하한 케이스에서 정수 절삭 경계 검증 회귀 가드 권고.

### Q4 — 헬퍼 명명: **함수명을 억원 기준으로 정리 (옵션 A 연장), 단 행위 보존 우선 단계적 접근**

`get_market_cap_millions` / `market_cap_master_to_millions`가 억원을 반환하게 되면 `_millions` 명명은 거짓이 된다. 그러나 이 두 헬퍼는 호출처가 여럿이고 사이클 129/153/155에서 영속 의무가 걸려 있어, **명명 변경은 행위 보존 리팩토링 영역**이다. 트레이더 관점 권고:

- **사이클 166 (이번)**: 단위 정합만 시정 — `get_market_cap_millions`의 2순위 raw.hts_avls 폴백을 `int(hts_avls)` 그대로(억원) 반환하도록 하고, `market_cap_master_to_millions`(prdy_avls_scal × 100)는 **단위 결정 필요**. 만약 내부 표준을 억원으로 통일하면 이 함수는 `× 1`(즉 prdy_avls_scal 억원을 그대로 억원 반환)이 되어야 하며 `× 100` 폐기. 함수명/시그너처 변경은 사이클 166 범위에서 최소화하되, **반환 단위가 억원임을 docstring + AST 가드로 명문화**.
- **명명 정리(`_millions` → `_eok` 또는 `_billion_won`)는 사이클 167+ 행위 보존 리팩토링으로 분리** — refactor-expert 검토. 한 사이클에서 단위 결정 + 명명 변경 + 호출처 일괄 변경을 모두 하면 리뷰 면적이 과대.

핵심: **사이클 166은 "비교가 올바른 결과를 내는가"가 목표** — 함수명 미관은 후속. 단, 단위가 억원임을 코드 내 상수/주석/AST로 못박아 미래 오용 차단.

### Q5 — 매매 안전성: **기존 안전망으로 충분, 단 후보 풀 폭증 모니터링 의무**

후보 풀 80 → 1,734(21배)는 외형상 급확대지만, **다층 안전망이 매수 진입 직전까지 작동**한다:

1. **거래대금 필터(사이클 65)** — `min_trade_amount` 임계로 저유동성주 차단. 이것이 작전주 1차 방어선. 단, 디폴트 0(비활성)이면 무효이므로 team-leader가 전략별 `min_trade_amount` 설정값 실측 확인 권고.
2. **가격 필터(사이클 64/148/151)** — price_filter_min/max로 동전주·초고가주 차단.
3. **1단계 차단 13건(사이클 129/155)** — 거래정지/관리종목/공매도과열/이상급등/정리매매/시장경고/투자주의환기. 작전주는 통상 시장경고·투자주의환기에 걸리므로 이 hook이 핵심 방어선.
4. **시세 구독 슬롯 우선순위(MAX_SUBSCRIPTIONS=41, HIGH bypass)** — 보유/익일청산 절대 보장. 후보 풀이 커져도 매수 후보는 LOW 우선순위로 슬롯 경쟁 → 보유 종목 시세는 영향 0.
5. **각 전략 prepare의 추가 컷** — VB K값/LTV consecutive_limit/donchian 신고가/VCP 베이스 등 종목별 정성 조건이 1,734 중 실제 매수 신호로 좁힌다. 후보 풀 확대가 곧 매수 폭증이 아니다.

**결론**: 후보 풀 21배 확대는 "각 전략이 설계 모집단을 회복하는 것"이며, 매수 진입 직전까지 5중 안전망이 작동하므로 **추가 가드 불필요**. 다만:

- **권고 모니터링 지표**: 시정 D+1 운영에서 (a) 후보 풀 실측 종목 수 (b) 시세 구독 slot 경쟁/stale 비율 (c) 일일 매수 신호 빈도 변화 (d) 신규 진입 종목의 시총 분포(1,000억~3,000억 비중). 만약 저유동성 중소형주 매수가 급증하면 그때 `min_trade_amount` 상향으로 대응(코드 변경 0, Settings UI).
- **사이클 38 명문화 영속 확인**: 이 영역은 전부 scanner 매수 진입 *전* 후보 풀 한정. 매도/손절/Trailing/익일청산/15:20 강제청산 hot path 변경 0. risk.on_tick / order_engine / realtime / auth 변경 0.

- **반례 1 [team-leader 검증 완료 — 동일 결함 확정]**: `list_paged_by_filter`(UI 페이징, 사이클 128)도 **동일 결함 전파 확정**. 추적 결과: `GET /stock-master/list` 라우트가 UI 입력(억원) → `_eok_to_won`(×10^8) → 원 단위로 `list_paged_by_filter(min_market_cap=...)` 전달. 그런데 `list_paged_by_filter` 내부 L431 `(min_market_cap + 999_999) // 1_000_000`(원→백만원) 후 `raw->'hts_avls'`(실제 억원) jsonb 비교 → **100배 어긋남**. 사용자가 UI에서 "1,000억" 입력 시 hts_avls≥100,000(10조) = 80종목만 표시. **scanner 경로(list_by_filter)와 UI 경로(list_paged_by_filter)가 같은 결함을 공유** → 사이클 166 범위에 **함께 포함 권고**(같은 함수 패턴, 분리 시 한쪽만 시정되는 비대칭 잔존). 프론트 표시 환산(StockMaster.tsx L226 "백만원→억원" 환산)은 별개 표시 로직으로, hts_avls를 백만원으로 가정해 표시 → **표시 환산도 100배 과대/과소 가능**(LOW, 표시 영역). team-leader가 프론트 표시 환산 정합도 사이클 166 또는 후속에서 확인 권고.
- **거래대금(acml_tr_pbmn) 정합 확인 완료**: 거래대금 필터는 원 단위로 일관(scanner + UI 라우트 `_eok_to_won` 억원→원 후 원 단위 비교) → **결함 없음**. 시정 범위는 시총(hts_avls)에 국한.
- **반례 2**: 삼성전자 hts_avls 절대값(20,812,752억=2,081조)이 실제 시총(~400조)과 5배 차이. 단위=억원 결론은 9종목 ÷10^8 실측으로 독립 확정되나, **hts_avls가 "상장주식수 전체 × 현재가"(우선주·자사주 포함)** 등 KIS 산출 기준 특성일 수 있음. 필터 임계 비교에는 무영향(상대 비교 일관)이나, UI에 "시가총액"으로 표시 시 사용자가 HTS 값과 다르다고 오인 가능. UI 라벨에 "(KIS hts_avls 기준)" 주석 권고는 LOW.
