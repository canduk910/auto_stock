# 자문: ndx2x_riskoff 나스닥100 일봉 적재 정지(10-09 이후) — 고치는 방식 선택

- 의뢰자: 메인 세션
- 의뢰일: 2026-10-16
- 긴급도: MEDIUM (섀도·비중 0 — 매매 영향 0, 신호만 낡음)
- 범위: `src/engine/ndx2x_ingest.py` + `src/engine/ndx2x_core.py` 순수 함수. 8영역·`scheduler.py` 무접촉. 새 기능 제안 없음.

## 질문 요약

`ensure_history` 의 widening 루프가 `len(collected_dates) < target_days` 로 돈다. `collected_dates` 가 DB 기존 날짜(397)로 시작하므로 이력이 이미 300 을 넘으면 루프가 0회 — 새 봉을 영원히 못 받는다(DB max = 2026-10-09). 고치는 방식으로 (1) 「기간을 늘려 잡기」(이번 실행에 받은 날짜 수 기준으로 매번 넓게 받기) 와 (2) 「슬라이딩」(최근 창만 증분 + 이력이 짧을 때만 widening backfill) 중 어느 쪽이 좋은가.

## 트레이더 시각

### 시장 가설(이 데이터가 지켜야 할 것)

규칙 C 는 느린 신호다(SMA120 의 20일 기울기 · 250일 최고종가 대비 −20%). 이 신호를 망가뜨리는 것은 「며칠 늦는 것」보다 **「틀린 값 하나」** 다. 특히 R4 는 250일 창의 **최댓값 하나**로 결정된다 — 과거 구간에 잘못된 종가 한 줄이 끼면 가짜 고점이 250일 동안 R4 를 끌어내리고 현금 칸 `01` 을 거짓으로 켤 수 있다. 그래서 적재는 「매일 새 봉 하나를 확실히 붙이고, 이미 확정된 과거는 되도록 건드리지 않는다」가 트레이더 본능에 맞다.

### 실측 사실

- `fetch_daily_chartprice` 1회 = 최대 100행(최신순), `tr_cont` 다음조회 불가.
- 현재 창 폭 `_WINDOW_CALENDAR_DAYS=160` ≈ 미국 영업일 110 → 캡 100 에 걸려 **가장 오래된 쪽이 잘린다**. 테스트(`test_cycle443_ndx2x_ingest.py:69~75`)도 「100 캡 뒤 시작 근처 5일 누락」으로 quirk 를 모사한다. 즉 quirk 는 **창의 과거 끝(시작일)** 에서만 생긴다 → 새 봉이 들어오는 최신 끝은 안전하다.
- 10-12(콜럼버스 데이)는 NYSE·나스닥 **정상 개장**(채권시장만 휴장). 10-16 KST 아침 기준 빠진 미국 영업일 = 10-12·13·14·15 **4일**.

### 위험 시나리오

1. 넓은 창을 매일 다시 받아 「새 배치 우선」으로 덮으면, KIS 가 어느 날 이상값(장중값·0·소수점 깨짐)을 한 줄 주는 순간 300일 이력 어디든 오염된다 → R4 가짜 고점.
2. 이력 중간 구멍(미국 영업일 하나 누락)은 `decide_daily` 가 날짜가 아니라 **리스트 위치**로 세기 때문에 T7 의 20일 시차가 21일로, R4 창이 251일로 조용히 늘어난다 — fail-closed 로 잡히지 않는다(`n ≥ 250` 이고 NaN 도 아니니 `reason="ok"`). 연구 함수와의 「날짜별 완전 일치」 요건이 깨진다.
3. 적재 실패 시 지금 코드는 낡은 종가로 `reason="ok"` 판단을 그대로 낸다(아래 「정합성」 참조).

## 두 방식 비교

| 축 | (1) 기간을 늘려 잡기(매번 넓은 창) | (2) 슬라이딩(증분 + 짧을 때만 backfill) |
|---|---|---|
| KIS 호출 수/일 | 300일 목표면 **3~4회 매일** | 정상일 **1회**, 주말·휴장 뒤도 1회. backfill 은 최초·이력 손실 때만 |
| quirk(시작일 근처 누락) | widening 으로 메움 — 단 매 창의 과거 끝마다 quirk 가 새로 생기고 다음 창이 메워야 함(마지막 창의 과거 끝은 DB 값에 의존) | 창 시작을 DB 최신일보다 **충분히 과거**에 두면 quirk 가 이미 DB 에 있는 날짜에서만 생겨 무해 |
| 과거값 수정(mod_yn) | 300일 전체를 매일 재반영 — 지수 종가 수정은 사실상 확정 직후 며칠 안에서만 생겨 과잉 | 겹침 폭 안(최근 10영업일)만 재반영 — 실제 수정이 생기는 구간을 덮음 |
| 오염 반경 | **300일 전체**(위험 시나리오 1) | **겹침 폭 + 새 봉**(약 2주)로 한정 |
| 미국 휴장·주말 | 영향 없음(넓게 받으니) | 영향 없음 — 창이 최신일 기준이라 휴장일은 그냥 행이 없을 뿐 |
| 결측 복구(10-12~15) | 자동 | 창을 「DB 최신일 − 겹침」부터 잡으면 **자동**(권고안) |
| 「모름 vs 새 봉 없음」 구분 | 어렵다(넓은 창은 늘 무언가 돌려줌 — 새 봉 유무는 최대일 비교로만) | **쉽다**(아래 §5 — 창에 이미 아는 날짜가 반드시 들어 있으므로 빈 응답 = 실패) |
| fail-closed | 적재 실패 시 판단은 그대로(현 구조 동일) | 동일 |

## 정량 권고 — 권고안 = (2) 슬라이딩, 단 창 시작을 「오늘 − N」 이 아니라 **「DB 최신일 − 겹침」** 에 고정

### 동작

1. **빠른 반환(현행 유지)**: `latest >= today − 1일 ∧ len(existing) >= target_days` → KIS 0회.
2. **분기**:
   - `len(existing) < MIN_HISTORY_DAYS(250)` 또는 DB 비었음 → **backfill 모드**: 지금의 widening 루프 그대로, 단 종료 조건을 「**이번 실행에 받은 날짜 + DB 날짜의 합** ≥ target(300)」으로(사실상 현행 — 이 모드에서는 결함이 안 난다).
   - 그 밖(이력 충분, 최신일만 낡음) → **증분 모드**: `anchor = latest − 14 달력일`, 첫 창 = `[anchor, today]`.
3. **증분 모드 종료 조건**: 받은 배치의 **가장 오래된 날짜 ≤ DB latest** 이면 끝(새 구간과 DB 가 겹쳐 이어졌다는 뜻). 아니면(낡은 기간이 길어 100 캡에 잘렸거나 quirk 가 겹침보다 컸음) 현행처럼 `cursor_end = 이번 배치 최저 날짜` 로 당겨 다시 받는다. 상한 `_MAX_FETCH_ATTEMPTS=6` 유지.
4. **병합**: `merge_batches([*fetched, existing])` 현행 그대로(새 배치 우선). 증분 모드에서 새 배치는 겹침 폭 안 날짜만 담으므로 오염 반경이 자동으로 약 2주로 묶인다.

### 수치와 근거

| 항목 | 값 | 근거 |
|---|---|---|
| 겹침 폭 | **14 달력일**(≈ 미국 10영업일) | quirk 모사 5일의 2배 여유 + 연휴 낀 주 대비. 지수 종가 사후 수정은 확정 직후 1~3일 안에서 생긴다 |
| 증분 첫 창 | `[latest − 14일, today]` | 평소(하루 낡음) 약 11행, 주말 뒤 약 12행, 이번 사고(7일 낡음) 약 15행 — 100 캡과 거리가 멀다 |
| 한 번에 못 메우는 낡음 | 약 **130 달력일 이상** | 이때만 100 캡에 걸려 2회차 이상. 6회 상한이면 수백 일 낡아도 회복 |
| backfill 진입 기준 | `len(existing) < 250`(= `MIN_HISTORY_DAYS`) | 판단이 실제로 서려면 필요한 수. 250~299 는 판단은 서므로 증분만 돌리고 이력은 날마다 자라게 둔다 |
| backfill 목표 | 300(현행 `MIN_HISTORY_DAYS + 50`) | 자문 10-06 §3 「최소 250, 권고 300」 그대로 |

> 「오늘 − N」 고정창이 아니라 「최신일 − 겹침」에 앵커하는 이유: 고정창(예: 최근 30일)은 적재가 30일 넘게 멈추면 그 사이 구멍을 **영원히** 못 메운다(같은 종류의 조용한 결함 재발). 최신일 앵커는 낡은 기간이 얼마든 구멍을 남기지 않는다.

## 3. 10-12~10-15 결측은 자동으로 메워지는가

**예.** 권고안을 배포한 다음 첫 `sync_daily_decision` 에서 `latest=10-09` → 창 `[09-25, today]` 1회 호출 → 10-12·13·14·15(+그 뒤 영업일) 수신, 배치 최저일(09-25 근처, quirk 로 며칠 잘려도 ≤ 10-09) ≤ latest 이므로 1회로 종료. 수동 적재·DB 조작 불필요.

단, **기존 397행 안의 숨은 구멍**은 이 수정이 메우지 않는다(증분 창 밖). 위험 시나리오 2 때문에 1회 대조를 권고한다(후속 검증 — tester).

## 4. 테스트 시나리오(tdd-engineer 용)

가짜 `fetch_daily_chartprice` 는 기존 `_fake_fetch` 꼴(창 안 원자료 → 100 캡 → 시작 근처 5일 누락)을 재사용한다.

1. **본 결함 회귀**: DB 397행·latest=10-09, today=10-16, 원자료는 10-15 까지 → KIS **1회**, upsert 에 `20261012~20261015` 4일 포함, 결과 `latest_date="20261015"`. (현 코드에서는 KIS 0회로 Red.)
2. **오래 낡음 + 100 캡**: DB 300행·latest 가 today − 200일 → 2회 이상 호출로 구멍 0(받은 연속 구간과 DB 사이에 빠진 영업일 없음), 호출 수 ≤ 6.
3. **오염 반경**: 증분 모드에서 가짜 KIS 가 겹침 밖(예: latest − 60일) 날짜에 다른 값을 실어 보내도 upsert 에 그 날짜가 **없다** — 즉 첫 창이 `latest − 14일` 이전을 요청하지 않는다(요청 `start` 단언). 겹침 안 날짜의 바뀐 값(mod_yn)은 반영된다.
4. **미국 휴장(새 봉 없음)**: 원자료 최신일 = DB latest(예: 추수감사절 다음 날) → KIS 1회, 정상 응답, 행 추가 0, 결과가 「no_new_bar」 로 구분(§5), 예외·ERROR 없음.
5. **KIS 실패(모름)**: 빈 응답(`OverseasIndexEmptyResponseError`)·예외 → upsert 로 기존값을 덮지 않음, 결과가 「fetch_failed」, 다음 날 같은 앵커로 재시도해 구멍 없이 회복(2일 시뮬레이션).
6. (backfill 보존) 빈 DB → 기존 `test_empty_db_widening_fetch_reaches_target_within_attempt_budget` 가 그대로 초록.

## 5. 「모름(KIS 실패)」 vs 「새 봉 없음(미국 휴장)」 구분

증분 창은 항상 이미 아는 날짜(겹침 폭)를 포함하므로 **정상 응답은 결코 비지 않는다**. 이것이 판별 열쇠다.

| 결과 | 판정 | 등급 |
|---|---|---|
| 응답 수신, 최대일 > DB latest | `new_bar` | INFO |
| 응답 수신, 최대일 == DB latest | `no_new_bar` — 미국 휴장 또는 KIS 미반영 | INFO. 단 **평일 기준 2일 연속**이면 WARNING(미국 연속 휴장은 극히 드물다 — 2012 샌디 2일, 2001 9·11 4일 정도) |
| 빈 응답·예외·파싱 실패 | `fetch_failed` — 모름 | **ERROR**(매번) |

- 구현은 `ensure_history` 안에서 한 줄 마커(예: `[ndx2x_ingest_outcome] outcome=… latest=… fetched_max=…`)로 남기고 `IngestResult` 에 같은 값을 실으면 된다 — `ndx2x_ingest.py` 범위 안에서 끝난다.
- 기존 `[ndx2x_data_stale]`(평일 근사 gap ≥ 3, 전략 파일) 은 그대로 둔다. 위 표가 그 앞단에서 원인(실패 vs 휴장)을 알려 주므로 stale 경고를 볼 때 「왜」를 바로 가를 수 있다.

## 현 코드와의 정합성

- 충돌 항목: **`src/engine/ndx2x_ingest.py:68·72`** — `collected_dates` 를 DB 날짜로 시작하고 그 수로 루프를 거는 것이 결함 원인. 권고안은 증분/백필 분기와 종료 조건만 바꾼다. `ndx2x_core.merge_batches`·`parse_kis_rows`·`decide_daily` 무변경.
- **알려 둘 별도 사실(이번 수정 범위 아님)**: `strategies/ndx2x_riskoff.py::sync_daily_decision` 은 적재가 실패해도 낡은 종가로 `reason="ok"` 판단을 낸다 — 「낡음」은 fail-closed 가 아니라 경고만이다. 섀도라 지금은 무해하고 규칙 C 가 느린 신호라 며칠 낡음의 오차도 작지만, R4 가 −20% 경계 근처일 때는 칸이 하루 늦게 뒤집힌다. 실전 전환 전 결정 항목으로만 남긴다(선택지: 유지 / 최신일이 미국 N영업일 넘게 낡으면 `desired_state=None`). 이 메모는 **유지**를 기본으로 둔다(범위 확장 금지).
- 선택지 정리:
  - **권고(슬라이딩·최신일 앵커)** — 호출 1회/일, 오염 반경 2주, 구멍 자동 회복, 실패/휴장 구분 쉬움.
  - (1) 넓은 창 — 구현은 한 줄(종료 조건을 이번 실행 수신 수로)이라 가장 빠르지만, 매일 300일을 덮어써 R4 가짜 고점 위험을 상시로 진다. 권하지 않는다.
  - 고정 「오늘 − 30일」 슬라이딩 — 30일 넘게 멈추면 같은 종류의 영구 구멍이 생긴다. 권하지 않는다.

## 반례 / 한계

- 반례 1: KIS 가 그날 아침 미국 전일 봉을 늦게 올리면(호출 시점 미반영) 그날은 `no_new_bar` 로 지나가고 다음 날 메워진다 — 하루 1회 구조(`_decision_date`)의 한계이고, 신호가 하루 늦는다. 규칙 C 속도에서는 수용 가능.
- 반례 2: 겹침 폭 밖의 과거 종가가 실제로 수정돼도 반영되지 않는다. 지수 종가에서는 드물다. 필요 시 이력 손실 때의 backfill 이 새로 받아 덮는다.
- 반례 3: quirk 가 「시작 근처 5일」이 아니라 더 크게(14일 초과) 나는 날이 있으면 증분 1회로 겹침에 못 닿는다 → 종료 조건(배치 최저일 ≤ latest)이 2회차를 불러 회복한다. 6회 상한 소진 시 `[ndx2x_ingest_short]` 류 WARNING.
- 한계: quirk 의 실제 크기는 운영 실측이 아니라 테스트 모사(5일)에 기댄다. 소창(약 15행)에서 quirk 가 나는지 자체도 미확인 — 앵커 설계는 나든 안 나든 무해하다.
