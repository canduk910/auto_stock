## 트레이더 시각

### 시장 가설 — 이 가드는 "이미 뛴 종목 추격 금지" 로 개념 타당

extension 가드의 트레이더 어법: **"돌파는 맞는데, 이미 너무 뛰어버린 종목을 시가에 뒤늦게 쫓아 사면, 산 순간이 그날의 고점이 될 확률이 높다."** 돌파 스윙에서 진입 지점의 손익비는 *돌파선(기준가)으로부터의 거리* 에 반비례한다. 기준가 바로 위에서 사면 손절선(기준가 재이탈)까지 짧고 상방 여유가 크지만, 기준가에서 6~7% 위에서 사면 손절폭이 6~7% 로 벌어지면서 되돌림(mean-reversion)에 그대로 노출된다. 그래서 이 가드의 개념은 옳고, **제거는 답이 아니다.** (제거 시 급등 당일 뒷북 추격이 무방비.)

### 그러나 — donchian 후보의 구조적 특성상 0.5% 는 "상시 스킵" 을 강제한다 (정량 확정)

코드를 정독한 결과, 이 가드가 donchian 에서 상시 발화하는 것은 우연이 아니라 **정의상 필연**이다.

- `donchian_high = prior_high = max(highs[1 : donchian_period+1])` (L294/L372) — **어제(index 0)를 제외한** 직전 20일 최고가.
- 후보 자격 = `prev_close > prior_high` (L295) — **어제 종가가 이미 그 기준선을 돌파**했을 때만 후보로 등록.

즉 후보로 등록되는 순간 이미 `어제 종가 > donchian_high` 가 참이다. 그런데 extension 가드는 `daily_high = max(당일고가, current, open)` 을 **같은 donchian_high** 와 비교한다. 오늘 시가/현재가는 대개 어제 종가 근처 이상에서 출발하므로:

```
ext_pct = (오늘 daily_high − donchian_high) / donchian_high × 100
        ≥ (어제 종가 − donchian_high) / donchian_high × 100   ← 후보 자격상 이미 양수
```

**후보의 최소 ext_pct 하한 = "어제 종가가 기준선을 얼마나 넘겨 마감했는가".** 어제 돌파가 강하게(예: 어제 종가가 기준선 대비 +2~3%) 마감한 종목일수록 오늘 ext_pct 는 그만큼 이상에서 시작한다. 여기에 오늘 장중 상승분이 더해진다. 따라서 **0.5% 임계는 "어제 기준선을 0.5% 이내로 아슬아슬하게 돌파하고 오늘도 거의 안 오른" 극소수만 통과** → 사실상 donchian 매수 0. 박스 필터(208)를 걷어냈어도 이 게이트가 2차 병목으로 남은 것이 실측(S-Oil) 그대로다.

### 실전 사례 — S-Oil(010950) 은 "정상 스킵" 이 맞다

- donchian_high 134,800 / 오늘 고가 143,500 = **+6.45%**.
- 어떤 합리적 임계(3~5%)로도 6.45% 는 스킵되는 게 맞다. **오늘 S-Oil 못 산 것 자체는 결함이 아니다** — 6.45% 뒤늦은 추격은 손익비가 깨진 진입이고, 시가에 사면 되돌림 리스크가 크다. 트레이더로서 나도 안 산다.
- 문제는 **"S-Oil 을 걸러낸 것" 이 아니라 "0.5% 라는 값이 6.45% 짜리뿐 아니라 정상적인 1~3% 돌파 종목까지 전부 상시 차단" 한다는 것.** 두 사안을 반드시 구분해야 한다. 값 복원의 목표는 "S-Oil 을 사게 만드는 것" 이 아니라 "**정상 돌파 종목이 통과할 창을 여는 것**".

### 위험 시나리오 (가드가 깨지는/과하게 여는 경우)

- **임계를 너무 크게(예: 8~10%) 열면**: 급등 당일 고점 추격이 통과 → 시가 진입 후 당일 되돌림 손실. donchian 은 멀티데이 보유라 오버나이트까지 물릴 수 있음. → 상한을 5% 이내로 눌러야 함.
- **임계를 너무 작게(0.5~1%) 조이면**: 위 구조상 정상 후보 전멸 → 매수 0 (현 상태). → 하한을 3% 이상으로.
- **gap 가드와의 모순**: gap_skip_threshold=3% 는 시가 갭이 +3% 이상이면 스킵. 그런데 extension=0.5% 면, 갭 2.9%(gap 통과)로 열린 종목도 daily_high 가 기준선 대비 0.5% 초과하는 순간(사실상 즉시) extension 에서 스킵 → **gap 가드가 "3% 까지 허용" 해놓고 extension 가드가 "0.5% 에서 차단" = 두 게이트가 서로 논리적으로 모순.** 정합을 맞추려면 extension ≥ gap 이어야 개념이 일관된다(갭으로 열린 만큼은 최소한 extension 이 수용해야 함).

## 정량 권고

### (a) 적정값 — `max_breakout_extension_pct = 4.0` 권고 (default 3.0 복원이 아니라 3.0→4.0 소폭 상향)

| 후보 | 값 | 트레이더 판단 |
|---|---|---|
| 0.5 (현 운영 DB) | ✗ | AI 과적합 하한 바닥. 구조상 상시 스킵 = 매수 0. **즉시 폐기** |
| 3.0 (코드 default) | △ | 개념상 무난하나, gap 3% 와 겨우 동률 → 갭 2.9%+장중 소폭 상승 종목이 3% 살짝 넘겨 스킵되는 경계 마찰 잔존 |
| **4.0 (권고)** | ✓ | gap 3% 대비 +1%p 여유 = "갭으로 열린 3% + 장중 소폭(≤1%) 추격" 까지 수용. 6%+ 뒷북 추격(S-Oil)은 여전히 차단. **손익비 하한(진입~손절 4% ≈ ATR×2 트레일링 폭과 정합)** |
| 5.0 | △ | 허용 상한. 4.0 이 안 통하면(1개월 후보 빈도 실측 후) 5.0 까지 완화 여지. 그 이상은 추격 위험 |

**4.0 근거:**
1. **gap 정합**: gap_skip 3% 를 통과한 갭 종목이 장중 1% 를 더 붙여도 extension 4% 안에서 수용 → 두 게이트 모순 해소 (extension ≥ gap + 장중 소폭 여유).
2. **손익비**: donchian 청산 = ATR(14)×2 트레일링 + -7% 하드. 기준선 대비 4% 위에서 진입하면 기준선 재이탈(손절 트리거 지점)까지 ~4% = ATR×2 트레일링의 통상 폭(대형주 3~5%)과 겹침 → 진입 후 즉시 손절 위험이 관리 가능한 최대치. 5% 넘어가면 손절폭이 하드 -7% 에 근접해 손익비 열화.
3. **한국 대형주 돌파 통계(실전 감각)**: KOSPI 대형주가 20일 신고가를 돌파하는 날, 어제 종가는 기준선 대비 통상 +1~3% 마감 → 오늘 시가가 그 근처면 ext 1~3%. 4% 창이면 "어제 강하게 마감(+2~3%) + 오늘 갭 소폭" 조합까지 포용. 3% 면 이 조합이 경계에서 잘림.

> **중요**: default 3.0 을 "복원" 하는 게 아니라, **구조적 병목을 인지한 상태에서 3.0→4.0 으로 소폭 상향** 하는 것이 이번 사이클의 실질이다. 사용자가 "default 복원(3.0)" 로 보수적으로 가길 원하면 3.0 도 수용 가능(0.5 대비 압도적 개선) — 단 gap 3% 와 동률인 경계 마찰이 남는다는 점을 명시.

### (b) gap_skip_threshold 정합 — **3.0 유지** (변경 불요), 단 extension ≥ gap 불변식 명문화

- gap_skip_threshold=3.0 자체는 적정(시가 +3% 이상 갭은 뒷북 진입 위험 → 스킵). **변경 권고 없음.**
- 정합 규칙: **`max_breakout_extension_pct ≥ gap_skip_threshold` 를 불변식으로 둔다.** extension < gap 이면 "갭 3% 까지 허용" 이 "extension 에서 즉시 차단" 되는 모순 재발. 4.0 ≥ 3.0 로 이 불변식 충족. 이 관계를 `00_leader_trading_rules.md` 와 회귀 테스트(불변식 가드)에 박아두면, 향후 어느 한쪽만 만지는 실수를 구조적으로 차단.

### (c) PARAM_RANGES 처리 — `max_breakout_extension_pct` **AI 자동튜닝에서 제외** (사이클 208/198 선례 계승)

**제외 권고 (강).** 근거:
1. **이번 결함의 근본 원인이 정확히 AI 자동튜닝.** `(0.5, 10.0)` 범위에 열어둔 탓에 20:00 자문이 소표본 승률에 과적합해 하한 0.5 로 조였고, 표본을 0으로 소멸시켰다. 사이클 208(box 2키 제외)·198(flag_lookback_min 제외)에서 이미 확립한 원칙: **"진입 기준/시간창은 전략 정체성 상수 — 손익 최적화 대상이 아니다."** extension 가드는 손익 파라미터가 아니라 "추격 금지선" = 전략의 진입 철학 그 자체.
2. gap_skip_threshold 는 이미 PARAM_RANGES 밖(자동튜닝 제외). extension 만 안에 있는 것은 **비대칭** — 두 게이트가 정합해야 하는데 한쪽만 AI 가 흔들 수 있는 구조는 위험. 둘 다 상수로 고정하는 게 일관.
3. **INT_PARAMS 무관** (extension 은 float, INT_PARAMS 미등록 — 확인 완료).

**조치**: `recommendation_engine.py` PARAM_RANGES L105 `"max_breakout_extension_pct": (0.5, 10.0)` 엔트리 삭제 (사이클 208 box 2키 삭제 diff 와 동형). `breakout_fail_n_days`/`breakout_retention_minutes` 등 나머지 P2 키는 손익성 청산/시간 파라미터라 자동튜닝 유지 여부는 별건(이번 범위 아님, 유지).

> **운영 DB 값 지혈 동반 필수**: 코드 default 를 4.0(또는 3.0)으로 바꿔도, 운영 DB `strategy_config.donchian_swing.params.max_breakout_extension_pct` 에 0.5 가 이미 apply 되어 있으면 코드 배포만으로 즉시 반영 안 됨(`__init__` 은 `{**DEFAULT_PARAMS, **config.params}` 로 DB 값 우선). → **운영 DB UPDATE 로 0.5 → 4.0 직접 지혈**(사이클 201 weight 지혈 선례) 을 배포와 동반. 이후 PARAM_RANGES 제외로 재발 차단.

### (d) 근본 재설계 필요 여부 — **이번 사이클 범위 아님, 별도 인계로 표기** (아래 명시)

donchian 진입 구조에 더 깊은 이슈가 있는 것은 **사실**이나, 이번 사이클은 "매수 재개" 에 집중하고 근본 재설계는 분리해야 한다. 발견된 구조적 이슈 2건을 인계로 명시한다.

## 반례 / 한계

- **4.0 도 "정상 돌파" 를 100% 통과시키지는 않는다.** 어제 종가가 기준선 대비 +4% 이상 강하게 마감한 초강세 돌파 종목은 오늘 시가만으로도 ext>4% → 스킵될 수 있다. 이는 "어제 이미 강하게 뛴 종목을 오늘 시가에 또 사는 것" 이므로 **스킵이 트레이더 관점에서 오히려 옳다.** 즉 4.0 은 "정상 얕은 돌파는 통과, 강한 돌파의 뒷북 추격은 차단" 의 균형점 — 완벽한 통과율이 목표가 아님.
- **1개월 후보 빈도 실측 필요.** 4.0 이 실제로 몇 종목/일을 통과시키는지는 배포 후 funnel step9 실측으로 확인해야 한다. 만약 여전히 0~1 종목/일로 희소하면, (i) 5.0 완화 또는 (ii) **아래 인계의 근본 재설계(당일 돌파 순간 진입)** 로 전환. 값 조정은 임시 처방이고, 진짜 해법은 후보 재정의일 수 있다.
- **donchian_high 정의 자체의 재검토 여지**: 현재 gate 가 "어제 제외 20일 신고가" 와 오늘 고가를 비교하는데, 후보 자격도 같은 기준을 쓰므로 게이트가 자기 참조적으로 상시 발화. 인계 항목 2 참조.

## 근본 재설계 인계 (별도 사이클, 이번 범위 밖)

### 인계 1 — donchian 진입 구조 = "창 안 아무 틱 즉시 매수" 의 적절성

현 구조는 `check_buy_signal` 이 09:05~09:30 창 안에서 **돌파 순간 cross 체크 없이** (후보가 어제 이미 돌파했으므로) 갭·extension 가드만 통과하면 즉시 BUY. 이는 CLAUDE.md "절대 규칙: 매수는 돌파 순간 감지(이전 틱<기준가 AND 현재 틱≥기준가)" 와 **철학이 다른 예외**다(donchian 은 "전일 종가 돌파 확인형" 이라 의도된 설계이긴 함). 그러나:
- "창 안 아무 틱 즉시 매수" 는 진입 타이밍 통제가 약함 — 09:05 첫 틱이 그날 고점이어도 산다.
- 대안: **"당일 신고가(또는 어제 종가) 돌파 순간 진입"** 으로 재정의하면, extension 가드의 상시 발화 문제가 자연 해소되고(진입점이 기준선에 밀착) 진입 타이밍도 개선. 단 이는 후보 정의·진입 로직 전면 수정 = HIGH 위험 = domain-expert + tdd-engineer 별도 사이클 필수.

### 인계 2 — donchian_high 기준선 정의 (어제 포함 vs 제외)

extension 가드가 자기 참조적으로 상시 발화하는 뿌리는 "후보 자격 기준선(어제 제외 20일 신고가) == extension 가드 기준선" 인 점. 만약 gate 기준선을 "당일 시가" 또는 "어제 종가" 로 바꾸면 extension 의 의미가 "오늘 얼마나 뛰었나" 로 명확해지고 gap 가드와 역할이 깔끔히 분리됨. 이 역시 별도 사이클 검토 대상.

## 후속 검증 권고 (tdd-engineer / tester)

1. **값 정합 회귀**: `max_breakout_extension_pct` default == 4.0 (또는 사용자 확정값) 단언.
2. **불변식 가드 (신규)**: `max_breakout_extension_pct >= gap_skip_threshold` 를 코드/테스트 불변식으로 박기 (b 항 정합 규칙 영구화).
3. **PARAM_RANGES 제외 AST 가드**: `recommendation_engine.PARAM_RANGES` 에 `max_breakout_extension_pct` 키 **부재** 단언 (사이클 208 box 2키 제외 가드 패턴 답습). INT_PARAMS 무관 확인.
4. **구조 재현 테스트**: 합성 후보(prev_close 가 prior_high 대비 +2% 마감) + 오늘 시가 소폭(+1%) → ext≈3% → 4.0 통과 / S-Oil 유형(ext 6.45%) → 4.0 스킵. "정상 돌파 통과 + 뒷북 추격 차단" 이분법 직접 검증.
5. **운영 DB 지혈 확인**: 배포 후 `strategy_config.donchian_swing.params.max_breakout_extension_pct` 실측값이 4.0 인지 (0.5 잔존 시 코드 무효).
6. **D+1 funnel 실측**: 배포 후 익일 donchian step9(최종 후보) 통과 종목 수 — 0 탈출 확인 + 1주 빈도 관찰 → 여전히 희소 시 인계 1(근본 재설계) 승격.
