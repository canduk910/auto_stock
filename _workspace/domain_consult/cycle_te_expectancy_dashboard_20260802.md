## 질문 요약

트레이딩 서적의 두 개념을 각 전략 카드에 **최근 3개월** 지표로 통합 표시:
- **TE** = `승률 × 평균수익 − 패율 × 평균손실` (= 수학적으로 **전체 청산 거래의 평균 실현 손익**)
- **RR비율** = `평균수익 ÷ 평균손실` (= payoff ratio / **손익비**, 클수록 좋음) + **필요RR비율** = `(1−승률)÷승률` (손익분기 손익비)

TE 7질문(단위/계산기준/분해/표본임계/미실현/기간/안전성) + RR 5질문(Q8 표시/Q9 TE·RR 동치/Q10 진단/Q11 게이지/Q12 표본민감도) 를 통합해, **각 카드에 승률·평균수익·평균손실·거래수·RR비율·필요RR비율·TE·우위판정을 정직하게 배치하는 단일 권고**로 산출.

**★ 핵심 사전 정리 — RR은 새 개념이 아니라 Q3에서 이미 권고한 "손익비"다 ★**
서적의 RR비율(평균수익÷평균손실) = 제가 초안 Q3에서 이미 "반드시 포함"으로 권고한 **손익비(payoff ratio)** 와 동일. 서적의 필요RR비율 `(1−승률)/승률` = 초안에서 언급한 **손익분기 승률 `1/(1+손익비)`** 의 대수적 쌍대. 둘은 같은 부등식을 변수만 바꿔 푼 것:

> TE>0 ⟺ 승률×평균수익 > 패율×평균손실 ⟺ **RR > (1−승률)/승률** (RR로 품) ⟺ **승률 > 1/(1+RR)** (승률로 품)

즉 이번 RR 통합은 초안 설계를 **뒤엎지 않고 강화**한다. 서적이 준 진짜 선물은 `필요RR비율` 이라는 **손익분기 기준선** — TE의 부호(양/음)를 "얼마나 여유있게" 넘겼는지 안전마진으로 시각화할 앵커다.

## 트레이더 시각 (먼저 읽을 것)

### 시장 가설 — TE 는 "숫자 하나"가 아니라 "엣지의 해부도"다

TE 는 산술적으로 그냥 거래당 평균 손익이다. 하지만 서적이 `승률 × 평균수익 − 패율 × 평균손실` 로 **분해**해서 쓰는 이유는, 같은 TE 라도 **엣지의 원천과 취약성이 완전히 다르기** 때문이다.

- **고승률-저손익비형** (예: 승률 80%, 평균수익 +2%, 평균손실 −6%): TE = 0.8×2 − 0.2×6 = **+0.4%**. 겉보기 양수지만 손실 한 번이 이익 세 번을 먹는다. 연속 손절 3방이면 계좌가 휘청. **깨지기 쉬운(fragile) 엣지.**
- **저승률-고손익비형** (예: 승률 35%, 평균수익 +8%, 평균손실 −2%): TE = 0.35×8 − 0.65×2 = **+1.5%**. 돌파 전략(VB/donchian/BFB/VCP/kojiro)의 전형. 대부분 잘리고 가끔 크게 먹는다. **견고한(robust) 엣지.**

두 전략의 TE 를 숫자 하나로만 보여주면, 운영자는 +0.4%짜리 fragile 전략에 비중을 더 실을 수도 있다. **TE 는 반드시 승률·손익비(RR)와 함께 보여야 정직하다.**

**터틀 통찰 (RR의 무게중심)**: 서적의 핵심 메시지 — 승률이 35~40%로 낮아도 RR비율 3을 유지하면 압도적 승자. 반대로 승률 60%여도 RR 0.33이면 필요RR(0.67) 미달로 압도적 패자. 우리 돌파 전략군(VB/donchian/BFB/VCP/kojiro)이 바로 저승률·고RR 구조를 노리는 설계다. **무게중심은 승률이 아니라 RR** — 이 시스템의 손절(진입 가설 깨진 가격에서 빠르게 자르기)과 트레일링(추세 끝까지 태우기)이 정확히 RR을 키우는 장치다. 카드는 이 구조를 운영자가 한눈에 읽게 만들어야 한다: "이 전략은 자주 지지만 이길 때 크게 이기는가, 아니면 자주 이기지만 한 방에 무너지는가?"

### 실전 사례 / 코드 실측

우리 코드에는 이미 **두 가지 서로 다른 % 계산**이 살아있고, 이게 이번 설계의 핵심 갈림길이다.

1. `recommendation_metrics.compute_metrics()` (recommendation_metrics.py:131) — `pct = pnl / (매도가 × 수량) × 100` (**매도가 기준**).
2. `trade_history.get_trade_pairs()` (trade_history.py:625) — `rate = (매도평균가 − 매수평균가) / 매수평균가 × 100` (**진입가 기준, 표준 수익률**).

매도가 기준은 TE 에 **구조적 하방 편향**을 만든다. 실측 계산으로 증명:
- 매수 10,000 → 매도 11,000 (수익): 진입가 기준 **+10.0%** vs 매도가 기준 1,000/11,000 = **+9.09%** → *승리를 축소*
- 매수 10,000 → 매도 9,000 (손실): 진입가 기준 **−10.0%** vs 매도가 기준 −1,000/9,000 = **−11.1%** → *손실을 과장*

즉 매도가 기준은 승률·손익비 모두를 나쁜 쪽으로 왜곡 → TE 를 실제보다 비관적으로 만든다. **손익분기 근처의 전략은 부호가 뒤집힐 수도 있다.** 반면 `get_trade_pairs` 는 표준 수익률 + Decimal 정밀 + 가중평균 페어링 + 미실현(open) 분리까지 이미 되어 있다.

### 위험 시나리오 — 표본이 진짜 함정

3개월 실측 표본은 전략별로 극단적으로 비대칭이다. 메모리 기준 kojiro 는 **청산 N=1**, team-lead 보고 기준 donchian 4건 · BFB 0건. **N=1 의 TE 는 그 한 거래의 손익 그 자체** — 기댓값 추정치로서 무의미하다. 그런데 카드에 큼직하게 "+12%" 같은 숫자가 뜨면 운영자는 그걸 엣지로 착각해 비중을 올린다. 이게 이번 작업에서 **가장 큰 오용 위험**이다.

### Q1. TE 단위 — %인가 ₩인가

| 안 | 내용 | 트레이더 평가 |
|----|------|--------------|
| (a) % | 거래당 평균 수익률 | 전략의 **엣지**를 정직하게 드러냄. 포지션 크기·자본 규모에 불변 → 전략 간·시점 간 비교 가능 |
| (b) ₩ | 거래당 평균 실현손익 (서적 방식) | **계좌에 실제로 무슨 일이 있었나**를 보여줌. 심리적 앵커 강함. 그러나 `position_ratio × 전략비중 × 순자산` 으로 결정되는 포지션 크기에 지배됨 |
| (c) 둘 다 | | |

**판정: (c) 둘 다 — 단, %를 헤드라인 TE 로, ₩은 보조.**

근거: 우리 시스템은 (1) 소액 계좌, (2) 전략별 배정 자금이 `cash_usage_ratio`·비중 조정·순자산 변동으로 시간에 따라 변함, (3) 전략마다 배정액이 다름. 따라서 **₩ TE 는 엣지가 아니라 "그때 얼마를 걸었나(sizing)"에 지배**된다. 3개월 전 ₩10M 배정 시절의 ₩ TE 와 지금 ₩30M 배정의 ₩ TE 는 비교 불가. 전략 간 ₩ TE 비교는 엣지와 자본배분을 뒤섞는다. **%가 유일하게 정직한 헤드라인.** ₩은 "3개월 실현손익 합계" 또는 "거래당 평균 실현손익(₩)"으로 보조 표기.

- 헤드라인: **TE = +1.5%** (거래당 평균 수익률)
- 보조: 3개월 실현손익 합계 ₩ + 거래당 평균 ₩

### Q2. % 계산 기준 — ★핵심 결정, 기존 코드와 충돌★

| 안 | 내용 | 평가 |
|----|------|------|
| 매도가 기준 | `pnl / (매도가×수량)` (기존 compute_metrics) | **TE 부적합** — 승리 축소·손실 과장 편향 (위 실측 참조) |
| 진입가 기준 | `(매도−매수)/매수` (기존 get_trade_pairs) | **표준 수익률.** 트레이더가 말하는 "수익률". TE 정의에 부합 |
| R-multiple | `손익 / 진입시 리스크(진입가−손절가)` | Van Tharp expectancy 의 정본. **이론적 최선** |

**판정: 진입가 기준 (get_trade_pairs 재사용). 매도가 기준(compute_metrics) 금지.**

R-multiple 은 트레이딩 문헌에서 expectancy 의 정본이지만, 우리 손절선은 동적(트레일링/ATR/보드별/익일청산)이라 **"진입 시점의 계획된 리스크"가 trade_history 에 저장돼 있지 않다.** 현재 데이터로 R 계산 불가 → Phase 2 로 인계 (진입 시점 손절가 캡처 필요).

**★ 현 코드와 충돌 (team-lead Q2 프레이밍 "기존 compute_metrics 재사용"과 배치)★**: compute_metrics 는 두 가지 이유로 TE 소스로 부적합.
1. **매도가 기준 편향** (위 실측).
2. **PARTIAL SELL 이중 카운트**: compute_metrics 는 status ∈ (COMPLETED, PARTIAL) 인 *매도 row 각각*을 별개 거래로 셈 (recommendation_metrics.py:112) → 한 포지션을 3번 분할매도하면 "3거래"로 잡혀 N·승률 왜곡.

→ **"기존 인프라 재사용"의 정답은 compute_metrics 가 아니라 get_trade_pairs 다.** get_trade_pairs 는 (ticker, strategy) 그룹 내 누적 보유수량 0 사이클마다 **왕복 1건**으로 접어 진입가 기준 수익률을 이미 정확히 계산한다. 재사용 대상만 바꾸면 됨.

### Q3. 분해 표시 — TE 단일값 vs 서적식 분해

**판정: 전체 분해 + 손익비 동반. TE 단일값 금지.**

표시 항목:
- **TE** (헤드라인, %)
- **승률** (승/전체)
- **평균수익 / 평균손실**
- **손익비** = 평균수익 / |평균손실| ← *반드시 포함*
- **거래수 N** (승 W / 패 L / 보합 분리)

손익비(payoff ratio)가 엣지 스토리의 나머지 절반이다. 승률 + 손익비만 있으면 나머지를 재구성하고 **취약성(fragile/robust)을 판단**할 수 있다. 선택적으로 **손익분기 승률** = `1/(1+손익비)` 을 함께 주면 "실제 승률 > 손익분기 승률 → 양의 엣지" 를 한눈에 검증 가능 (카드가 복잡하면 툴팁으로).

**보합(±0 손익) 주의**: 이 시스템은 손절가=매수가 청산(코미코 사례: 138,200 매수→138,200 매도, pnl=0)이 실제로 발생한다. 그래서 **TE 는 "전체 청산 왕복 수익률의 단순 산술평균"으로 정의**해야 안전하다 (= net/N, 항상 성립). 분해값(승률=승/N 등)은 *설명용*이고, 헤드라인 TE 는 직접 평균이 진실의 원천. 승률 분모는 **보합 포함 전체 N** 으로 통일 (승/(승+패)로 하면 보합 존재 시 분해와 평균이 어긋남).

### Q4. 표본 부족 — ★가장 중요★

**판정: 3단계 임계. N<20 은 TE 숫자 자체를 뮤트하고 "표본 부족" 배지.**

| 표본 | 표시 |
|------|------|
| **N < 20** | TE 숫자 회색 뮤트 또는 미표시 + **"표본 부족 (N건)"** 배지. 대신 N·순손익 raw 만 노출 |
| **20 ≤ N < 50** | TE 정상 표시 + amber caption **"표본 적음 — 추세 참고용"** |
| **N ≥ 50** | TE 정상 표시 |

근거: TE 표준오차는 1/√N 로 줄어든다. N=4 면 신뢰구간이 +2%~−3% 를 넘나들어 **부호조차 못 가림**. fat-tail 손익분포에서는 30 도 빠듯 — 20 은 "방향조차 못 믿는 하한선"의 실무적 floor. 트레이딩 통상 규칙: N<20 일화 수준 / N≥30 중심경향 시작 / N≥100 안정.

추가 가드:
- **N 을 승 W / 패 L 로 분리 표시** (승률 분모 투명화).
- **단일 거래 의존 플래그**: 한 거래가 총이익의 >50% 면 "단일 거래 의존" 표기 (compute_metrics 의 max_profit_pct/max_loss_pct 재활용 가능). 절대 조용히 트리밍(winsorize)하지 말 것 — 그건 현실을 숨김. **드러내라.**

현실 인정: 3개월이면 momentum/VB 는 수십 건, 스윙계(donchian/BFB/VCP/kojiro)는 대부분 한 자릿수 → **대부분의 스윙 전략은 "표본 부족" 구간에 들어간다.** 이게 정직한 상태다. donchian(4)에 무서운 TE 를 큼직하게 띄우느니 "표본 부족"이 맞다.

### Q5. 미실현 / 부분체결 / open 포지션

**판정: 청산된 왕복만(realized-only). 미실현·open 제외. — get_trade_pairs 가 이미 해결.**

- get_trade_pairs 는 `status='closed'` 왕복(TE 모집단)과 `status='open'` 현 보유(미실현)를 이미 분리한다. **open 은 TE 에서 제외** (미실현은 아직 결과가 아니며, 포함하면 종이수익이 TE 를 부풀리고 매일 값이 흔들림).
- **부분체결**: get_trade_pairs 는 보유수량이 0 으로 돌아오는 시점에만 왕복 1건을 emit → 분할매도가 왕복을 조기 카운트하지 않음. **compute_metrics 의 PARTIAL row 별개 카운트 문제(Q2)를 구조적으로 회피** — get_trade_pairs 를 써야 할 또 하나의 이유.

주의(구현 인계): get_trade_pairs 는 현재 날짜 범위 인자가 없다(strategy/ticker 만). "최근 3개월"은 **전체 이력으로 페어링한 뒤 청산일(sell_date)이 윈도우 안인 왕복만 포함**해야 경계를 걸친 왕복이 잘리지 않음.

### Q6. 기간 · 해석 가이드

### Q8. RR비율 표시 — 실제RR vs 필요RR 병렬

**판정: 실제RR(평균수익÷평균손실) + 필요RR 병렬. 단, 필요RR = 패수/승수(L/W) 로 산출.**

- **실제RR** = 평균수익 / |평균손실| — 이미 Q3에서 권고한 손익비.
- **필요RR** = 손익분기 손익비. 서적은 `(1−승률)/승률`. **정확식은 `패수/승수 (L/W)`** 이고, 보합(pnl=0 청산) 이 없으면 `(1−승률)/승률` 과 동일. 우리 시스템은 손절=매수가 청산(코미코 사례)으로 보합이 실제 발생 → **L/W 채택**해야 정확 (서적 공식은 보합을 손실로 취급해 필요RR을 살짝 과대). 운영자에겐 툴팁으로 "(1−승률)/승률" 직관 제공.
- **우위/열위 판정**: 실제RR > 필요RR ⟺ TE>0 (동치). 운영자는 두 값 비교로 즉시 우위 판단.

**분모 0 처리 (평균손실=0, 무손실 표본)**: RR 분모 0 → 무한대. 이건 표본이 작고 운좋게 전승일 때만 발생(donchian 4전승, kojiro N=1승) → **Q4 표본부족 뮤트에 이미 포섭**. 그래도 명시 처리: RR 값을 "∞"/큰 숫자로 절대 표시 말 것. **"손실 표본 없음 (RR 산정 불가)"** + 표본부족 배지. TE는 자명히 양수지만 N이 작으니 판정 유보.

### Q9. TE ↔ RR 동치 — 중복인가 상보인가

**판정: 상보. 둘 다 표시. 중복 아님.**

수학적으로 연동(TE>0 ⟺ RR>필요RR)돼 있어도 정보가 다르다:
- **TE = 크기(magnitude)** — 거래당 얼마를 기대하나 (얼마나). %/₩ 숫자.
- **RR(+승률) = 구조(structure)** — 엣지가 어디서 오나, 얼마나 견고한가 (어떻게).

같은 TE=+1%라도 승률90%/RR0.2(취약) 와 승률35%/RR3(견고) 는 정반대 구조. **TE는 이 차이를 숨기고 RR이 드러낸다.** → TE는 헤드라인 크기, 승률·RR·필요RR은 그 아래 구조 진단.

**우위/열위 배지 앵커**: TE 부호로 배지(우위=TE>0) — 바텀라인이니까. 옆에 **RR vs 필요RR 안전마진**(여유 = 실제RR − 필요RR)을 붙여 "왜/얼마나 우위인가"를 보강. 손익분기 근처(TE≈0)는 소표본 노이즈로 배지가 뒤집히니 **배지도 표본부족 게이트 적용**(N<임계 → "판정 유보").

### Q10. 분해 진단 — 열위 시 개선 방향

**판정: 프리스크립션(처방) 대신 구조 태그(사실 라벨)만. N≥임계 시에만.**

열위(TE<0)일 때 원인이 "승률 낮음"인지 "RR 낮음"인지 구분은 가치 있음. 터틀식 = RR 키우기(익절 늦추고 손절 좁히기)가 정석. 그러나 **소표본 노이즈 위에 자동 처방을 얹으면 과잉지도** 위험. 그래서 카드에는 **구조 태그**만:
- 저승률·고RR → **"견고형"** (돌파 전략 정상 — 자주 지고 크게 이김)
- 고승률·저RR → **"취약형"** (한 방 위험 — 자주 이기고 크게 잃음)
- 중간 → **"균형형"**

구분선: 승률 50% / RR 1.0 기준 4분면(또는 필요RR 대비 실제RR). **"RR을 키워라" 같은 명령형은 카드에 넣지 말 것** — 그건 사람 판단. 터틀 통찰은 페이지 하단 교육용 캡션으로. 구조 태그도 N<임계면 미표시.

### Q11. 표 1-2 게이지 — 승률→필요RR 시각화

**판정: 카드당 컴팩트 게이지 1개(실제RR bar + 필요RR 마커) 채택. 전체 표 1-2 카드 복제는 과함.**

게이지 설계: 가로 bar에 **필요RR을 임계 마커(세로선)**로, **실제RR을 채움**으로. 채움 ≥ 마커 → 우위(빨강=이익색), 채움 < 마커 → 열위(파랑=손실색). 이게 서적 핵심(RR>필요RR)과 안전마진을 가장 정보밀도 높게 시각화. **6전략 카드 그리드에 표 1-2 전체(9행 승률→필요RR 매핑)를 매 카드 복제하는 건 과함** → 페이지 하단 1회 참조표 또는 게이지 툴팁으로. 게이지도 표본부족 시 뮤트.

### Q12. 소액계좌·표본부족과 RR — RR은 TE보다 outlier에 더 민감

**판정: RR에 TE보다 엄격한 표본 게이트. min(승수, 패수) 하한 추가.**

통계적 사실: RR = 평균수익/평균손실 은 **두 소표본 평균의 비(ratio)**. 분자·분모 각각 노이즈 + 비율분포는 분모가 0에 가까우면 분산이 폭발(정의역상 fat-tail이 TE보다 심함). 대박 1건이 평균수익을 부풀리면 RR이 튄다.

→ RR은 **총 N만이 아니라 min(승수 W, 패수 L) 하한**으로 게이트:
- **min(W, L) < 5** → RR "손실/이익 표본 부족 — RR 참고 불가" (총 N이 20 넘어도 손실이 3건뿐이면 평균손실이 3표본 → RR 분모 불안정).
- **단일거래 의존 플래그(RR 전용)**: 한 승자가 총이익 >50% → "RR 과대 가능(단일 대박 의존)". compute_metrics 의 max_profit_pct 재활용.

즉 표본 게이트는 2중: **TE는 총 N≥20**, **RR은 추가로 min(W,L)≥5**. RR은 TE보다 한 단계 더 보수적으로.

## 반례 / 한계

- **표본 임계의 반례**: N=15 전승 +45% 전략을 "표본 부족"으로 숨기면 진짜 엣지를 놓칠 수 있다. → 반박: 15전승은 추세장 survivorship 과 구분 불가. 오해를 주는 큰 TE(과다배분)의 비용 > "표본 부족, 지켜보는 중"의 비용. floor 유지하되 **N·순손익 raw 는 노출**해 가능성은 보이게.
- **진입가 기준 %의 한계**: 보유기간 무시. VB 의 하루 +5% 와 donchian 의 20일 +5% 는 같은 % TE 라도 복리 속도가 다름 → **전략 간 % TE 비교는 보유기간을 뒤섞는다.** (시간정규화 TE 는 별도 Phase.)
- **손익비/분해도 소표본에선 노이즈**: 평균수익이 승 3건에서 나오면 손익비 자체가 흔들림 — Q4 임계가 분해값에도 동일 적용.
- **3개월 윈도우의 우연**: 진짜 망가진 전략도 운으로 양의 3개월 TE, 멀쩡한 전략도 음수 가능 → **TE 만으로 자동 조치(비중 조정) 금지.** 운영자 판단 보조 지표.
- **R-multiple 미지원**: 이론적 정본(리스크 대비 기댓값)은 진입시 손절가 미저장으로 현재 불가.
- **RR은 비율이라 TE보다 더 불안정**: 분자·분모 각각 소표본 평균 + 비율분포 fat-tail. 평균손실→0 부근에서 RR 폭발. 대박 1건이 평균수익을 부풀려 RR 과대. → RR 표본 게이트(min(W,L)≥5)가 TE(N≥20)보다 엄격한 이유. 반례: 손실이 5건 미만이라 "RR 참고 불가"로 가리면 진짜 고RR 전략을 놓칠 수 있음 → 반박: 5표본 미만 손실평균 위의 RR은 다음 손절 한 방에 반토막 → 가리는 게 정직.
- **필요RR도 노이즈**: 필요RR=L/W 는 승/패 카운트의 소표본 추정. 실제RR·필요RR 둘 다 노이즈라 게이지 비교는 이중 노이즈 → 표본부족 구간 게이지 뮤트로 흡수.
- **구조 태그의 자의성**: 견고형/취약형 4분면 경계(승률50%/RR1.0)는 편의적. 경계 근처 전략은 태그가 흔들림 → 태그는 "참고", 자동 조치 금지(Q10).

1. **결정적 합성 시리즈 (tdd)**: (a) 매수 10,000→매도 11,000 왕복 → TE=+10.0%(진입가) ≠ +9.09%(매도가) 회귀로 소스 기준 고정. (b) 분할매도 3회 1왕복 → N=1 검증(PARTIAL 이중카운트 부재). (c) 보합 왕복(매수=매도) 포함 시 TE=net/N 항등 검증. (d) open 포지션 → TE 모집단 제외 검증.
2. **표본 임계 경계 (tdd)**: N=19/20/49/50 경계에서 배지·caption 전환 검증.
3. **청산일 윈도우 (tdd)**: 매수 D-100 / 매도 D-30 왕복이 90일 윈도우에 포함되는지(청산 기준).
4. **매매 안전성 (tester)**: `git diff` risk.py/order_engine.py/realtime/·scheduler 매매 hot path = 0 확인. 시장시간 DB 부하 측정(전용 엔드포인트 + 캐시).
5. **운영 데이터 실측 (tester)**: 6전략 3개월 실제 N 분포 뽑아 "표본 부족" 구간 전략 명단 확정 → 임계값(20/50) + RR게이트(min(W,L)≥5) 현실 검증. 필요 시 도메인 재자문.
6. **RR·필요RR·동치 (tdd)**: (e) 필요RR = 패수/승수 검증, 보합 포함 시 서적 `(1−승률)/승률` 과 분기(보합>0 케이스). (f) TE>0 ⟺ 실제RR>필요RR 동치 회귀(경계 TE≈0 포함). (g) 평균손실=0(전승 표본) → RR "산정 불가" + 표본부족 뮤트. (h) 우위/열위 배지 = TE 부호 AND 표본게이트 통과 시에만.
7. **RR 표본 게이트 (tdd)**: min(W,L)=4/5 경계에서 RR "참고 불가"↔표시 전환. 총 N≥20 이어도 L<5 면 RR 뮤트. 단일 승자 총이익>50% → "RR 과대" 플래그.
8. **구조 태그·게이지 (frontend tdd)**: 견고형/취약형/균형형 4분면 경계(승률50%/RR1.0) 렌더. 게이지 채움(실제RR) vs 마커(필요RR) 우위/열위 색상. 표본부족 시 게이지·태그·배지 뮤트 동시.
