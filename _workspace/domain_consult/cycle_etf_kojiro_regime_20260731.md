## 트레이더 시각 — 지수 대순환 스테이지를 레짐으로 쓴다는 것의 의미

### 시장 가설

고지로 대순환 스테이지는 EMA 5/20/40 배열이 만드는 **중기 추세 국면 판정기**다. 지수에 걸면 곧 "시장 전체가 지금 상승 사분면(6→1→2)인가 하락 사분면(3→4→5)인가"를 읽는 것. 우리 7 전략은 전부 **롱 온리 + 돌파/추세추종 계열**(VB·모멘텀·LTV·donchian·BFB·VCP·kojiro)이라, 지수가 무너지는 국면에서 개별 종목 돌파는 대부분 **페이크 돌파**가 되고 베타에 쓸려 내려간다. "하락 국면엔 신규 매수를 줄여라"는 지수 레짐 가드는 이 전략군의 최대 약점을 정확히 겨냥한다 — 방향성이 옳다.

핵심은 dkstock과 지수 스테이지가 **서로 다른 시간 척도**라는 점:
- **dkstock (VIX/공포탐욕)** = *빠른 패닉 감지*. 하루 만에 VIX 15→30 튀는 급락을 잡는다. 후행성 낮음, 노이즈 높음.
- **지수 대순환 스테이지** = *느린 국면 판정*. EMA 40일이 뼈대라 태생적 후행. 급락 못 잡지만, 추세가 꺾인 "장세 자체"를 안정적으로 읽는다.

→ 둘은 경쟁이 아니라 **상호보완**. dkstock이 "불났다"를 외치고, 지수 스테이지가 "계절이 겨울로 바뀌었다"를 알린다. 이래서 통합이 타당하다.

### 스테이지별 트레이더 해석 (posture 매핑의 근거)

| 스테이지 | EMA 배열 | 트레이더 언어 | posture |
|---------|---------|--------------|---------|
| 1 | S>M>L (정배열) | 안정상승·최강세, 돌파 승률 최고 | **aggressive** |
| 2 | M>S>L | 상승 후반/단기조정, 큰 추세는 생존 = 눌림목 | **neutral** (약간 aggressive) |
| 3 | M>L>S | 하락 전환, 단기선이 장기선마저 뚫음 = 추세 훼손 시작 | **defensive 경계** |
| 4 | L>M>S (역배열) | 안정하락·최약세, 롱 전략 전멸 | **defensive** |
| 5 | L>S>M | 하락 후반/반등 시작, 데드캣이냐 진바닥이냐 = 칼날 | **defensive 경계** |
| 6 | S>L>M | 상승 전환, 단기선 복귀 = 신규 매수 재개 적기 | **neutral** (약간 aggressive) |

**방어 트리거 집합 판정** — 대순환의 3-4-5는 "하락 사분면", 6-1-2는 "상승 사분면". 방어는 하락 사분면 전체 = **{3,4,5}가 정석**.

- 스테이지 3 조기 방어 vs 스테이지 4 지연 방어 트레이드오프의 핵심: 우리는 이미 **개별 종목 손절/트레일링/15:20 청산**이 하방을 지킨다. 지수 가드의 역할은 "새로 사지 마라"뿐. 하락 전환(3) 시점에 새로 사는 매수는 대부분 페이크 돌파 매수 → **3 포함(조기 방어)이 손익비를 개선**한다. whipsaw 헛방어 비용은 SOFT(×0.5, 절반만 산다)라 작다.
- 스테이지 5 딜레마: 5는 "반등 시작"이라 여기서 완전히 막으면 진바닥을 놓친다. 하지만 5는 아직 역배열 잔재(L>S>M) = 데드캣 위험 높음. 우리 전략은 돌파/추세추종이라 진짜 바닥은 스테이지 **6(상승 전환)**에서 잡아도 늦지 않다 → 5 방어 유지가 롱 온리에 안전.

### 실전 사례 / 통계

- EMA 5/20/40 대순환에서 지수는 개별 소형주 대비 스테이지 전환이 훨씬 안정적(유동성·노이즈 우위). 그러나 **횡보장**(방향성 실종)에서는 세 EMA가 뭉쳐 경계(특히 2↔3, 5↔6)가 하루 단위로 진동한다 — Q5 히스테리시스의 실체.
- 급반등장(V자, 예: 2020-03·2024-08 반등) 에서는 스테이지 4→5→6 전환이 며칠 지연되는 동안 지수 방어가 유지되어 반등 초입을 놓치는 것이 이 지표의 구조적 대가 — Q4에서 HARD 완전차단을 배제하는 근거.

### 위험 시나리오 (가설이 깨지는 조건)

1. **후행성**: 스테이지4 확정 시점엔 지수가 이미 상당폭 빠진 뒤. 급락 패닉은 못 잡음(그건 dkstock VIX 몫).
2. **V자 반등 뒤처짐**: 스테이지5 방어 유지 → 바닥 반등 초입(수익률 최고 구간) 매수 봉쇄.
3. **횡보장 whipsaw**: 방향성 없는 장에서 경계 진동 → 가드 on/off 깜빡임.
4. **지수 ≠ 우리 유니버스**: kojiro 전체상장·momentum 테마 회전 종목은 지수와 상관이 낮은 경우가 많음. 지수 방어가 이들엔 오탐.
5. **롱 온리 전제**: 전 논리가 "하락장엔 안 사는 게 낫다"에 의존. 인버스/공매도 전략이 생기면 스테이지4는 오히려 기회.

## 질문별 판정 + 3안 정렬

### Q1. 대상 지수 — KODEX200 단독 vs +코스닥150 vs 인버스

| 안 | 내용 | 평가 |
|----|------|------|
| A | KODEX200(069500) 단독 | 단순하나 코스닥 국면 놓침. 코스닥 비중 큰 kojiro/momentum 부적합 |
| **B** | KODEX200 + KODEX 코스닥150(229200) 결합 | **권고**. 우리 유니버스가 양 시장 혼재(kojiro=전체상장, donchian=KOSPI200∪KOSDAQ150) |
| C | 인버스(114800/251340) 병용 | **비권고**. 인버스 스테이지는 069500의 거울(4↔1 대칭) = 독립 정보 0, 노이즈만 추가 |

**결합 규칙 (B 채택 시) 3안**:
- **OR (하나라도 방어 스테이지면 방어)** — *1단계 권고*. 한 시장 무너지는데 다른 시장만 보고 계속 사는 것보다, 한쪽 경고에 절반 축소가 안전. 롱 온리 + SOFT 축소라 과잉 방어 비용 제한적.
- AND (둘 다 방어여야 방어): 보수적. 코스닥만 붕괴 시 코스닥 종목 계속 매수 = 위험.
- per-market (종목 소속 시장의 스테이지 적용): 가장 정교하나, 매수 가드가 **전략 단위 boolean**인 현 구조에서 종목→시장 매핑 분기는 상당한 재설계. **2단계 정교화 인계**.
- 시총가중: 코스피 시총 압도 → 사실상 KODEX200 단독화, 코스닥 희석 = **비권고**.

**반례**: 코스피 강세(스테이지1)인데 코스닥만 일시 스테이지3(순환매) → OR이면 코스피 대형주 매수까지 ×0.5로 기회 손실. 이 경우 AND/per-market이 우월. → OR 과잉 방어가 실측으로 크면 per-market 전환.

### Q2. 스테이지 → posture 매핑 + 방어 트리거 집합

- 매핑: **위 표** (1=aggressive / 2=neutral / 3·4·5=defensive / 6=neutral).
- 방어 트리거 집합 3안:
  - **{3,4,5}** — *권고*. 하락 사분면 전체. 조기 방어 + 반등 확인(6)까지 유지. SOFT라 기회비용 감내 가능.
  - {4,5}: 하락 확정 후 방어(3 전환 허용). 3에서 상당 하락 흡수. 조기 방어 포기.
  - {4}: 확정 하락만. 가장 지연. "소 잃고 외양간".
- 3↔4 진동은 **둘 다 {3,4,5} 내부**라 방어 유지에 무영향. 관리 대상은 방어집합 경계(2↔3, 5↔6) 진동뿐 → Q5로 처리.

### Q3. dkstock와 결합 구조

| 안 | 내용 | 평가 |
|----|------|------|
| **(a)** | 지수 스테이지를 **항상 평가되는 독립 OR 사유**로 추가 | **권고**. dkstock 생사 무관하게 우리 데이터로 계산 → 로버스트니스 본질. dkstock 죽어도 지수 사유 잔존(=자동 fallback), 살아있어도 지수의 독립 정보 활용 |
| (b) | dkstock 다운 시에만 fallback | 로버스트니스는 풀지만 dkstock 정상 시 지수 독립 정보 버림 = (a)의 부분집합 |
| (c) | 가중 결합/스코어링 | 현 boolean OR 구조와 이질 + 가중치 근거 데이터 없음 = **비권고** |

**(a)가 (b)를 포함**: 독립 OR 사유로 두면, dkstock 사유가 0개여도(=다운) 지수 사유가 남아 (b)의 fallback 효과가 자동 발생. 따라서 (a) 하나로 충분.

**cash_usage_ratio 관계**: 지수 스테이지는 **cash_usage_ratio에 미연동**, 매수 가드(block_reason)에만 연동 권고.
- cash_usage_ratio = "자금 배분"(느림, 다음 영업일 반영), 매수 가드 = "실시간 진입 억제"(빠름).
- 지수 방어는 장중 진입 억제가 목적 → 매수 가드 계층이 정확. cash_usage_ratio 연동은 복잡도 + 이중 축소 위험(Q4)만 키움.
- cash_usage_ratio는 dkstock `cash_min` 전용 유지.

### Q4. 신호 강도 — 이중 축소 위험 해소가 핵심

**먼저 안심**: 현 `get_buy_block_state` 구조상 **이중 축소는 발생하지 않는다**. `soft_multiplier`는 SOFT 모드 + triggered이면 **0.5 고정 단일값**(reasons 개수 무관, 곱셈 누적 아님). dkstock defensive + 지수 스테이지4가 동시에 reasons에 들어가도 수량은 ×0.5 **한 번**. 오늘 이미 SOFT+defensive로 ×0.5 발동 중인데, 지수4가 합류해도 여전히 ×0.5 — 이중 아님.

| 안 | 내용 | 평가 |
|----|------|------|
| A | dkstock 사유와 **완전 동급 합류** (HARD면 지수4도 완전 차단) | 지수 스테이지는 일봉 후행 지표 → HARD 완전차단은 과격. 스테이지4 지속 며칠간 신규 매수 전무 + 반등 초입(5/6) 봉쇄 |
| **B** | 지수 스테이지는 **자체적으로 SOFT 상한, HARD 승격 금지** | **권고**. 지수 사유 단독 trigger면 mode=HARD여도 blocked=False + multiplier=0.5로만 기여. dkstock 매크로(패닉)는 HARD 정당, 지수(국면)는 SOFT 적정 |
| C | 별도 약한 곱수(×0.7 등) | 복잡도 + 근거 데이터 없음 = 비권고 |

**B 근거**: 지수 대순환은 EMA 후행이라 스테이지4 확정 = 이미 상당폭 하락 후. HARD 완전차단으로 쓰면 "바닥에서 매수 금지" 부작용(스테이지5/6 진입 전까지 완전 봉쇄). 반면 개별 손절/트레일링이 이미 하방을 지키므로 지수 가드는 "신규 진입 속도 조절(절반)"이면 충분.

- 구현 유일 변경점: reasons에서 dkstock 사유와 지수 사유를 **구분**해야 함(태그 또는 별도 필드). HARD 분기에서 "지수 사유만 있으면 blocked=False + 0.5" 특수 처리. dkstock 사유가 동반 trigger면 dkstock 규칙 우선(HARD 차단 가능).

### Q5. 노이즈 / 히스테리시스

EMA 5/20/40은 이미 평활(특히 40일). 지수는 개별주보다 안정적. 그러나 횡보장 경계 진동은 실재. `stage_of`는 이미 "동가 시 직전 유지"로 미세 진동 일부 흡수.

| 안 | 내용 | 평가 |
|----|------|------|
| A | 단일일 stage_of로 충분 | EMA 평활 신뢰. 단, 경계 진동 시 ×0.5↔×1.0 깜빡임 → 진입 일관성 훼손 |
| **B** | **N일 연속 확인 (2일)** | **권고**. 방어 스테이지 2일 연속이면 방어, 상승 스테이지 2일 연속이면 해제. 1일 깜빡임 제거. 지수 레짐 1일 지연은 무해 |
| C | 비대칭(진입 즉시, 해제 지연) | 위험 회피엔 이상적이나 구현 복잡. 현 boot 1회/일 구조에 과함 |

**B 구현 이점**: 우리 boot는 07:50 1회 fetch = 레짐 하루 1회 갱신(일봉이라 장중 불변). whipsaw는 오직 "일 단위 전환"만 문제 → `get_recent_daily`로 **최근 2거래일 스테이지**만 확인하면 정확히 그것을 잡음. 매우 단순.

- 3↔4 경계: 둘 다 방어집합 → 진동 무영향. 2일 확인은 방어집합 경계(2↔3, 5↔6)에만 실효.

- **boot 로그**: `[etf_regime] KODEX200=stage4(안정하락) KOSDAQ150=stage3(하락전환) combine=OR posture=defensive mode=observe` 1행/일.

- **snapshot**: `market_regime_snapshots.raw_response` JSONB에 `etf_stage` 블록 포함(마이그레이션 없이 간단) + UI 노출. 별도 컬럼은 2단계 활성 시 고려.
- **다크런치 → 활성 게이트 4조건**:
  1. 2주 관찰 데이터 축적
  2. dkstock defensive 구간 ↔ 지수 방어 스테이지 구간 **overlap 분석**(지수가 dkstock을 얼마나 재현/선행/후행)
  3. **지수 단독 방어**(dkstock 미방어)일 때 실제 시장 하락 여부 = 신호 유효성(헛방어율)
  4. 2일 확인 후 **잔존 whipsaw 빈도**

## 현 코드와의 정합성

### 충돌 항목

- **충돌 없음(호환적 확장)**. `_collect_reasons` 4임계 OR에 1항 추가 + `soft_multiplier=0.5` 단일 구조라 이중 축소 원천 부재.

### 구조 변경점 (신규 결정 필요)

1. **[HIGH] reasons 사유 태깅**: 지수 스테이지를 SOFT 상한(Q4-B)으로 두려면 `get_buy_block_state`의 HARD 분기에서 "지수 사유 단독이면 blocked=False + multiplier=0.5" 특수 처리 필요. 현 구조는 reasons 존재만으로 blocked 판정 → dkstock 사유와 지수 사유를 리스트에서 **구분**(태그/별도 필드)해야 함. **유일한 실질 구조 변경.**
2. **[MEDIUM] `has_regime_data` / 사이클 D `guard_inert` 조정**: 지수 스테이지는 우리 자체 데이터라 dkstock 죽어도 available. `has_regime_data`가 dkstock 필드만 보므로, 지수 신호 도입 시 `[regime_guard_inert]` 경보가 "지수 신호는 살아있음"을 반영하도록 조정(지수 신호 available이면 완전 inert 아님). 이 조정이 **로버스트니스 동기의 완결점**.
3. **[MEDIUM] 일봉 신선도 게이트**: 지수 스테이지는 `stock_master_daily`에 069500/229200 일봉이 매일 16:00 적재돼야 유효. 두 ETF가 daily load 유니버스에 안정적으로 포함되는지(VCP universe=KOSPI200∪KOSDAQ150엔 ETF 미포함 → 현재는 kojiro 전체상장 경로로 적재 추정) + boot 시점 D-1 봉 최신성 확인 필요. **stale 일봉으로 계산한 스테이지는 오판** → boot에서 `max(bas_dd)` 신선도 가드 + stale 시 관찰/미반영 폴백.

### 변경 vs 유지 선택지

- **변경(권고)**: 위 3개 구조점 반영 + 관찰 전용 다크런치 배선. 로버스트니스 확보 + 검증 경로 확보.
- **유지**: 현 dkstock 단독. 07-27 프래질리티 재발 위험 존속.

### 안전 규칙 충돌 (CLAUDE.md "절대 깨지 말 것") — **0건**

- 이 기능은 **매수 진입 전 가드**(risk.on_tick 매수 분기) 한정. 매도/손절/트레일링/익일청산/15:20 강제청산/상한가 손절 hot path **무접촉**(사이클 38 명문화 준수).

### tdd-engineer (Red 테스트 결정적 입력 시리즈)

- **스테이지 매핑 결정성**: 합성 EMA 배열 6종(각 스테이지 대표) → `stage_of` 정확 판정 + `_STAGE_MAP` 정본 회귀 가드.
- **방어집합 판정**: 스테이지 {3,4,5}→방어 True / {6,1,2}→False. 경계값(동가 시 직전 유지) 케이스.
- **2일 확인 히스테리시스**: `[2, 3]`(어제2 오늘3)→미방어(1일뿐) / `[3, 3]`→방어 / `[3, 6]`→해제 / `[4, 4, 5]`→방어 유지. freezegun 불필요(일봉 시리즈 직접 주입).
- **OR 결합**: (KODEX200=1, KOSDAQ150=4)→방어(OR) / (1,1)→미방어 / (4,4)→방어.
- **SOFT 상한 (Q4-B 핵심)**: mode=HARD + **지수 사유 단독** → `blocked=False, soft_multiplier=0.5` (완전차단 아님) / mode=HARD + dkstock defensive 동반 → `blocked=True`(dkstock 우선). **이중 축소 부재 회귀**: dkstock defensive + 지수4 동시 → multiplier 정확히 0.5(0.25 아님).
- **관찰 모드(다크런치)**: `etf_regime_enabled=False` → reasons에 `[관찰]` 기록만 + blocked/multiplier 미반영(배제 0).
