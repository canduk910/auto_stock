# 자문 주제 — 종목수 제한(max_positions) vs 종목별 유닛 제한 + Σ오픈리스크 캡

작성: domain-expert (데이/스윙 트레이더 출신 컨설턴트)
요청: team-leader (사용자 원질문 전달)
대상 전략: kojiro(고지로 대순환), BFB, VCP — "최소 3개 전략 유닛 단위 매매" 결정 맥락

## 질문 요약

> "종목별로 유닛 제한이 있으니 굳이 **종목수 제한**을 또 해야 하나? 종목별 유닛수 제한을 두면 리스크 관리가 되는 것 아닌가? 혹시 **피라미딩**을 빨리 적용해야 종목수 제한을 걷어낼 수 있을까?"

사용자의 직관 = **"종목별 유닛 제한이 곧 리스크 관리"** → 그러므로 개수 캡은 중복.
과거 결론(2026-08-04, `strategies/CLAUDE.md`) = **"리스크 캡만 두면 저ATR 종목 수 폭증"** → 개수 캡을 리스크 캡으로 대체 금지.

이 둘을 정면으로 대조한다. **선(先)정정 사항 하나** — team-leader 브리핑은 유닛 리스크를 ~1%로 가정했으나, 코드 실측은 `risk_pct=0.005`(0.5%, 1N 기준)이고 손절이 2N(`stop_atr=2.0`)이라 **손절선 기준 유닛 리스크 = 1.0%**다(코드 주석 line 182 "유닛 1.0%"와 정합). 아래 모든 정량은 이 커플링을 사용한다.

## 트레이더 시각

### 1. "유닛 = 리스크 브릭" 이라는 전제가 성립할 때만 사용자 직관이 옳다

원전 터틀(리처드 데니스 / 커티스 페이스)에서 **1 유닛은 정의상 "계좌의 1%가 1N(=ATR) 움직임에 노출되도록" 사이징한 고정 리스크 벽돌**이다. 손절이 2N이라 유닛당 손절 도달 시 손실 = 2%. 이 세계에서는:

- **유닛 개수를 세는 것 = Σ리스크를 %로 캡하는 것 (완전 동치)**. 12유닛까지 = 24% heat까지. 개수와 리스크가 같은 물건의 두 이름이다.

즉 **사용자 직관은 "이상적 터틀"에서는 100% 옳다.** 유닛이 깨끗한 리스크 벽돌이면 종목수 제한은 유닛 총량 캡에 흡수된다 — 터틀에는 애초에 별도의 "종목 개수 제한"이 없었다.

**문제는 우리 시스템의 유닛이 깨끗한 벽돌이 아니라는 것이다.** 세 가지가 벽돌을 찌그러뜨린다(08-04 실측이 이미 증언):

1. **1주 양자화** — 예산 706K·소액 계좌에서 `floor(예산×0.5%/ATR)` 가 1주로 절삭. 08-04 실측 실현 유닛 리스크 = 목표의 58%.
2. **hard_stop_pct(−8%) backstop** — atr_ratio가 크면 2N이 −8%보다 넓어 캡에 잘림 → 리스크 축소.
3. **사이징 혼재** — position_ratio 포지션과 turtle 포지션이 섞이면 position_ratio 포지션은 고정 리스크 관계 자체가 없음.

그래서 우리 유닛은 "0.4~1.0% 사이를 오가는 들쭉날쭉한 벽돌"이다. **바로 이 때문에 2026-08-04에 Σ오픈리스크 캡(③)을 신설**해, 유닛 개수가 대리하려던 실제 값(Σ리스크)을 직접 재고 캡한 것이다. ③의 존재 자체가 "유닛 개수 ≠ 리스크"라는 자백이다.

### 2. 과거 결론 "저ATR 종목 폭증"을 라이브 숫자로 검증 — 결론은 옳으나 **메커니즘이 계좌 크기에 의존**한다

kojiro 실측 파라미터: 예산 706K, `position_ratio=0.20`, `risk_pct=0.5%`(1N)→유닛 리스크 1.0%(2N), Σ리스크 캡 4.5%, ATR 밴드 1.0~6.0%.

가드된 터틀 사이징의 임계(`strategies/CLAUDE.md` line 37) = `atr_ratio = risk_pct ÷ position_ratio = 0.005/0.20 = 2.5%`.
- **atr_ratio 2.5~6.0% (고변동, 리스크-제한 영역)**: 터틀 수량이 notional 상한보다 작음. 각 유닛이 목표 1.0% 리스크에 근접 → Σ리스크 캡 4.5% ÷ 1.0% = **약 4.5포지션**에서 ③이 물린다.
- **atr_ratio 1.0~2.5% (저변동, notional-제한 영역)**: 수량이 `position_ratio×예산=141K`로 클램프. 실현 리스크가 작아짐. atr_ratio 1.0%면 2N 손절폭 2% → 리스크 = 141K×2% = 2,824원 = 예산의 0.4%. Σ리스크 캡 4.5% ÷ 0.4% = **약 11포지션**까지 ③이 안 물린다.

**여기가 핵심이다.** 저ATR 종목만 담으면 ③(리스크 캡)은 11개까지 슬랙이다 → 과거 결론 "리스크 캡만으로는 폭증"은 **정확히 옳다.** 그러나 —

**현재 소액 계좌에서는 폭증이 실제로 일어나지 않는다.** 왜냐하면 ②(명목 캡: Σ매수금액 ≤ 예산)이 먼저 물리기 때문이다. notional-제한 포지션은 각 141K를 쓰므로 706K ÷ 141K = **5포지션**에서 ②가 소진된다. 그리고 이 5 = `1/position_ratio = 1/0.20`. 즉 **position_ratio가 0.20으로 큰 소액 계좌에서는 ②가 이미 개수를 ~5로 묶는다.**

정리하면 현재 계좌의 실효 개수 천장:
- 고ATR 위주 → ③이 ~4.5에서 물림
- 저ATR 위주 → ②가 5에서 물림 (1/position_ratio)
- **어느 쪽이든 max_positions(5 또는 6)와 거의 겹친다** → **개수 캡은 현 계좌에서 사실상 ②③에 이미 중복이다.**

### 3. 그런데 이 중복은 **계좌 크기에 의존**한다 — max_positions는 "미래를 위한 보험"

계좌가 커지면 position_ratio를 낮추게 된다(대형 계좌에서 종목당 20%는 과집중). position_ratio를 0.05로 낮추면:
- ②의 개수 천장 = 1/0.05 = **20포지션**
- 저ATR 포지션 각 0.4% 리스크 → ③은 4.5%/0.4% = **11포지션**까지 슬랙

→ 이제 **저ATR 종목 11개**가 ②③ 어디에도 안 걸리고 실제로 쌓인다. 개별 리스크는 작지만, 한국 중소형 11종목은 **테마 붕괴·전 시장 하한가 날 상관계수가 1로 수렴**한다. "독립적 작은 리스크 11개"라는 ③의 가정이 폭락일에 무너진다. 이게 08-04 결론이 지킨 것 — **상관·운영 리스크는 ②(자본)도 ③(정상 시장 heat)도 못 보는 축이고, 개수 캡만이 계좌 크기와 무관하게 그것을 막는다.**

### 4. 반례 — 개수 캡이 "죽은 제약"으로 드리프트할 위험

정직하게 반대편도: 현 계좌에서 max_positions가 ②③과 겹쳐 **독립적으로는 한 번도 물리지 않는다면**, 그것은 "있으나 마나"한 인지 부담이자 드리프트 소지다(누군가 나중에 "안 물리네" 하고 완화). 이 반례는 "개수 캡을 없애자"의 근거가 아니라 **"개수 캡의 역할을 문서로 못박아, ②③과 다른 축(상관·운영)을 지킨다는 걸 명시하라"**는 근거다.

## 원전 터틀의 실제 규칙 (질문 2)

커티스 페이스 "Way of the Turtle" / 원전 규칙:

| 층위 | 유닛 상한 | 우리 대응물 |
|------|-----------|-------------|
| 단일 시장(종목) | **4 유닛** | `max_units_per_stock=2` (피라미딩 부재로 도달 불가) |
| 밀접 상관 시장군 | 6 유닛 | **없음** (crude proxy = `max_positions_per_sector=2`) |
| 느슨 상관 시장군 | 10 유닛 | 없음 |
| 단일 방향(롱/숏) 전체 | **12 유닛** | `max_units_total=10` (피라미딩 부재로 ≡ max_positions) |

**결정적 사실 3가지:**

1. **터틀에는 "종목 개수 제한"이 별도로 없었다.** 개수 통제는 (a) 방향별 총유닛 캡 12 + (b) 상관군 유닛 캡이 대신했다. 피라미딩 없으면 12유닛 = 12종목이라 **총유닛 캡이 곧 개수 캡의 역할**을 했다.

2. **터틀의 개수 통제는 여전히 "유닛을 센다"** — %-리스크 캡 하나로 하지 않았다. 유닛이 고정 1% 벽돌이라 세는 것 = 리스크 캡이라서 그렇게 할 수 있었다. **우리 유닛은 벽돌이 아니므로(§1), 우리에게 "센다"와 "리스크 캡"은 갈라진다.** 그래서 둘 다 필요하다.

3. **터틀은 상관군 유닛 캡으로 집중을 막았다** — 순수 개수가 아니라 "상관 그룹 내 유닛 수". 우리는 이게 없고 `max_positions_per_sector=2`(kojiro 한정)가 조악한 대용물이다. **개수 캡을 없애려면 이 상관군 캡부터 갖춰야** 터틀처럼 "개수 없이 집중 통제"가 가능하다.

**→ `max_units_total`이 max_positions를 대체하려면 두 전제가 동시에 필요**: (a) 피라미딩(§질문3) + (b) 상관군 유닛 캡. 둘 다 없으면 `max_units_total`은 max_positions의 다른 이름일 뿐이다.

## 피라미딩 선행 여부 (질문 3)

### 피라미딩이 유닛 캡을 "의미 있게" 만드는 유일한 것 — 맞다

피라미딩(같은 종목 0.5N마다 유닛 추가, 최대 4유닛) 없이는:
- 1종목 = 항상 1유닛 → `max_units_per_stock=2`는 도달 불가(무의미)
- `max_units_total=10` ≡ `max_positions` (완전 동치)

→ **피라미딩 없이 max_positions를 제거하고 max_units_total로 대체하는 것은 "개명"이지 행위 변화가 0이다.** 순수 churn.

### 그러나 피라미딩을 넣어도 개수 캡을 완전히 대체하진 못한다

피라미딩 도입 후 `max_units_total=10`이면 "3종목×3~4유닛" 또는 "10종목×1유닛" 둘 다 허용. **총유닛 캡은 종목 수를 직접 안 묶는다** — 여전히 10개 단일유닛 종목을 담을 수 있다. 터틀은 이걸 **상관군 캡**으로 막았지 개수 캡으로 막지 않았다. 우리에겐 상관군 캡이 없다. → 피라미딩 후에도 개수(또는 상관군) 통제는 별도로 필요.

### 소액 계좌 115만원에서 피라미딩의 현실성 — **비현실적** (질문 3·4의 핵심)

피라미딩은 **본질적으로 대형 계좌 기법**이다. 유닛에 해상도가 있어야 "0.5N마다 1유닛 추가"가 의미를 갖는다.

숫자로: 예산 706K·risk_pct 0.5%·1유닛 목표 리스크 = 3,530원(1N 기준). 종목가 50,000원, 손절폭 2N=8%(hard cap)면 유닛 명목 = 3,530/0.08 = 44K → **0.88주 → 절삭 0~1주**. 이미 1유닛이 1주 이하다. 여기에 4유닛 피라미딩 = "4번에 걸쳐 1주씩" = 사이징이 순수 노이즈. **0.5N 간격 추가의 우아함이 "가끔 1주 더" 로 붕괴**한다.

피라미딩이 해상도를 가지려면 대략 **1유닛 ≥ 10주**가 필요하고, 50K 종목·8% 손절 기준 유닛 명목 ≥ 500K → 예산 × 0.5% / 8% ≥ 500K → **예산 ≥ 수백만~수천만 원**. 현재 706K로는 3~4배 이상 성장해야 피라미딩이 기능한다.

**→ 지금 피라미딩을 "종목수 제한 제거의 근거"로 도입하는 것은, 유닛을 깨끗하게 표현조차 못 하는 계좌에서의 조기 최적화다.** 순서가 거꾸로다.

## 소액 계좌에서 지금 max_positions를 걷어내면 실제로 무슨 일이 (질문 4)

**현 계좌(706K, position_ratio 0.20)에서는 행위가 거의 변하지 않는다.** ②(명목 캡)이 1/0.20 = 5에서 이미 물리므로, max_positions를 없애도 예산이 5~6종목에서 소진된다. 즉 —

- **제거의 실익 = 0** (오늘 아무것도 안 바뀜)
- **제거의 비용 = 계좌가 커져 position_ratio를 낮추는 순간 다시 넣어야 하는 가드를 잃음 + 의도의 명시적 진술을 잃음**

이론(터틀: 개수 캡 불요)과 실제(소액·position_ratio 큼 → ②가 대신 캡)의 괴리가 정확히 여기다. **지금 걷어내는 건 순수 하방(다운사이드)만 있고 상방이 없다.**

## 당장의 불변식 위반 처리 (질문 5)

`ratio 0.2 × maxp 6 = 1.2 > 1.0` — 불변식 `position_ratio × max_positions ≤ 1.0` 위반(코드 기본값은 0.20×5=1.0 정합, DB가 maxp 6으로 덮으며 깨짐). **방향 결정과 무관하게 즉시 시정 필요.**

| 안 | 조치 | 결과 | 트레이더 평 |
|----|------|------|-------------|
| **A** | maxp 6→5 | 0.2×5=1.0 | 안전하나 라이브 6보유 → **6>5 오버캡 상태**(매수 게이트만 막힘, 강제매도 없음 — 안전규칙상 청산 미차단). 새 매수만 1종목 청산 시까지 대기. legit하지만 표기상 "초과" |
| **B** | ratio 0.2→0.167 | 0.167×6=1.0 | **maxp를 현재 보유 6과 일치**시키고 종목당 명목만 축소. 오버캡 상태 없음. 최소 변경 |
| C | 코드 기본 복귀(0.20/5) | 1.0 | A와 실질 동일(오버캡) + DB 튜닝 이력 상실 |

**권고 = B (ratio 0.167, maxp 6).** 근거: (1) 개수 캡을 현재 보유 6과 정합시켜 인위적 오버캡 상태를 안 만든다, (2) 불변식을 정확히 1.0으로 만족, (3) 방향 A/하이브리드(개수 캡 유지)와 정합. A도 안전하나(청산 미차단이라 6보유 무해) 표기상 초과가 운영 혼선을 준다. **집중을 오히려 강화하고 싶으면 A**(종목당 20% 유지, 5종목) — 이건 사용자 취향 문제이지 안전 문제가 아니다.

## 정량 권고 — 3안 정렬

### 안 1 — 종목수 제한 유지 (삼중 캡 존치)

- ①②③ 그대로. 불변식만 B로 시정(ratio 0.167).
- **근거**: 소액 계좌에서 ①은 ②와 겹치나, 계좌 성장 시 상관·운영 리스크를 지키는 유일한 축. 값싼 보험. 08-04 결론과 정합.
- **반례**: 현 계좌에서 ①이 독립적으로 안 물려 "죽은 제약" 드리프트 소지 → 안 3이 이를 보완.

### 안 2 — 종목수 제한 철거 + 유닛 캡 전환 + 피라미딩 로드맵

## 정량 재계산 — 3대 발견 (모두 실측 스크립트)

파라미터: `risk_pct=0.005`(1N) → 2N 손절 시 **유닛 리스크 = 1.0%**. kojiro budget = 순자산 × weight(현 0.60). ATR 밴드 1.0~6.0%.

### 발견 1 — 피라미딩 해상도 임계가 **바로 net 500만**에 걸린다

`1유닛 주수 = floor(예산 × 0.005 / (atr_ratio × 가격))`. "1유닛 ≥ 10주"(양자화 오차 ≤10%, 피라미딩 유의미 임계)를 넘는 예산:

| 자본(net@w0.6) | 예산 | 대형 P10만·a2% | 중형 P5만·a3% | 소형 P1만·a5% |
|---|---|---|---|---|
| 현재 117만 | 702K | **1주** | 2주 | 7주 |
| **500만** | 300만 | 6주 | **10주** | 30주 |
| 5000만 | 3000만 | 60주 | 100주 | 300주 |
| 1억 | 6000만 | 120주 | 200주 | 600주 |
| 2억 | 1.2억 | 240주 | 400주 | 1200주 |

**중형주 기준 1유닛 10주 = net 500만(예산 300만)에서 정확히 교차. 최악(대형 고가·저ATR)도 net ~667만.** 즉 **근시일 목표 500만이 피라미딩이 "노이즈→유의미"로 바뀌는 문턱**이다. 초판의 "수백~수천만" 추정을 정밀화하면 **net 500만 = 피라미딩 배선 준비 게이트, net ~667만 = 전 종목 커버**. 다만 현재(117만)에서 대형주는 아직 1주라, 500만 이전엔 여전히 해상도 부족.

### 발견 2 — ② 명목 개수 천장 = `floor(1/position_ratio)`, **자본과 무관**

| position_ratio | 명목 개수 천장 | notional/risk 크로스오버 atr_ratio |
|---|---|---|
| 0.20 (현재) | 5 | 2.50% |
| 0.166 | 6 | 3.01% |
| 0.125 | 8 | 4.00% |
| 0.10 | 10 | 5.00% |
| 0.08 | 12 | 6.25% |
| 0.05 | 20 | 10.0% |

**개수 천장은 예산이 아니라 position_ratio가 결정한다.** 그리고 position_ratio가 낮아질수록 크로스오버 atr_ratio가 올라가 **밴드(1~6%)의 더 많은 부분이 notional-제한 영역**이 된다 = 각 포지션 리스크가 1%보다 작아짐 = **③이 슬랙해지고 저ATR 종목이 실제로 쌓인다.** 이게 초판 §3에서 예고한 "계좌 성장 시 폭증 현실화"의 정확한 메커니즘. position_ratio 0.05면 크로스오버 10%라 밴드 전체가 notional-제한 → 20종목까지 ②만으로 허용.

### 발견 3 — ③ Σ리스크 캡은 **규모 불변(scale-invariant)**, 항상 4.5 full유닛에서 물림

③은 예산 대비 %, 유닛 리스크도 예산 대비 %(1.0%)라 **비율끼리 상쇄 → `max_open_risk_pct / 1.0%` 는 자본이 100배 커져도 4.5개 그대로.** 규모가 커져 종목을 20개 담고 싶어도 **③은 여전히 4.5 full유닛에서 잠근다.** 더 많은 이름을 가지려면 둘 중 하나: (a) 저ATR notional-제한 포지션 위주(각 <1% → ③ 슬랙) — 위험한 우회 or (b) **max_open_risk_pct를 명시적으로 상향** — 단 이건 상관군 캡이 전제(안 그러면 상관 노출만 키움). 터틀은 방향별 12유닛(=12% heat)까지 허용했는데, 그건 **밀접상관 6·느슨상관 10 유닛 캡이 동반됐기 때문**이다.

**→ 사용자 직관("종목수 제한 걷어내기")은 방향은 옳고, 성장 경로의 최상단(net 1-2억, 지원 기제 완비 후)에서 비로소 실현된다. 그 전 모든 단계에선 걷어내면 안 된다. 제거는 로드맵의 마지막 단계지 첫 단계가 아니다.**

## 상관군 캡 — kojiro 섹터캡은 씨앗인가?

**씨앗이 맞다.** `max_positions_per_sector=2`(kojiro, `_kojiro_sector_key` KRX basket)는 터틀 "밀접상관 시장군 유닛 캡"의 조악한 대용물이다. 성숙 경로:
1. **T2 — 유닛화**: 개수 → 유닛(`max_units_per_sector`). 피라미딩으로 1종목 4유닛이 되면 개수 캡이 유닛 집중을 못 봄.
2. **테마 축 추가**: 한국 중소형은 **섹터를 가로질러 테마로 동반 등락**(2차전지·초전도체·정치테마 등). 섹터(KRX 업종) 단독은 테마 상관을 놓친다. `_kojiro_sector_key`에 테마 그룹핑 보강 필요.
3. **전략 간 통합 — 이미 관측 인프라 존재**: 사이클 H `portfolio_risk.py`의 `by_sector`가 **7전략 통합 섹터 노출을 이미 관측**한다(관찰 전용). donchian 반도체A + VCP 반도체B + kojiro 반도체C 동시보유를 지금은 못 막는다. **이 관측을 게이트로 승격**(사이클 H Phase 2 인계 항목)하는 것이 전략 간 상관군 캡이다. T2에서 활성.

⚠️ **한국 중소형 상관=1 폭락 리스크**는 성장의 핵심 위험이다. net 5000만·15종목 중소형은 테마 붕괴·전 시장 하한가 날 "독립적 작은 리스크 15개"가 아니라 **동시 −30% 락 1개**로 행동한다. ③(정상 heat)도 ②(자본)도 이걸 못 본다 — 상관군 캡만이 본다. **그래서 max_open_risk_pct 상향의 전제 조건이 상관군 캡**이다.

## VCP/BFB — kojiro와 같은 로드맵인가? **아니다 (핵심 차별)**

세 전략을 "유닛 매매"로 묶었으나 **피라미딩 적합성이 근본적으로 다르다.**

| 전략 | 유닛 사이징 | 피라미딩 | 이유 |
|---|---|---|---|
| **kojiro** | ✅ 자연 적합 | ✅ T2+ | EMA 대순환 = **개방형 추세추종**. 승자에 유닛 추가가 정의상 맞음(터틀 원형) |
| **VCP** | ✅ (게이트) | ❌ 부적합(최대 2 "progressive" T3+) | **변동성 수축 진입** = entry ATR이 국소 최소 → 2N 손절 과도 타이트(−3%, `turtle_min_stop_pct` 밴드 필수). 베이스 돌파 1회지 피라미딩할 추세 아님. 미너비니 progressive exposure는 있으나 소수·타이트 |
| **BFB** | ✅ (게이트) | ❌ 부적합 | **measured-move 목표가 확정**(flag_high + pole). 정해진 목표가 있는 트레이드에 유닛 추가는 모순. 한 번의 thrust 트레이드 |

**함의:**
- VCP/BFB는 **유닛 사이징(리스크 균등화)까지만** 로드맵에 태우고 **피라미딩 분기는 제외**한다. 피라미딩 없음 → `max_units_total ≡ max_positions` 영구 → **VCP/BFB의 개수 캡은 T4에서도 흡수되지 않고 load-bearing 영구 존치**(kojiro와 정반대).
- **체결 게이트 우선(자본 게이트 아님)**: VCP/BFB는 도입 이래 **체결 0건**(진입 엄격). 라이브 표본이 0이라 유닛 사이징 활성은 **(a)체결 누적 (b)백테스트 스윕** 게이트지 자본 단계와 무관. 지금은 position_ratio(byte-identical) 유지. 자본 게이트(피라미딩)는 **kojiro 전용**.
- VCP/BFB도 성장 시 상관군 캡 필요 — 단 개수-기반(유닛화 불요, 피라미딩 없으니). 전략 간 통합 섹터 캡(사이클 H)이 이 셋을 함께 덮는 게 효율적.

## 지금 당장 vs 자본 게이트 vs 체결 게이트

**지금 당장 (표본 오염 회피 — kojiro N=1·0/4·0.35 FREEZE 국면이라 구조 재설계 금지):**
1. **불변식 1.2 지혈** — 권고 **B′: DB `position_ratio` 0.20→0.166**(×6=0.996 ✅. 초판의 0.167은 ×6=1.002 미세위반, team-leader 정정 수용). maxp 6 유지 = 현 보유 6과 정합·성장 방향(더 많은 이름)과도 정합. **대안 A**: maxp 5·ratio 0.20(=1.0 정확)이나 6보유 시 6>5 오버캡 표기(청산 미차단이라 안전하나 혼선). **B′ 권고.**
2. **개수 캡 역할 문서화** — `strategies/CLAUDE.md`에 "① = 상관·운영 백스톱(②자본·③heat과 다른 축), **소액=중복·중대형=load-bearing·대형=상관군캡으로 흡수가능**" 생애주기 1~2줄. 코드 diff 0.
3. **`max_units_*` inert 봉인 유지** — 소비처 0건 AST 가드 존치(피라미딩 배선 전 재도입 차단).

**자본 게이트 (kojiro):**
- T1(net~500만): 피라미딩 배선+다크런치, position_ratio 0.166 유지/미세조정
- T2(net~5000만): 피라미딩 활성·상관군 유닛캡 승격·max_open_risk_pct 6~8·position_ratio 0.08~0.10
- T3~T4: position_ratio 0.04~0.08·max_open_risk_pct 10~12·max_positions 흡수 검토

**체결 게이트 (VCP/BFB, 자본 무관):**
- 체결 누적 + 백테스트 스윕 → 유닛 사이징 활성(하드손절 ATR화 동반). 피라미딩 없음. 개수 캡 영구 존치.

## 사용자에게 물어야 할 결정 지점

1. **weight 궤적** — kojiro weight를 성장 내내 0.60으로 두나? net 2억 × 0.60 = **1.2억을 단일 스윙 전략에 배분**하는 셈. 통상 대형 계좌는 전략 분산(weight↓)한다. weight가 낮아지면 위 예산/티어 매핑이 바뀐다. **성장 시 weight 궤적을 어떻게 가져갈지**가 선결.
2. **피라미딩 스타일 선택** — 승자에 유닛 추가(터틀 원형)는 수익률과 **드로다운 변동성을 동시에** 키운다. 고정 1유닛 진입(현재)을 유지할지, 터틀식 4유닛 피라미딩을 지향할지는 **스타일 결정**(정답 아님). 이 답이 T1 배선 여부를 가른다.
3. **max_open_risk_pct 상향 상한** — 규모 성장 시 총 heat 허용을 어디까지(터틀 방향별 12% / 보수 6~8% / 공격 10~12%)? 상관군 캡 완비가 전제.
4. **상관 그룹핑 입도** — 섹터(현재) / 테마 추가 / 전략 간 통합(사이클 H 승격) 중 어디까지?
5. **기제 구축 착수 자본** — 피라미딩·상관군캡 기제를 **어느 net에서 코드 착수**할지. 권고 = **net 500만 도달 시**(해상도 교차점), 그 전엔 지금-당장 3항목만.

**개정판 한 줄**: 성장 경로에서 리스크 구조는 **"소액 notional-집중 → 대형 ATR유닛-계층"의 인계**다. 피라미딩 해상도는 정확히 **net 500만**에 교차하고(발견1), ③은 규모 불변이라 성장하려면 **상관군 캡 완비 후 max_open_risk_pct 상향**이 필수(발견3). max_positions는 소액=중복·중대형=load-bearing·대형(T4)=흡수가능이라 **사용자의 "걷어내기"는 net 1-2억 최상단에서 비로소 실현**된다. VCP/BFB는 피라미딩 부적합이라 kojiro와 로드맵이 갈린다(유닛 사이징만, 개수 캡 영구). **지금은 불변식 B′ 지혈 + 문서화만**(FREEZE 표본 보호), 나머지는 자본/체결 게이트.
