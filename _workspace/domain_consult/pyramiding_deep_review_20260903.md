## 0.0 ⚠️ 재프레이밍 — 사용자가 실제로 마주한 결정은 "추가할까" 가 아니다

적대 비판이 찾아낸 가장 중요한 사실이다. **초판 §1.2 에 데이터는 있었으나 결론에 반영되지 않았다.**

| 전략 | 실제 체결 1랏의 크기 (터틀 유닛 환산) | 책의 완성된 4유닛 피라미드 |
|---|---|---|
| **donchian** | 평균 **4.94유닛** · 중앙 4.42 · 최대 **15.61** | 4유닛 |
| kojiro | 평균 1.52유닛 · 중앙 1.28 · 최대 3.37 | 4유닛 |

**donchian 은 진입하는 그 순간 이미 완성된 4유닛 피라미드보다 크다.** 확인 사다리도, 단계적 손절 상향도 없이, D0 에 한 방에 그 리스크를 진다. 원인은 `_fallback_one_share`(`strategy_base.py:431`) — 이론 유닛 수량이 0주면 **가격 무관하게 1주를 산다**(notional 상한 미검사, cycle233 `[oversized_fallback]` 은 관측만). 유니버스 중앙가가 kojiro 의 "1유닛 = 1주" 가격 상한(83,835원)보다 낮아도, donchian 의 상한(32,063원)은 이미 유니버스 절반 아래다.

시뮬이 이 사실을 그대로 증언한다 — 초판 헤드라인 −264,556원의 **87.6%(−231,636원)가 상위 악화 12건**에서 나오는데 그중 10건이 이론 유닛 0주(=1주 폴백)다:

| 종목 | 매수가 | 실제 1랏 = 터틀유닛 | 이론 유닛 수량 | Δ |
|---|---|---|---|---|
| 192820 코스맥스 (donchian) | 273,500 | **8.69** | 0주 | −44,336 |
| 336260 두산테스나 (donchian) | 89,600 | 7.56 | 0주 | −29,575 |
| 096770 SK이노베이션 (donchian) | 117,300 | 8.73 | 0주 | −29,054 |
| 086280 현대글로비스 (donchian) | 246,000 | **15.61** | 0주 | −13,875 |

**결론: "1주 폴백 = 진입 시점의 무허가 과잉 피라미딩(R15 위반)" 을 먼저 닫는 것이, 피라미딩 도입 여부보다 크고 급하고 확실한 개선이다.** 피라미딩 논의는 이것을 고친 다음에야 의미가 생긴다 — 고치기 전에 4유닛을 얹으면 15.6유닛짜리 "1유닛" 을 네 번 쌓는 셈이다.

> **시정안은 두 형태가 있고 대가가 다르다.** ⓐ *"이론 유닛 < 1주면 스킵"* — 가장 깨끗하지만 **donchian 은 왕복 24건 중 이론 유닛 ≥1주가 5건(21%)뿐**이라 거래 빈도가 ~79% 줄어든다(kojiro 는 9/14 = 64% 라 영향 작음). ⓑ *"폴백에 notional 상한"*(예: 1주 명목 ≤ `position_ratio × 예산`) — 거래를 덜 죽이지만 여전히 1유닛보다 큰 랏을 허용한다. **어느 쪽이든 4유닛을 얹기 전에 정해야 한다.**
>
> 이 시정은 매수를 **줄이는** 방향이라 안전하고, 접촉면이 `strategy_base.py` 한 곳(**비8영역**)이며, 피라미딩과 독립적으로 유효하다. **워크리스트 독립 등재를 권고한다**(아래 G0/G2′ 가 이것의 게이트 형태). ⚠️ 다만 ⓐ 는 매매 빈도를 크게 바꾸므로 "안전 방향" 이어도 **사용자 결정 사안**이다.

## 0.1 ⚠️ 조사 중 정정된 사실 3건 (전제)

**정정 1 — donchian 의 터틀 유닛 사이징은 살아 있다.**
한 렌즈가 "donchian 은 `risk_pct=null` 이라 no-op" 이라 보고했으나 틀렸다. 운영 DB 에서 `risk_pct` 는 **null 이 아니라 키 자체가 부재**하고, 병합 로직(`scheduler.py:423-426`)이 `if key in strategy.config.params` 라 **부재 키는 코드 DEFAULT 를 유지**한다(`risk_pct 0.005` · `stop_atr 2.0`). 라이브 검산 2건 일치:

| 종목 | 가격 | ATR14 | 이론 수량 `floor(387,320×0.005 / ATR)` | 실제 체결 |
|---|---|---|---|---|
| 088350 한화생명 | 5,790 | 354.6 | 5주 | **5주** ✓ |
| 293490 카카오게임즈 | 9,600 | 648.6 | 2주 | **2주** ✓ |

**일반 교훈: "DB 에 키가 없다" ≠ "기능이 꺼졌다".**

**정정 2 — kojiro 의 브레이크이븐 승격은 라이브에서 켜져 있다.**
코드 DEFAULT `breakeven_promote_atr: 0.0`(다크런치)이지만 **운영 DB 가 1.5 로 덮어쓴다**. donchian(코드 기본 1.5)·kojiro(DB 1.5) 둘 다 활성.
⚠️ **초판의 산술 오류 정정** — 초판은 "3번째 유닛 지점에서 브레이크이븐이 터틀선을 이기고 리스크가 훨씬 작아진다" 고 적었으나, 승격 트리거는 `high_since_buy ≥ buy_price + 1.5×ATR` 이므로 **4번째 유닛 지점**(P0+1.5N)이고, 그때 스택 리스크는 0/0.5N/1N/1.5N = **3N**(책 5N 의 60%)이다. "훨씬" 이 아니라 "40% 작다".
⚠️ **더 중요한 함의(초판 누락)** — 가중평단을 앵커로 쓰면 4유닛 스택의 승격 손절선이 **마지막 진입가 −0.75N** 에 놓인다(책 예: 평단 2075, N=100). kojiro MAE 중앙값이 **1.55N** 이므로 통상적 되돌림에 관통한다 → **4배 왕복비용을 내고 손익 0 근처에서 청산되는 구조**. §2.5 시뮬은 이 상호작용을 모델링하지 **않았다**(시뮬은 "손절 = 마지막 진입 −2N" 고정). 즉 시뮬은 '우리 시스템 + 피라미딩' 도 '책' 도 아닌 혼성이며, 실제 결과는 시뮬보다 **더 나쁠 수 있다**.

**정정 3 — 계좌 Σ리스크 상한은 구속되지만, 초판이 든 근거는 잘못됐다.**
초판은 "4랏 피라미드 최종손절 리스크 최대 **5.82%**(현대글로비스)" 를 근거로 삼았다. 재검산 결과:
- 그 5.82% 는 **2026-05-11 자본 1,089,256원** 기준이다. 오늘 자본(2,582,132원) 기준으로는 **2.47%**.
- 그 트레이드는 **donchian** 이고(초판은 kojiro 열에 배치), 이론 유닛 수량이 **0주**(1주 = 15.61유닛)라 어떤 유닛 사이징 규칙에서도 피라미딩이 발화하지 않는다 = 허수아비 사례.
- 초판 §2.5 표의 "avg 1.27% / max 5.82%" 는 **ALL 표본값**이다. kojiro 자체는 **avg 0.81% / max 2.18%**, donchian 은 avg 1.54% / max 5.82%.

**대체 근거(실제로 구속되는 것) = `max_open_risk_pct`.** kojiro Σ오픈리스크 캡은 예산의 4.5% 이고 4유닛 스택의 최종 리스크는 5N = 예산 2.5% 다. **4.5 ÷ 2.5 = 1.8** — 즉 kojiro 는 **4유닛 스택을 1.8개** 담으면 매수가 정지한다(BE 승격 후 3N 기준으로도 3.0개). 예산 한도(2.4개)보다 **리스크 캡이 먼저 물린다**. 초판은 이 캡을 kojiro 의 강점으로 나열하면서 그것이 구속 조건임을 계산하지 않았다.
그리고 **계좌 Σ상한을 강제할 장치(`account_risk_block_pct`)는 여전히 꺼져 있다**(system_config 키 부재 = 다크런치). 이것이 게이트 G4 의 근거다.

## 1. 첨부 규칙 요지와 이 계좌로의 번역

### 1.1 책 규칙 (p.162~179)

| 항목 | 1/2N 룰 | 1N 룰 |
|---|---|---|
| 추가 간격 | 유리한 방향 **0.5×ATR** 마다 1유닛 | **1×ATR** 마다 1유닛 |
| 동일 종목 상한 | 4유닛 | 4유닛 |
| 추가 시 손절 | **전 유닛 일괄** = 마지막 진입가 − 2N | 동일 |
| 예시 | 2000/2050/2100/2150 (N=100) → 손절 1950, 평단 2075 | 500/540/580/620 (N=40) → 손절 540, 평단 560 |
| 유닛별 리스크 | 0.5N / 1N / 1.5N / 2N = **합 5N** | −1N / 0 / 1N / 2N = **합 2N** |
| 책의 결론 | 기본 | 상황에 따라 보완적 |

상위 캡: 상관 높은 종목군 6유닛 / 상관 있는 군 10 / 전체 12. 물타기(손실 중 추가)는 금지 — 피라미딩은 **이익 중인 포지션에만**.
⚠️ 책의 사다리는 **"마지막 체결가 + 0.5N"** 이다. 갭업 체결 시 다음 눈금이 그만큼 위로 밀린다. (본 조사의 시뮬은 `P0 + k×0.5N` 고정 사다리를 썼다 — 책보다 유닛을 빨리 채우므로 **음수 엣지에서 손실을 과대계상하는 방향**의 편향. §2.5 한계 참조.)

### 1.2 이 계좌로의 번역 (2026-09-02 실측)

기준값: 순자산 **2,582,132원**, `cash_usage_ratio` 1.0, Σweight 1.00 (7전략 enabled).

| 항목 | kojiro (w 0.30) | donchian (w 0.15) |
|---|---|---|
| 전략 예산 | **774,640원** | **387,320원** |
| `risk_pct` | 0.005 | 0.005 (코드 기본) |
| **1유닛 리스크(1N 이동 시)** | **3,873원** (계좌 0.150%) | **1,937원** (계좌 0.0750%) |
| **책의 5N (4유닛 총리스크)** | **19,366원** = 예산 2.50% = **계좌 0.750%** | **9,683원** = 예산 2.50% = 계좌 0.375% |
| 실측 ATR비율 (중앙 / 평균) | **4.62% / 4.87%** | **6.04% / 5.88%** |
| 1유닛 명목(중앙 변동성) | 83,835원 (예산 10.8%) | 32,069원 (예산 8.3%) |
| **4유닛 스택 명목** | **346,961원 (예산 44.8% / 계좌 13.4%)** | 132,700원 (예산 34.3%) |
| notional 상한(호출당) | 128,590원 | 77,464원 |

| **실효 구속 조건** | **`max_open_risk_pct` 4.5% → 4유닛 스택 1.8개** | **없음 (Σ리스크 캡 부재)** |

유니버스 가격 중앙값: KOSPI200∪KOSDAQ150 **54,100원**(n=348) / 전체 상장 **24,520원**(n=990).

**핵심 번역 4.**

1. **책의 "1N = 자본 1%" 가 우리에겐 "전략예산 0.5%" 다.** 계좌 환산 kojiro 0.150% / donchian 0.075% — 유닛 밀도가 책 대비 **1/6.7 ~ 1/13.3**. 책의 "전체 12유닛 = 자본 12%" 는 우리 척도로 계좌 1.80%. **책 숫자를 그대로 읽고 "5%나 위험하다" 고 판단하면 틀린다.**
2. **그럼에도 위험하다 — 1주 불가분성 때문이다.** §0.0 참조. kojiro 는 중앙가 54,100원에서 1유닛 = **1.55주**, donchian 은 **0.59주**. donchian 은 구조적으로 항상 폴백 영역에 있다.
3. **실효 캡은 예산이 아니라 Σ리스크다.** kojiro 는 4유닛 스택 **1.8개**에서 매수 정지(정정 3). 즉 피라미딩 도입은 "6종목 분산 → 실질 2종목 집중" 이며, **파라미터 조정이 아니라 전략 정체성 전환**이다. (대안: "1유닛 = `position_ratio`/4" 로 정의하면 분산은 유지되나 해상도가 4배 악화 → kojiro 의 1주 폴백 경계가 ~21,000원으로 내려가 §0.0 문제가 폭증한다. **분산과 해상도의 교환이지 공짜 선택지가 아니다.**)
4. **donchian 에는 Σ리스크 캡 자체가 없다.** kojiro 에만 있다. 피라미딩을 donchian 으로 확장하려면 캡 신설이 선행이다.

### 2.2 아키텍처 제약 (배관 결함 4건)

**P-1 (핵심).** `order_engine.py:1211-1213`
```
else:   # 주석: "추가 체결 (부분 체결 이후)" ← 동일 주문의 분할 체결만 상정
```

`total_filled` 은 `_filled_qty[order_no]` = **order_no 별 누적**이다. 별개 주문인 2번째 유닛이 체결되면 1차 유닛 수량이 **사라지고** 매수가가 최신 체결가로 교체된다. DB 도 동일(`positions` ticker PK, `ON CONFLICT DO UPDATE`).
⚠️ **초판 정정** — 초판은 "자가 치유 없음 → 손절 감시 밖 고아 주식 영구 잔존" 이라 했으나 **과장**이다. `_sync_positions_from_balance`(`scheduler.py:3613`, `_scan_loop` 3회마다 ≈15분)가 매도 후 미보유 잔량을 KIS 평단으로 재등록한다. 정확한 심각도는 **"≤15분 지연 치유 + 손절 규약 열화"** — 재등록된 포지션은 `_entry_atr`·`_stop_floor`·BE 래칫을 잃어 **−8% backstop 만 남는다**. 그리고 매도 *전* 구간의 과소계상(손절이 실보유의 일부만 매도)과 DB 불일치는 실재한다.

**P-1b (초판 누락, 부분 체결 트리거).** `state.pending_buys.discard(ticker)` 가 `if total_filled >= ordered_qty:` **전량/부분 분기 앞**에 있다(`:1216`). 오늘은 `has_position` 이 2번째 주문을 막아 무해하지만, **`is_ticker_blocked_for_buy` 를 "보유중 허용" 으로 분해하는 순간** add#1 의 부분 체결 → `is_buy_pending`=False → add#2 통과 → `_schedule_cancel`(`:1465`, **ticker 키**)이 add#1 의 잔량취소 태스크를 `.cancel()` → **미체결 잔량이 KIS 에 영구 방치** + `pending_buy_amounts` pop 으로 예산 이중 청약. 시정(discard 를 전량 분기 아래로 이동)은 `is_max_positions` 카운트 의미까지 바꾸는 8영역 변경이다.

**P-2.** `update_trade_status`(`db/trade_history.py:113-117`) WHERE 에 `order_no` 가 없어(`ticker + trade_type + status='PENDING' + strategy`, LIMIT 없음) 같은 종목 PENDING BUY 2건이 겹치면 첫 체결이 **둘 다** COMPLETED 로 뒤집는다. **초판 누락 — 영향 범위가 체결 경로보다 넓다**: 같은 WHERE 를 `_schedule_cancel`(`order_engine.py:1474`)과 `mark_pending_buys_completed`(`scheduler.py:3633`)도 공유하므로, add#1 의 30초 취소가 **add#2 의 PENDING 행을 CANCELLED 로 뒤집는다**.

**P-3.** `pending_buys`(set) · `pending_buy_amounts`(dict) · `_pending_cancel_tasks`(dict) 전부 ticker 키 = 동일 종목 2건 동시 주문을 표현할 수 없다.

**P-4.** `check_budget_invariant` 가 params 만 읽어 실보유 유닛 미검사 → 4유닛 시 불변식 위반 탐지 불가. (단 `unit_count ≡ 1` 인 현재는 이 공백이 공허하다.)

**변경 불필요(유리) 3** — ① 매도는 이미 `pos.quantity` 전량 청산이라 터틀의 "전 유닛 동일 손절선 동시 청산" 과 정합 ② `get_trade_pairs` 가 분할 매수를 이미 가중평균 처리 ③ ①안(가중평단) 채택 시 UI·손익 리포트 diff 0.

### 2.4 시장 미시구조·KIS

- **KIS 는 피라미딩을 막지 않는다.** `docs/kis/error-codes.md` 실측 거부 코드 중 동일종목 재매수 거부 **0건**이고, 운영 이력이 동일 종목 재매수 체결을 증명한다(001440 · 042700 · 092220).
- ⚠️ **초판 오류 정정 — 그 이력은 물타기가 아니다.** 초판은 "이 시스템이 이미 물타기를 실행한 실측 기록" 이라 했으나 **범주 오류**다. EC2 재조회 결과 세 종목 모두 **전량 청산 후 재진입**이다: 042700 은 `BUY 310,500 (08:15) → SELL 295,000 (08:41) → BUY 300,000 (11:14) → SELL 289,000 (11:32)`; 001440 은 `BUY 43,700 → SELL 43,900(이익) → BUY 42,700 → 15:20 SELL`; 092220 은 동일가 1,843원 3건 + order_no 공란 = sync 산물. **열린 손실 포지션에 추가한 기록은 0건이며, 세 종목 모두 VB·momentum(피라미딩 대상 아님)이다.** 정확한 서술: *"KIS 도 코드도 동일 종목 재매수를 물리적으로 허용하며, 그것을 막는 것은 100% 내부 게이트다."*
- **호가 해상도는 제약이 아니다** — 0.5N 이 보유 8종목 전부에서 9.0~29.8틱. 제약은 **1주 불가분성**이다.
- **비용**: 왕복 ≈ 0.32~0.53%(매수·매도 각 1틱 crossing + 거래세 0.15% + 수수료 ~0.014%/편도) = **1N 의 5.3~11.5%**(초판 "9~13%" 정정 — 0.32/6.04% ~ 0.53/4.62%). 유닛 수와 무관하게 비율은 일정(절대액만 4배). 진짜 위험은 시장가 거부 시 `step_up(5)` 폴백 = 5틱 = 1N 의 최대 27.9%. 다만 09:05~09:30 창 매수 폴백 실측은 **0건**.
- ⚠️ **라이브 경로에 수수료·세금 모델이 전무하다** — `profit_loss = (price − buy_price) × quantity`(gross). `daily_realized_pnl` 도 `daily_loss_limit` 게이트도 비용을 못 본다. **회전율을 4배로 올리는 변경을 gross 손익으로 관리하게 된다.**
- **상관 캡은 신설 없이 근사 가능** — `resolve_sector_name` 단일 진실원 + kojiro `max_positions_per_sector=2` 라이브 + `portfolio_risk.by_sector{risk_won}` 집계가 이미 있다. ⚠️ **단, 현행 `max_positions_per_sector=2` 는 4유닛 허용 시 "같은 섹터 2종목 × 4유닛 = 8유닛" 을 설계상 허용**한다 — 책 R15 의 "높은 상관 6유닛" 초과. **개수 캡을 유닛 캡으로 바꾸는 것은 선택이 아니라 필수**(→ G11).
- 유동성·레이트리밋·WS 슬롯은 이 규모에서 제약이 아니다.

- **donchian 은 충실 사이징에서 피라미딩이 성립하지 않는다.** 24건 중 이론 유닛 ≥1주가 5건뿐이고, D1 부터 추가하면 그 5건의 추가 트리거가 전부 D0 에 있어 **Δ = 0**(한 건도 발화 안 함). 초판의 "donchian 4유닛 도달 6건 · 오른쪽 꼬리 없음" 서술은 전부 V0 허수아비 구성에 대한 것이었다.
- **kojiro 에는 꼬리가 있다** — 슈프리마(236200) 1랏 3.96N → 4유닛 **+12.83N(+31,179원)**, 에스원(012750) +5,700 → +14,914. 오픈 3종목(빙그레 5.74N · SK케미칼 3.61N · 삼성화재우 3.06N)도 4유닛 도달. **단 kojiro 합산은 as-built 에서도 −23,927 로 악화**(개선 2 / 악화 7)이고, 오픈 종목 수치는 **생존 편향**(지금 이기고 있는 것만 남은 표본)이다. kojiro 실현 총이익 15,330원(승 3건)의 **63%가 슈프리마 1건(+9,600원)**에서 나온다 — **오른쪽 꼬리 논거는 표본 1건에 걸려 있다**.

**모형 한계 (반드시 병기).**
1. **청산 규약 혼성** — 손절만 터틀(마지막 진입 −2N), 청산은 현행 전략 규약. **BE 승격 1.5 와 가중평단 앵커의 상호작용은 미모델링**(정정 2 — 실제는 시뮬보다 나쁠 수 있다). 터틀 원전 10/20일 채널 청산과의 **결합 편익은 완전 미측정**.

흑자 전략은 momentum(+285원/트레이드) · LTV(+163원)뿐이고 **둘 다 당일·익일 청산이라 피라미딩 무관**.

**1/2N vs 1N — 초판 권고 철회.**
초판은 "실측은 1N 이 덜 나쁘다 → 재개 시 1N" 이라 권고했다. **총 Δ 만 보면 맞지만 노출량 착시다.**

| 척도 | 1/2N | 1N |
|---|---|---|
| as-built 총 Δ (kojiro) | −23,927 | **−22,424** |
| 추가된 터틀 유닛 수 | 10.9 | **7.0** |
| **추가 유닛당 Δ** | **−2,190원** | **−3,193원** ← 더 나쁨 |

**모든 변형에서 유닛당으로는 1N 이 1/2N 보다 나쁘다**(V0 −1,027 vs −1,129 / V0b −1,042 vs −1,329). 총 Δ 가 작은 이유는 **추가가 덜 발화**해서일 뿐이다. 정확한 서술: **"1N 은 더 나은 규칙이 아니라 더 적은 용량(dose)이다."** 재개 시 1N 을 고른다면 그것은 "노출 축소" 선택이지 "실측이 지지하는 규칙" 이 아니다.
(초판이 근거로 든 *"MFE 중앙값 1.41N 이 1/2N 완성점 1.5N 과 겹치는 최악 정렬"* 도 철회한다 — 실제 kojiro MFE 중앙값은 **1.30N** 이고, 무조건부 MAE 를 조건부 손절선과 비교한 범주 오류였다. 필요한 통계는 *"+1.5N 도달 후 P0−0.5N 까지 되밀린 비율"* 인데 일봉 데이터로는 산출 불가다. 약한 프록시: 1.5N 도달 왕복 중 MAE ≥ 0.5N 이 donchian 4/6 · kojiro 4/5.)

**물타기 변질 함정 11종** (초판 8종 + 신규 3):
①랏 원장 부재 ②매수 창 09:05~09:30 1회/일(익일 창 체결 = 사다리가 아니라 고점 추격) ③`is_sold_today` 축까지 뚫으면 손절 직후 재매수 = 진짜 물타기 ④`_entry_atr` 재스탬프가 기보유 유닛 손절 규약을 바꿈 ⑤`high_since_buy` 리셋/유지 미정 ⑥cycle235 가 겨우 닫은 체결통보 수량 정합을 랏 병합이 재개방 ⑦부분 청산 개념 부재 ⑧`_stop_floor` tighten-only 래칫은 **유일하게 우리 편**
**⑨(신규) 트리거 앵커** — ①안 가중평단 채택 시 추가 트리거를 `pos.buy_price`(평단)에 걸면 *"마지막 진입가 아래 · 평단 위"* 되돌림에서 재무장 추가 = **사다리 기준으로는 물타기**. 트리거는 반드시 `last_entry_price + step×N` **단조 사다리**(되돌림 재무장 금지).
**⑩(신규) 래치 오용** — 트리거를 `high_since_buy ≥ level` 래치로 두면 스파이크 후 되밀린 현재가에 추가가 나간다. cycle228 추격 상한과 동일하게 **발화 시점 `current_price ≥ level` 단독 판정**이어야 한다.
**⑪(신규) 계좌 게이트 선점** — 계좌 SOFT Σ상한은 7전략 공통이라 한 스택이 6% 근처를 채우면 **나머지 6전략 신규 매수를 굶긴다**. 추가는 전략별 heat 캡에서만 소비하고 계좌 헤드룸을 선점하지 않는 설계 결정이 필요하다.

**1주 폴백 스택 (이론 유닛 0주 → `_fallback_one_share` 4회)** — §0.0 의 구조가 꼬리에서 폭발한다:

## 4. 권고 · 반대 논거 · 활성화 게이트

### 4.1 권고

> **옵션 A 채택.** 피라미딩 기제 코드 착수를 보류하고, 게이트를 **착수(T1) / 활성(T2)** 로 분리해 워크리스트에 명문화한다.
> **그보다 먼저 §0.0 — 1주 폴백의 진입 시점 과잉 피라미딩(R15 위반)을 독립 사이클로 시정**한다. 이것이 피라미딩보다 크고 급하고 확실하다.
> **B 는 선택적 B-lite(20:10 리포트 일봉 배치)로 축소.**
> **C 는 반대.**
> 재개 시 **대상은 kojiro 한정.** donchian 은 (a) 충실 사이징에서 추가가 발화조차 안 하고 (b) Σ리스크 캡이 없으며 (c) 청산 재튜닝이 미완이라 **제외**.
> 재개 시 간격 = **1N**. 단 이는 "더 나은 규칙" 이 아니라 **"더 적은 용량"** 선택임을 명시한다(§2.6).

**프로젝트 자신의 로드맵과의 관계 — 초판 서술 정정.**
초판은 "충돌하지 않고 정량 보강한다" 고 했으나 **실은 초판이 더 느슨했다.** `src/engine/strategies/CLAUDE.md:60-72` 의 T-표는:

| 자본 | 피라미딩 | 상관군 캡 |
|---|---|---|
| T0 (~117만) | inert 봉인 | 섹터 캡 2 |
| **T1 500만** | **배선 + 다크런치** | 섹터 캡 2 |
| **T2 5,000만** | **ON (4유닛)** | **유닛-섹터 캡** |

즉 로드맵은 **500만 = 배선/다크런치, 5,000만 = 실활성**인데 초판 G1 은 500만을 **실구현 게이트**로 썼다. 또 로드맵의 "게이트 3 = 상관군 캡 유닛화는 피라미딩의 필수 선행" 과 "게이트 1 = 백테스트 스윕 통과 후 활성" 이 초판 게이트 7건에 **없었다**(결합 백테스트는 '열린 질문' 으로 강등). 그리고 cycle232 는 `risk_pct` 0.5→1.0(heat 2배)조차 **규칙 4(heat 상향은 상관군 캡 전제)** 로 보류했는데, **피라미딩은 종목당 heat 를 최대 5배로 올리는 변경**이므로 같은 논리가 더 강하게 적용된다.
→ **아래 §4.3 에서 착수/활성을 분리하고 상관군 유닛 캡(G11)·결합 백테스트(G12)를 게이트로 승격했다.**

### 4.2 반대 논거 (A 에 대한 정직한 반박 4)

1. **표본이 통계적으로 빈약하다.** n=24/14 로 "기대값 음수" 는 확정이 아니다(kojiro CI [−1.30,+0.43] 은 0 을 포함). → 다만 이는 "하지 말자" 를 약화시키는 게 아니라 **"증거 없이 레버리지를 올리지 말자" 를 강화**한다. 엣지가 미확정일 때 증폭기를 다는 것이 정확히 피해야 할 순서다.
2. **시스템의 반쪽만 테스트했다.** 터틀의 편익은 (피라미딩 + 10/20일 채널 청산 + 상관군 캡)의 **결합**에서 나온다. 우리 청산을 고정한 채 피라미딩만 얹어 기각하는 것은 알려진 오류 유형이다. → **인정한다. 가장 강한 반론이다.** 2차 시뮬이 이상적 터틀 청산(2N + 2.5N 샹들리에)으로도 돌렸으나 이는 원전의 채널 청산이 아니다. **결합 편익은 미측정이며 이것이 A 를 뒤집을 수 있는 유일한 증거 경로다**(→ G12 로 게이트 승격).
3. **kojiro 의 오른쪽 꼬리를 포기하는 비용.** 슈프리마 사례(+12.83N)는 피라미딩이 아니면 얻을 수 없는 종류의 이익이다. → 완화: G3/G3′ 통과 시 kojiro 한정 재개로 문을 열어 뒀다. ⚠️ **그 꼬리는 표본 1건**(kojiro 총이익의 63%)이다. 그리고 kojiro 손익분기 승률 36.8% vs 실제 21.4% — **먼저 고칠 것은 "청산이 오른쪽 꼬리를 지켜주게 만드는 일" 이지 진입을 키우는 일이 아니다**.
4. **원전 이식의 부분성.** 터틀 원전은 −50% 드로다운을 견디도록 설계됐고 우리 설계 천장은 훨씬 낮다 — 애초에 다른 게임이다. → 이는 A 를 지지하기도(부분 이식은 위험) 반대하기도(우리 척도로 5N 이 계좌 0.75%) 한다. §1.2 와 §2.7 이 이 긴장을 보여준다 — **계획 리스크는 작지만 꼬리는 3.8배 커진다.**

### 5.2 손절선 세트 관리 (가장 조심할 부분)

- **책 규약**: 추가 시 전 유닛 손절선 = `last_entry_price − stop_atr × N_entry`. `pos.buy_price`(가중평단)가 **아니다**.
- **N 은 진입 스탬프 고정** — ⚠️ **kojiro 에는 그 스탬프가 없다**(§2.3). `_effective_atr` 는 live 우선이고 `_position_atr` 은 `recompute_held_atr` 가 매번 덮어쓴다. **G9(entry_atr 영속 컬럼)가 선행 필수**이며, 이때 **두 개의 N 이 공존**하게 된다: 사다리·추가 사이징용 `entry_atr`(고정) vs 손절용 `_effective_atr`(live 우선 + tighten-only floor). **어느 쪽을 손절 N 으로 쓸지는 명시 결정 사항**이다 — CLAUDE.md 커플링 불변식("스탬프 값은 sizing 에 쓴 ATR 과 동일")을 만족하려면 손절도 고정해야 하는데, 그것은 kojiro 의 'live 우선' 독트린과 정면 충돌한다.
- **기존 4선 max 와의 관계를 계약으로 못박을 것.** 현행 `_position_stop_price` = `max(pct_line, atr_line, trail_line, be_line)` 이고 **네 선 전부 `pos.buy_price` 단일 앵커**다(`kojiro.py:1057-1075`). 가중평단으로 병합하면 넷이 동시에 이동한다. **§6 에 '4선 각각의 앵커(첫 진입가 / 가중평단 / 마지막 진입가) 결정' 을 열린 질문으로 추가**했다.
- ⚠️ **BE 승격 + 가중평단 = 휩소 구조** (정정 2) — 4유닛 후 BE 선이 마지막 진입가 −0.75N 에 놓이고 kojiro MAE 중앙 1.55N 이라 통상 되돌림에 관통한다. **재개 전 시뮬을 BE-at-avg 포함으로 재실행할 것.**
- `_stop_floor` tighten-only 래칫은 **유지**(하락 중 평단 하락에도 floor 미하강 = 물타기 방지).
- `high_since_buy` 는 추가 시 **유지**(리셋 금지) — DB 경로 포함(§5.1).

### 5.3 트리거 소스와 실행 창

- **가격 소스**: `check_exit_signal` 이 받는 `current_price`(WS 틱 + `_swing_rest_poll_loop` 60초 REST, 09:05~15:20 커버). 관측기를 청산 함수에 두면 프리장 보류 게이트(`_defers_pre_market_exit`)를 **공짜로 상속**한다.
- **실행 창**: 현행 매수 평가는 09:05~09:30 뿐. 장중 추가에는 (a) 매수 창 확장 (b) 신규 폴 루프 (c) `risk.on_tick` 매수 분기 개방 중 하나가 필요하다.
  ⚠️ **초판 정정** — (a) 는 strategy 파일 변경이라 **8영역이 아니지만 단독으로는 무효**(보유 종목이 `risk.py:617` / `scheduler.py:2752` / `order_engine.py:226,230` 에서 먼저 걸러진다). (b) 는 **`scheduler.py` 가 3,999줄로 4,000 상한에 붙어 있어** cycle233 `account_risk_watcher` 처럼 **신규 leaf 모듈 + boot_manager 배선**이 강제된다. 정확한 서술: **어떤 설계든 `strategy_registry` + `order_engine`(8영역 2~3곳) 접촉은 불가피**하고, 트리거 판정 자체는 strategy 파일에 둘 수 있다.

### 5.5 회귀 가드 (최소 12)

1. **P-1**: 같은 ticker · 다른 order_no 2건 체결 → `pos.quantity` = **합**, `buy_price` = **가중평단**, `last_entry_price` = 마지막 체결가.
2. **P-1b (신규)**: **부분 체결 직후 동일 종목 2번째 주문 시도 → 차단**. `_pending_cancel_tasks` 가 `(ticker, order_no)` 키라 1차 취소 태스크 생존.
3. **손절 세트**: 4유닛 사다리 후 손절선 = `last_entry − 2N`(또는 그보다 높은 지배선)이고 **기존 유닛 손절선이 느슨해지지 않음**(tighten-only 단조성).
4. **재시작 불변 (신규)**: 재시작 후 `last_entry_price` · `entry_atr` 복원 → **손절선·사다리 눈금 불변**.
5. **DB 고점 (신규)**: 추가 체결 후 DB `high_since_buy` **불감소**.
6. **물타기 차단**: `current_price < last_entry_price` 일 때 추가 신호 **0건**. ⚠️ 앵커는 **평단이 아니라 마지막 진입가**(§2.6 ⑨).
7. **래치 금지 (신규)**: `high_since_buy ≥ level` 이지만 `current_price < level` 이면 추가 **0건**(§2.6 ⑩).
8. **게이트 동등성 (신규, G8)**: 추가 경로에서 8개 매수 게이트 각각을 뮤테이션 제거 → **각각 FAIL**.
9. **1주 폴백 금지 (신규, G10)**: 이론 유닛 0주인 종목에서 추가 신호 **0건**(1주 반환 금지).
10. **예산 원자성**: `calc_buy_quantity` ↔ `pending_buys.add` 사이 `await` 0건 유지(A-ATOMIC).
11. **캡 비공허성**: `unit_count` 캡 · Σ리스크 캡 · 상관군 유닛 캡을 각각 1줄 변조 → **FAIL** 실증. (cycle224 의 "정의상 항상 참인 AST 가드" 선례 반복 금지.)
12. **P-2**: PENDING BUY 2행 상태에서 1건 체결통보 → **해당 order_no 행만** COMPLETED. **취소 경로(`_schedule_cancel`)도 동일 검증.**

## 6. 열린 질문 (사용자 결정 필요)

1. **분산 vs 집중.** 피라미딩은 kojiro 를 "6종목 분산" 에서 **"실질 1.8종목 집중"**(Σ리스크 캡이 먼저 물림)으로 바꾼다. 받아들인다면 `max_positions` 를 6 → 2~3 으로 함께 낮추거나 `max_open_risk_pct` 를 올려야 하고, **후자는 G11 상관군 유닛 캡이 전제**다. (대안 "1유닛 = position_ratio/4" 는 분산을 지키지만 해상도를 4배 악화시켜 §0.0 문제를 폭증시킨다 — 공짜 선택지가 아니다.)

4. **B-lite 채택 여부.** 20:10 리포트에 would_add 일봉 배치 시뮬을 붙일 것인가? (보유 종목 한정 소량 KIS 폴백 발생 — 초판의 "호출 0" 은 오류.)
5. **(신규) 4선 앵커 결정.** kojiro 청산 4선(`pct_line` · `atr_line` · `trail_line` · `be_line`)의 앵커를 **첫 진입가 / 가중평단 / 마지막 진입가** 중 무엇으로 할 것인가? 가중평단이면 §0.1 정정 2 의 휩소 구조가 생긴다.

9. **수수료·세금 관측 배선.** 라이브 손익이 gross 다. 회전율을 바꾸는 **어떤 변경보다 먼저** 최소 비용 모델을 관측 항목으로 붙일 것인가?
