## 결론 (쉬운 말)

1. 상한가를 찍은 뒤 되밀려도 **실제로 잃는 돈은 매수가 −3.5% 에서 멈춘다**(운영 DB 값). 「23% 반납」은 고점에서 본 **평가이익**이 줄어드는 폭이고, 그만큼 되밀린 경우는 과거 373건 중 2% 였다.
2. 당일 트레일링(고점 대비 몇 % 밀리면 판다)을 넣으면 **평균 수익이 줄어든다.** 상한가 종목은 잠겼다 풀렸다 하면서 4~7% 흔들리는 게 보통이라, 폭이 좁으면 다음 날 갭업할 종목을 털린다. 두 표본 모두 같은 방향이다(폭 10~12% = 건당 −0.6~−2.0%p).
3. 같은 걱정을 가장 싸게 닫는 것은 **「15:20 에 아직 상한가 근처인가」 한 번만 묻는 것**이다. 아니면 그날 종가에 판다. 평균 수익은 거의 그대로(−0.07%p)이고 **−5% 넘게 잃는 경우가 절반으로 준다**(6건 → 3건). 전략 파일 한 곳에서 끝나고 8영역·`scheduler.py` 를 건드리지 않는다.
4. 🔴 **크리티컬 분기 있음** — 사용자 결정의 전제(트레일링이 없어서 23% 를 잃는다)와 실측이 다르다. 권고는 「15:20 확인(B)」이지만 이름 그대로의 「트레일링」을 원하면 폭 **15%** 만 근거가 선다. 형태를 골라 주셔야 한다(§9).
5. 돈의 크기는 작다 — 실매매에서 상한가 모드는 5개월에 **1건**, 랏 중앙 **59,240원**. 이 결정은 수익보다 **설계 정합성과 꼬리 위험**의 문제다.

## 3. 트레이더 시각

**시장 가설** — 상한가 모드의 존재 이유는 「상한가 = 매수세가 끝까지 이긴 날이고, 그 힘이 다음 날 시초가 갭으로 이어진다」이다. 실측도 맞는다(모집단 현행 평균 +11.6~+13.1% — 익일 트레일링 가정 하단~실측 보정, 잠김 마감의 익일 갭 중앙 +2.9%).

**그 가설이 깨지는 시점은 「터치」가 아니라 「마감」이다** — 한 번 찍고 풀린 종목은 그날의 줄다리기에서 진 것이고, 밤을 넘길 자격(강한 마감)을 잃었다. 현행 코드는 **첫 터치 한 틱으로 밤 보유를 확정**한다. 그래서 고칠 곳은 「장중에 얼마나 밀리면 파느냐」가 아니라 「**밤을 넘길 자격을 언제 확인하느냐**」다.

**호가창 동학** — 잠긴 상한가는 매도 호가가 없고 매수 잔량만 쌓인다. 대량 매도가 잔량을 먹으면 잠깐 풀려 2~7% 밀렸다가 다시 잠기는 일이 흔하다(분봉 중앙 4.7%). 좁은 트레일링은 이 「잔량 소진 흔들기」에 반응해 그날 최고의 종목을 판다. 반대로 풀린 뒤 추세적으로 밀리는 종목(풀림 마감 45%)은 대개 +20% 언저리에서 마감한다 — 반납은 평가이익이고 손실이 아니다.

**위험 시나리오**
- 잠김 마감 → 익일 갭 하락(−10~−14%, 3건): 어느 당일 규칙으로도 못 막는다(애초에 들고 가기로 한 종목).
- 풀림 마감 → 익일 갭 하락(−12%대 2건 · −6.6% 1건): **15:20 확인이 막는다**(B 의 −5% 이하가 6 → 3 으로 주는 몫이 이것이다).
- 상한가 → 매수가 −3.5% 왕복: 모집단 373건 중 종가 기준 확정 14건(3.8%). 손실은 −3.5% 로 제한된다.

## 5. 권고안 — B「15:20 상한가 유지 확인」+ TDD 구현 명세 초안

### 5.1 행위 명세

`LongTailVolatilityStrategy.check_force_clear()`(15:20 `scheduler._force_clear_main_only` 가 부른다)를 다음처럼 바꾼다.

```
반환 = [당일 모드 종목 전부]                                         # 현행 그대로
     + [상한가 모드 ∧ 당일 매수(not pos.is_next_day) ∧ 확인 모드 enforce
        ∧ 15:20 가격의 전일대비 등락률 < limit_up_threshold 인 종목]   # 새로 추가
```

- **가격 출처** = `scanner.ticker_prices[t]["current_price"]` 와 `scanner.ticker_prev_close[t]` — 모드 전환 판정(`:1081-1084`)과 **같은 출처**다. 경계는 `>=` 면 보유(전환 조건과 대칭).
- **판정 불가면 보유(= 현행)** — 가격 없음·0 이하·전일종가 없음·예외. 잠긴 상한가는 체결이 드물어 틱이 오래될 수 있는데 그때 마지막 가격은 상한가라 보유가 맞다. 그래서 **신선도 게이트를 두지 않고** 나이만 로그에 남긴다.
- **익일(`is_next_day`) 상한가 모드 종목은 대상이 아니다** — 갭업 트레일링 중인 종목은 현행대로.
- 🔴 **never-raise 가 계약이다** — `_force_clear_main_only`(`scheduler.py:2024`)는 `check_force_clear()` 를 try 없이 부른다. 새 분기가 예외를 던지면 **당일 모드 종목까지 15:20 청산을 못 하고 밤을 넘긴다.** 새 판정 전체를 감싸고, 실패하면 현행 목록을 돌려준다.
- 동기 함수 유지 — `await`·DB·HTTP 0(읽기는 모듈 dict 뿐).
- 청산은 기존 `Signal.FORCE_CLEAR` 경로(15:20 시장가 → KRX 종가 단일가) 그대로. 체결 뒤 `on_position_closed` 는 `was_limit_up=True` 라 재진입 쿨다운이 걸리지 않는다(현행 계약 유지).

## 8. 반례 / 한계

- **B 가 틀리는 날** — 풀린 채 마감한 종목이 다음 날 갭업하는 경우(모집단 풀림 마감 169건의 54% 가 익일 시가가 매수가 +7% 이상). B 는 그 몫을 포기하고 갭 하락 몫을 피한다. 평균이 0 근처인 이유가 이것이다.
- **15:20 가격 ≠ 종가** — 종가 단일가에서 무너지는 종목이 있다(분봉 393210: 15:19 +21% → 종가 +12.1%). B 는 그 종가에 판다. 반대로 단일가에서 다시 잠기면 상한가에 판다.
- **분봉 표본의 치우침** — 45건 대부분이 LTV 유니버스 밖 소형주다. 유니버스 안(전일 거래대금 200억 이상) 5건은 흔들림이 더 얕았다(잠김 3건 최대 4.7% 이하) — 유니버스 안에서는 좁은 트레일이 덜 털릴 수 있다. N=5 라 결론을 바꾸지 않는다.
- **일봉 모집단의 한계** — 장중 순서를 모른다. 손절(−3.5%) 발동을 「종가가 손절선 아래」일 때만 확정으로 셌고(확정 14건), C 의 모호 구간은 분봉 표본의 실측 발동률로 가중했다. 시총 필터는 현재 값 근사다.
- **익일 NXT 프리장 트레일링** — 갭업이면 08:00:30 부터 `high_since_buy = 시가` 로 −2% 트레일링이 **얇은 NXT 프리장 가격 위에서** 돈다(LTV 가 프리장 청산 평가 화이트리스트라서). 이번 범위 밖이고 모집단 계산은 KRX 시가로 근사했다.
- **재시작** — `_limit_up_reached` 는 메모리 전용이다. 당일 재시작 후 가격이 +29% 아래면 모드를 잃고 15:20 에 청산되는데, B 를 넣으면 그 결과가 B 의 판정과 **같아진다**(둘 다 판다). B 가 이 누수의 당일 쪽을 사실상 무해하게 만든다. 15:20~15:30 재시작은 여전히 모드를 잃은 채 전량 청산 — 현행과 같다.
- **꼬리의 절반은 못 막는다** — 잠김 마감 → 익일 갭 하락(−10~−14%, 3건)은 B·C 어느 쪽도 못 막는다. 막으려면 「종가 잠김이어도 밤 보유 한도」 같은 별개 규칙이 필요하고, 그건 이 전략의 정체성(연속 상한가 추구)을 건드린다.

1. 실현 손실은 이미 −3.5% 에서 멈춘다(운영 DB). 23%(운영 값으론 약 21%) 는 평가이익 기준이고 모집단에서 15% 넘게 되밀린 경우는 2%.
2. 「트레일링」을 이름 그대로 넣으면 평균 수익이 준다. 폭 선택이 결과를 가르는데(7% −2.1 ~ 15% −0.9 %p/건) **어느 폭도 현행보다 낫다는 근거가 없다.**

| 선택 | 내용 | 권고 |

| **① B — 15:20 상한가 유지 확인** | 위 §5 | ✅ **권고** — 평균 ≈ 0, −5% 이하 손실 절반, 전략 파일 한 곳, 벽시계 게이트 없음 |
| ② C15 — 당일 트레일 15% | 위 §6 | 이름 그대로의 트레일링이 꼭 필요할 때만. 평균 −0.9~0, CI 게이트 비용 |
| ③ B + C15 | 둘 다 | 이득이 B 와 거의 같고 비용은 둘의 합 — 비권고 |
| ④ 현행 유지 + 문서 정정 | 코드 무변경. 워크리스트 `B6` 를 「반납은 평가이익, 실손 −3.5% 캡」으로 닫는다 | 기대값만 보면 동률. 꼬리를 줄이지 못한다 |
