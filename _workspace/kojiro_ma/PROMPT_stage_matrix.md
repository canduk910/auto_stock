# 작업 지시: 대순환 스테이지 엔진 + 일봉×분봉 매트릭스 구현

> PLAN.md의 확장 작업. 기존 "핵심 설계 원칙(§1)"을 그대로 상속한다 — 특히 **판정은 규칙 코드, LLM은 설명만 / 임계값·정의는 코드 상수 한 곳 / 매매 주문 미실행**.

---

## 0. 배경과 목적

모듈 2·3의 기술적 분석을 이평/RSI 수준에서 한 단계 올린다. 고지로 강사(小次郎講師)의 **이동평균선 대순환 분석**을 도입해:

1. EMA(지수이동평균) 3선(단기 5 · 중기 20 · 장기 40)의 배열로 종목의 **스테이지(1~6)**를 판정하고,
2. **일봉 스테이지 × 분봉 스테이지** 매트릭스로 신호의 시간축 정합성을 확인하며,
3. 기존 **매크로 국면(회복/확장/과열/수축)**을 최종 보정자로 결합한다.

계층 구조: `매크로 국면(시장 전체) → 일봉 스테이지(종목 추세) → 분봉 스테이지(진입 타이밍)`.
모듈 3의 "진입 신호 판정(국면 결합)"이 이 구조의 1차 소비자다. 모듈 2(보유종목)도 동일 엔진을 재사용한다(관점만 "정리/비중조정"으로 전환).

## 3. 데이터 소스 (KIS)

- **일봉**: `inquire_daily_itemchartprice` (기존 확인됨). EMA(40) 안정화를 위해 **최소 120봉** 조회.
- **분봉 [P2]**: KIS 분봉 조회 API는 1회 호출당 반환 봉 수 제한이 있는 것으로 알려져 있다(당일분봉조회는 회당 약 30봉). 15분봉 EMA(40)에는 40봉 이상 + 워밍업이 필요하므로 **여러 날에 걸친 페이지네이션이 가능한지 KIS 코드 어시스턴트로 먼저 확인**하고, 불가하면 (a) 일별분봉조회 계열 API 탐색, (b) 분봉을 자체 수집·적재(DynamoDB) 중 택일하여 보고할 것. 이 확인 결과에 따라 [P2] 착수 여부를 결정한다.
- **캐시 정책**: 일봉 EMA는 장 마감 후 1회 계산이면 충분(TTL 당일). 분봉은 15분 TTL. 현재가는 기존 정책대로 캐시 금지.

## 4. 신호 매트릭스 — 전부 상수 테이블로

판정 로직에 if-else를 흩뿌리지 말고, **조회 테이블 상수**로 정의한다(임계값 단일 정의 원칙의 확장).

### 4.1 [P1] 매크로 국면 × 일봉 스테이지 → 신호 라벨

신호 라벨은 4단계: `진입검토` / `조건부관찰` / `관망` / `정리검토`. (모듈 3은 앞 3개를, 모듈 2는 `정리검토` 포함 전체를 소비)

```python
SIGNAL_MATRIX_P1 = {
    # (매크로 국면, 일봉 스테이지): 신호 라벨
    ("회복", 1): "진입검토", ("회복", 6): "진입검토", ("회복", 5): "조건부관찰",
    ("확장", 1): "진입검토", ("확장", 6): "조건부관찰",
    ("과열", 1): "조건부관찰", ("과열", 2): "정리검토",
    ("수축", 1): "관망",  # 시장이 겨울이면 종목이 여름이어도 신규 진입은 관망
    # ... 4국면 × 6스테이지 = 24칸 전체를 빠짐없이 채울 것. 미정의 조합 기본값 금지.
    # 기본 성향: 스테이지 3·4는 국면 무관 "관망"(보유 시 "정리검토"), 매크로가 방어적일수록 한 단계 보수화.
}
```

24칸을 채울 때의 원칙: (1) 스테이지 3·4에서는 어떤 국면에서도 `진입검토`가 나오지 않는다. (2) 매크로 수축에서는 최고 라벨이 `조건부관찰`을 넘지 않는다. (3) 라벨은 "제안"의 강도일 뿐 주문과 무관하다.

### 4.2 [P2] 일봉 스테이지 × 분봉 스테이지 → 타이밍 보정

일봉이 방향, 분봉이 타이밍. 6×6 전체를 채우지 말고 **그룹으로 축약**해 과적합을 피한다:

```python
STAGE_GROUP = {1: "상승권", 2: "전환권", 3: "하락권", 4: "하락권", 5: "전환권", 6: "상승권"}

TIMING_MATRIX_P2 = {
    # (일봉 그룹, 분봉 그룹): 타이밍 코멘트 키
    ("상승권", "상승권"): "정렬일치_강",      # 두 시간축 동방향 → 신호 신뢰도 상향
    ("상승권", "하락권"): "눌림목_관찰",      # 큰 추세 유효, 단기 조정 중
    ("하락권", "상승권"): "약반등_할인",      # 겨울 속 갠 날 — 신호 강도 하향
    ("하락권", "하락권"): "정렬일치_약",
    ("전환권", "*"): "전환대기",             # 전환권은 분봉 무관 관찰 유지
    # 나머지 조합도 명시적으로 채울 것
}
```

P2 매트릭스는 P1 신호 라벨을 **한 단계 올리거나 내리는 보정자**로만 작동한다(독립 신호 아님).

## 5. LLM 연동 — 설명 전용

- `build_prompt.py`의 기준표 자동 생성 함수를 확장: `STAGE_DEF`·`SIGNAL_MATRIX_P1`에서 기준표 텍스트를 생성해 시스템 프롬프트에 포함(코드-설명 일치 보장, 매크로 `THRESHOLDS` 처리와 동일 패턴).
- 종목 프롬프트에 주입할 블록 예:

```
[대순환 스테이지 — 시스템이 EMA 실값으로 판정함. 재판정·숫자 변경 금지]
- 일봉: 스테이지 4 (안정 하락기), 직전 대비 순행, 최근 이벤트: 20/40 데드크로스(2일 전)
- EMA 실값: 단기 251,300 / 중기 268,900 / 장기 271,200
- 종합 신호: 관망 (매크로 '과열' × 일봉 스테이지 4)
```

- LLM 지침에 추가: 스테이지·신호 라벨을 바꾸지 말 것, "반드시 하락한다" 류 단정 금지, 라벨은 제안일 뿐임을 응답에 자연스럽게 포함.
- 팝업: 별도 신규 툴을 만들지 말고 `show_stock_report(focus="technical")`의 리포트 데이터에 `StageResult`를 포함시켜 프론트가 스테이지 게이지를 렌더링(프론트 실데이터 직접 조회 원칙 유지).

## 6. 테스트 요구사항

1. **경계값**: 세 EMA가 같은 값(동률), 두 값만 동률, 스테이지 정의 6종 각각의 대표 케이스.
2. **순환 방향**: 6→1 순행, 2→1 역행, 1→1 유지 판별.
3. **크로스 감지**: 크로스 당일/전일/미발생 3케이스.
4. **매트릭스 완전성**: `SIGNAL_MATRIX_P1`이 24칸 전부 정의되었는지, 원칙(스테이지 3·4에 진입검토 없음 등) 위반 칸이 없는지 검사하는 테스트를 코드로 작성(사람 눈 검수 금지).
5. **합성 시계열**: 상승→고점→하락 시나리오의 가짜 가격 시계열로 1→2→3→4가 순서대로 나오는지 통합 테스트.
