# 고지로(小次郎講師) 방식 자동매매 전략 설계서

**대상**: 국내주식 · 일봉 · 한국투자증권 Open API (REST)
**운용 주기**: 하루 1회, 장 마감 후 신호 계산 → 익일 주문
**포지션 방향**: 매수(Long) 전용 — 국내 현물 특성 반영. 하락 국면(스테이지 4)은 "진입 금지 + 보유분 청산" 신호로만 사용

---

## 1. 전략 구성 3축

고지로 방식은 세 개의 기둥으로 이루어진다. 자동매매로 옮길 때도 이 세 모듈을 분리해 구현한다.

| 축 | 역할 | 모듈 |
|---|---|---|
| ① 이동평균선 대순환 분석 | 시장 국면(스테이지) 판별 → 진입/청산 **방향** 결정 | `indicators.py` |
| ② 대순환 MACD | 스테이지 전환의 **선행 신호** → 조기 진입/조기 경계 | `indicators.py` |
| ③ 터틀식 자금관리 (ATR·유닛) | **얼마나 살지**, 손절선, 피라미딩 | `money.py` |

비유하면 ①은 계절 판별(지금이 봄인지 겨울인지), ②는 일기예보(계절이 바뀌기 직전의 징후), ③은 옷장 관리(추워질 때 얼마나 껴입을지)다.

## 2. 지표 정의 (파라미터)

* **EMA**(지수이동평균: 최근 가격에 가중치를 더 주는 이동평균) 3본
  * 단기 `EMA5`, 중기 `EMA20`, 장기 `EMA40` — 고지로 표준 파라미터 (5, 20, 40)
* **띠(帯, band)**: EMA20과 EMA40 사이 영역. 대국(큰 흐름) 추세를 나타냄
  * 띠 폭 = |EMA20 − EMA40|. 폭이 넓어지며 기울면 추세 명확
* **대순환 MACD** (MACD: 두 이동평균의 간격으로 추세의 힘을 보는 지표)
  * `MACD1 = EMA5 − EMA20` → 단·중기 크로스(스테이지 1→2, 4→5)의 선행 신호
  * `MACD2 = EMA5 − EMA40` → 단·장기 크로스(스테이지 2→3, 5→6)의 선행 신호
  * `MACD3 = EMA20 − EMA40` (띠 MACD) → 중·장기 크로스(스테이지 3→4, **6→1**)의 선행 신호
  * 각 MACD의 시그널선 = 해당 MACD의 9일 EMA
* **ATR(20)** (Average True Range: 하루 평균 변동폭. 종목의 "보폭") — Wilder 방식
* **기울기 판정**: `EMA(t) > EMA(t−1)`이면 우상향. 노이즈 방지를 위해 `(EMA(t)−EMA(t−3))/3 > 0` 옵션 제공

## 3. 스테이지 판별 (대순환 분석의 심장)

세 EMA의 위→아래 배열 순서는 수학적으로 6가지뿐이며, 정상 장세에서는 1→2→3→4→5→6→1 순으로 순환한다.

| 스테이지 | 배열 (위→아래) | 국면 의미 |
|---|---|---|
| **1** | 단기 > 중기 > 장기 | 안정 상승기 — **매수 엣지** |
| 2 | 중기 > 단기 > 장기 | 상승 쉼표 (조정 시작) |
| 3 | 중기 > 장기 > 단기 | 하락 전환 예고 |
| **4** | 장기 > 중기 > 단기 | 안정 하락기 — 매수 금지 |
| 5 | 장기 > 단기 > 중기 | 하락 쉼표 |
| 6 | 단기 > 장기 > 중기 | 상승 전환 예고 |

구현: `stage(ema5, ema20, ema40)` — 배열 비교만으로 1~6 반환. 동가(같은 값)일 경우 직전 스테이지 유지.

## 4. 매매 규칙 (알고리즘)

### 4-1. 신규 진입 (매수)

**기본형(정공법) — 모든 조건 AND:**

1. 스테이지가 6 → 1로 전환된 날 (또는 5→6→1을 3영업일 내 통과)
2. 3본 EMA 모두 우상향
3. 종가 > EMA5 (가격이 선 위)

**조기 진입형(선행, 옵션 플래그로 on/off):**

1. 현재 스테이지 6 (또는 5 후반)
2. `MACD3`(띠 MACD)가 시그널선 **위에 있고**(상승 에너지 유지) 아직 **0선 아래**(중·장기 크로스 전) + 3봉 상승 중
3. 띠 폭이 직전 5일 대비 축소 중 (추세 전환 임박의 표식)
4. 조기 진입은 **0.5유닛**만 — 신호가 약할 때는 보폭을 줄인다

> **검증 과정에서 확인된 사실**: MACD3의 시그널선 골든크로스 "순간"은 바닥 직후(스테이지 4 후반)에 이미 발생한다. 따라서 조기 진입 창은 "GC 직후"가 아니라 "GC 상태 유지 & 0선 돌파 전"으로 정의해야 스테이지 6과 시점이 맞는다. 0선 돌파 = 중기선이 장기선을 넘는 순간 = 스테이지 1 전환과 동치.

### 4-2. 청산 (우선순위 순서대로 평가, 먼저 걸리는 것 실행)

1. **손절**: 종가(또는 장중가) ≤ 진입가 − 2×ATR(진입 시점) → **전량 시장가 청산**. 무조건 최우선
2. **추세 종료**: 스테이지가 3에 진입 (단기선이 장기선 아래로) → 전량 청산
3. **1차 경계(보수 모드 옵션)**: 스테이지 1 → 2 전환 + `MACD1` 데드크로스 → 절반 청산
4. **트레일링 스톱**: 보유 중 최고 종가 − 2.5×ATR 하회 → 전량 청산 (이익 보호)

### 4-3. 피라미딩 (증축 매수, 터틀 방식)

* 조건: 보유 포지션 평가익 ≥ +1×ATR **그리고** 스테이지 1 유지 중
* 1회당 1유닛 추가, **종목당 최대 2유닛** (조기 진입분 포함)
* 추가 매수 시 손절선을 전체 평균단가 기준으로 재계산

## 5. 자금관리 (터틀 → 고지로 단순화 버전)

**유닛(unit) = 한 번에 살 수량의 기본 단위. "종목의 보폭(ATR)에 반비례"**

```
리스크 허용액 = 총투자자금 × 1%          # 예: 5,000만원 → 50만원
1유닛 주식수  = floor(리스크 허용액 ÷ ATR) # ATR 3,000원 종목 → 166주
```

손절폭이 2ATR이므로 1유닛의 실질 최대손실 = 총자금의 약 **2%**.

**포트폴리오 한도(동시 보유 제한):**

* 종목당 최대 2유닛
* 동일 업종(상관 높은 종목군) 합산 최대 3유닛
* 계좌 전체 합산 최대 10유닛 (= 이론상 동시 최대손실 20% 상한)
* 신규 진입 전 주문가능현금 조회로 실제 체결 가능 여부 확인

## 6. 일일 운영 파이프라인 (자동화 흐름)

```
[매 영업일 16:00 KST 배치]
 1. 휴장일 체크 (국내휴장일조회) → 휴장이면 종료
 2. 토큰 확보 (24h 유효, 파일 캐시 재사용)
 3. 유니버스 종목별:
    a. 일봉 100개 조회 (기간별시세, 수정주가)
    b. EMA/스테이지/MACD/ATR 계산
    c. 보유 포지션 → 청산·피라미딩 신호 평가
    d. 미보유    → 진입 신호 평가
 4. 자금관리 필터 통과분만 주문 큐에 적재
[익일 08:50]
 5. 주문 큐 실행 (시장가 or 전일종가 지정가, Hashkey 첨부)
 6. 체결 확인 → 포지션 상태 DB(json/sqlite) 갱신, 손절선 기록
[장중 (옵션, 2단계 확장)]
 7. WebSocket 체결통보 + 실시간가로 손절 즉시 집행
```

**API 규격 매핑 (2026-07 기준, 실전/모의):**

| 기능 | URL | tr_id (실전) | tr_id (모의) |
|---|---|---|---|
| 접근토큰발급(P) | `/oauth2/tokenP` | - | - |
| Hashkey | `/uapi/hashkey` | - | - |
| 기간별시세(일봉) | `/uapi/domestic-stock/v1/quotations/inquire-daily-itemchartprice` | FHKST03010100 | 동일 |
| 주식주문(현금) 매수 | `/uapi/domestic-stock/v1/trading/order-cash` | TTTC0012U | VTTC0012U |
| 주식주문(현금) 매도 | 〃 | TTTC0011U | VTTC0011U |
| 잔고조회 | `/uapi/domestic-stock/v1/trading/inquire-balance` | TTTC8434R | VTTC8434R |
| 휴장일조회 | `/uapi/domestic-stock/v1/quotations/chk-holiday | CTCA0903R | (실전만) |

> POST body 키는 전부 대문자(`CANO`, `ACNT_PRDT_CD`, `PDNO`, `ORD_DVSN`, `ORD_QTY`, `ORD_UNPR`), 수량·단가는 String — 프로젝트 지침 준수.

## 7. 리스크·예외 처리

* `rt_cd != "0"` → `msg_cd`, `msg1` 로그 후 해당 종목 스킵 (전체 중단 아님)
* REST 호출 간 0.06초 이상 간격 (초당 제한 대응, 토큰버킷)
* 토큰 만료(EGW00123) → 1회 재발급 후 재시도
* 주문 후 미체결 지정가는 14:50에 시장가 정정 (추세추종은 "타는 것"이 우선)
* 스테이지 판별 불가(EMA 동가) → 직전 스테이지 유지, 신호 없음 처리

## 9. 유니버스 스크리너 (screener.py) — 종목선정 자동화

전제: 일봉을 저장한 **종목마스터DB**를 보유 (API 호출 없이 로컬에서 전 종목 계산).
DB 접근은 `datastore.py`의 DataStore 인터페이스(list_codes/get_daily/get_master)로 추상화 — sqlite 기본 구현 제공, 스키마가 다르면 어댑터만 교체.

**4단 깔때기:**

| 단계 | 조건 | 목적 |
|---|---|---|
| ① 체급 필터 | 시총 ≥ 3,000억 · 20일 평균 거래대금 ≥ 10억 · ATR/종가 1~4.5% | 자동매매에 적합한 체급 |
| ② 재무 훅 | 사용자 주입 함수 (예: PER 0~25, PBR 0~3) — 프로젝트의 재무DB 연결 지점 | 좋은 저수지 선별 |
| ③ 스테이지 스크리닝 | **매수후보**: 스테이지1 진입 3봉 이내 + 3선 우상향 / **관심종목**: 스테이지6 + 띠MACD 시그널 위 & 0선 아래 & 상승 중 | 지금 사도 되는 종목 |
| ④ 점수 랭킹 | 0.4×MACD3 기울기 + 0.3×띠 폭 확장률 + 0.3×진입 신선도 (min-max 정규화 가중합) | 유닛 배정 우선순위 |

**운영 연결**: `python -m kojiro.runner --db master.db --top 10` → 스크리너 상위 N종목 + 기존 보유 종목이 당일 유니버스가 된다. 보유 종목은 후보에서 빠져도 청산 감시를 위해 항상 포함.

**검증 결과** (합성 7종목 DB): 상승초입(2일차)만 매수후보, 바닥전환만 관심종목으로 분류. 장기 상승 지속(신선도 초과)·하락 추세·시총 미달·PER 40·저변동 종목은 모두 의도한 단계에서 걸러짐.

## 10. 백테스트 검증 항목 (코드 골격에 스텁 포함)

* 승률보다 **손익비(Pay-off ratio)** 와 기대값 = 승률×평균이익 − 패률×평균손실 중심 평가 — 추세추종은 승률 30~40%가 정상
* 스테이지 1 체류일수 분포, 조기 진입 on/off 비교, 2ATR vs 3ATR 손절 비교
* 거래비용: 수수료 0.015% + 매도 시 거래세 0.15% (2026년 기준 코스피) + 슬리피지 0.1% 가정
